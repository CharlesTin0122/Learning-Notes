**非常推荐使用 PySide 来编写 MotionBuilder 的界面。**

虽然 MotionBuilder 自带了 `pyfbsdk_additions` 用于创建 UI，但它的控件较为陈旧，布局方式不够灵活。在现代的影视和游戏工业流水线中，**PySide (Qt for Python)** 已经是标准配置。使用 PySide 开发工具不仅界面更美观、功能更强大，而且同一套 UI 代码可以很容易地移植到 Maya、Nuke、Houdini 等其他 DCC 软件中。

### 1. MotionBuilder 版本与 PySide 版本的对应关系

在编写代码前，你需要确认你使用的 MotionBuilder 版本，因为这决定了你需要导入哪个版本的 PySide：

- **MotionBuilder 2024 及更新版本**：使用 Python 3，内置 **PySide6** (Qt6)。
- **MotionBuilder 2017 到 2023**：使用 Python 2.7 或 Python 3，内置 **PySide2** (Qt5)。
- **更早的版本**：内置 **PySide** (Qt4)。

### 2. 基础代码示例

在 MotionBuilder 中运行 PySide 窗口时，需要注意**垃圾回收（Garbage Collection）**的问题。如果在函数内部创建窗口，函数运行结束后窗口变量会被销毁，导致界面一闪而过或崩溃。因此，通常需要将窗口实例保存在全局命名空间中。

下面是一个兼容现代 MotionBuilder（使用 PySide2 或 PySide6）的简单 UI 示例：

```python
import sys
from pyfbsdk import FBApplication

# 兼容性处理：尝试导入 PySide6 (MoBu 2024+)，如果失败则导入 PySide2 (MoBu 2017-2023)
try:
    from PySide6 import QtWidgets, QtCore
except ImportError:
    from PySide2 import QtWidgets, QtCore

class MoBuPySideTool(QtWidgets.QWidget):
    def __init__(self, parent=None):
        super(MoBuPySideTool, self).__init__(parent)
        
        # 设置窗口标题和属性
        self.setWindowTitle("MotionBuilder PySide 工具")
        # 确保它作为一个独立的窗口显示，并保持在顶层 (可选)
        self.setWindowFlags(QtCore.Qt.Window | QtCore.Qt.WindowStaysOnTopHint)
        self.resize(300, 150)
        
        # 创建布局
        layout = QtWidgets.QVBoxLayout()
        
        # 创建标签和按钮
        self.label = QtWidgets.QLabel("这是一个 PySide 界面！")
        self.btn_action = QtWidgets.QPushButton("获取场景模型数量")
        
        # 绑定按钮事件
        self.btn_action.clicked.connect(self.get_model_count)
        
        # 将控件添加到布局
        layout.addWidget(self.label)
        layout.addWidget(self.btn_action)
        self.setLayout(layout)

    def get_model_count(self):
        # 调用 pyfbsdk 获取场景数据
        from pyfbsdk import FBSystem
        models = FBSystem().Scene.Models
        self.label.setText(f"当前场景共有 {len(models)} 个模型")

# === 启动窗口的逻辑 ===
# 使用全局变量防止窗口被 Python 垃圾回收机制销毁
if 'my_mobu_tool' in globals():
    try:
        my_mobu_tool.close() # 如果已经打开了，先关闭旧的
        my_mobu_tool.deleteLater()
    except:
        pass

# 实例化并显示窗口
my_mobu_tool = MoBuPySideTool()
my_mobu_tool.show()
```

### 3. 高级集成：窗口父子关系

在更复杂的插件开发中，为了让 PySide 窗口完全融入 MotionBuilder 的生命周期（例如，当 MoBu 最小化时，工具窗口也跟着最小化），你可以将 MotionBuilder 的主窗口作为 PySide 窗口的 Parent。

这通常需要获取 MotionBuilder 的主窗口句柄（Window Handle / winId），然后通过 `shiboken` 或 Qt 的原生方法将其包装为 Qt Widget。不过，对于绝大多数日常脚本和自动化工具，上面示例中使用的 `QtCore.Qt.WindowStaysOnTopHint`（让窗口置顶）已经足够满足需求了。

总结来说，抛弃 `pyfbsdk_additions` 的 UI 模块，全面拥抱 **PySide + pyfbsdk** 组合，是目前 MotionBuilder TA 和工具开发者的最佳实践。
### 3. 获取MB主窗口
在 MotionBuilder 中获取主窗口作为 PySide 界面的父级（Parent），是非常标准的进阶做法。这样做有几个明显的好处：

1. **自动层级管理**：你的工具窗口会自然地保持在 MotionBuilder 主界面之上，不需要使用强制置顶（`WindowStaysOnTopHint`），这样就不会遮挡其他应用程序。
2. **生命周期绑定**：当 MotionBuilder 最小化时，你的工具也会跟着最小化；当 MotionBuilder 关闭时，你的工具会自动安全关闭。

因为现代版本的 MotionBuilder 底层就是基于 Qt 构建的，所以我们可以直接通过 PySide/Qt 的原生方法，遍历当前应用程序的顶层窗口（Top Level Widgets）来找到主窗口。

#### 获取主窗口的代码实现

以下是一个兼容 PySide2 (MoBu 2017-2023) 和 PySide6 (MoBu 2024+) 的通用函数：

```python
try:
    from PySide6 import QtWidgets
except ImportError:
    from PySide2 import QtWidgets

def get_mobu_main_window():
    """
    获取 MotionBuilder 的主窗口 (QWidget)
    """
    # 获取当前的 QApplication 实例
    app = QtWidgets.QApplication.instance()
    if not app:
        return None
    
    # 遍历所有顶层 Qt 窗口组件
    for widget in app.topLevelWidgets():
        # MotionBuilder 的主窗口标题通常包含 "MotionBuilder" 字样
        # 且通常是 QMainWindow 的子类
        if "MotionBuilder" in widget.windowTitle() and isinstance(widget, QtWidgets.QMainWindow):
            return widget
            
    # 如果通过标题没找到（比如被重命名或由于某些特定布局），退化为获取当前激活的窗口
    active_window = app.activeWindow()
    if active_window:
        return active_window
        
    return None
```

#### 完整示例：将主窗口设为自定义工具的父级

结合上一个回答中的 UI 框架，现在我们将获取到的 `main_window` 传递给我们的自定义工具：

```python
import sys
from pyfbsdk import FBApplication

try:
    from PySide6 import QtWidgets, QtCore
except ImportError:
    from PySide2 import QtWidgets, QtCore

def get_mobu_main_window():
    app = QtWidgets.QApplication.instance()
    if not app:
        return None
    for widget in app.topLevelWidgets():
        if "MotionBuilder" in widget.windowTitle() and isinstance(widget, QtWidgets.QMainWindow):
            return widget
    return app.activeWindow()

class MoBuPySideTool(QtWidgets.QWidget):
    # 将 parent 参数默认设为 None，但在实例化时我们会传入主窗口
    def __init__(self, parent=None):
        # 这一步非常关键：将 MoBu 主窗口传给父类 QWidget
        super(MoBuPySideTool, self).__init__(parent)
        
        self.setWindowTitle("集成父子关系的工具")
        
        # 注意：这里我们移除了 QtCore.Qt.WindowStaysOnTopHint
        # 改为使用 QtCore.Qt.Window，使其作为独立窗口运行，但属于主窗口的子窗口
        self.setWindowFlags(QtCore.Qt.Window)
        self.resize(300, 150)
        
        layout = QtWidgets.QVBoxLayout()
        self.label = QtWidgets.QLabel("尝试最小化 MotionBuilder\n你会发现这个窗口也会跟着最小化！")
        layout.addWidget(self.label)
        self.setLayout(layout)

# === 启动逻辑 ===
if 'my_mobu_tool' in globals():
    try:
        my_mobu_tool.close()
        my_mobu_tool.deleteLater()
    except:
        pass

# 获取主窗口
mobu_main_win = get_mobu_main_window()

# 实例化时，将主窗口作为 parent 传入
my_mobu_tool = MoBuPySideTool(parent=mobu_main_win)
my_mobu_tool.show()
```

#### 注意事项

- **`setWindowFlags(QtCore.Qt.Window)` 是必须的**：即便你设置了 Parent，如果不加这个 Flag，Qt 会尝试将你的部件作为普通控件嵌入到 MotionBuilder 的主 UI 布局内部（通常会导致工具不可见或 UI 崩溃）。加上这个 Flag 告诉 Qt：“我有父级，但我是一个独立的浮动窗口”。
- 在极少数早期的 MotionBuilder 架构中，如果这种方法获取不到准确的窗口（返回 `None`），通常开发者会使用 Python 的 `ctypes` 模块结合 Windows API (`win32gui.FindWindow`) 去抓取 HWND 句柄，然后再通过 `shiboken` 转换。但在 MotionBuilder 2017 以后的版本中，上述纯 Qt 方法已经足够稳定且跨平台。
