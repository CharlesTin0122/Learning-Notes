# 1.04 MoBu MCP 编写指南 —— 为 MotionBuilder 搭建远程 Python 执行桥

> 让 AI Agent（Hermes/Claude 等任何 MCP 客户端）在 MotionBuilder 内远程执行 Python 代码。
> 代码仓库：`D:\Code\MoBuMCP`。架构与 maya-mcp 相同，可套用到任意 DCC（Houdini/Blender/3ds Max）。
> 实战案例：[MoBu-MetaHuman面部驱动实战](../../Unreal/MetaHuman/5.4-MoBu-MetaHuman面部驱动实战-OpenRigLogic.md) 的全部 MoBu 操作都通过本桥完成。

## 一、要解决的问题

AI Agent 运行在自己的进程里（Hermes venv / Node 等），而 DCC 软件的 Python 解释器**内嵌在 DCC 进程内**——`pyfbsdk` 只在 MotionBuilder 里 import 得到。要让 Agent 操作 MoBu 场景，必须跨进程通信。

MCP（Model Context Protocol）是 AI Agent 调用外部工具的标准协议，于是整体链路：

```
Hermes (MCP client)
   ↕ stdio（MCP 协议）
server/mobu_mcp_server.py            ← MCP 服务器，跑在 Hermes venv 的 Python 里
   ↕ TCP 127.0.0.1:4600（JSON 行协议）
mobu_side/mobu_command_server.py     ← 监听器，跑在 MoBu 进程内（pyfbsdk 可用）
   ↕ OnUIIdle 任务队列
MoBu 主线程 exec 代码 → 操作场景
```

两段式设计的原因：
- **MCP 服务器不能跑在 MoBu 里**——MCP 用 stdio 通信，而 MoBu 的 stdin/stdout 不归你管；MCP SDK 也未必装得进 MoBu 的 Python
- 所以 MCP 服务器独立成进程（依赖随便装），与 MoBu 之间用最朴素的 **TCP + newline-delimited JSON** 通信

## 二、MoBu 端监听器（核心：线程模型）

完整源码 `mobu_side/mobu_command_server.py`（~150 行），三个组成部分：

### 2.1 关键约束：pyfbsdk 不允许跨线程

**这是整个设计的出发点。** socket 线程里直接调 `FBSystem()` 等场景 API 会崩溃或行为异常。解法：socket 线程只收发，代码排队到 `FBSystem().OnUIIdle` 回调，**在主线程执行**：

```python
import queue, threading
from pyfbsdk import FBSystem

_task_queue = queue.Queue()

def _on_ui_idle(control, event):
    """OnUIIdle 回调：清空任务队列（主线程）。"""
    while True:
        try:
            request, done, holder = _task_queue.get_nowait()
        except queue.Empty:
            return
        holder["response"] = _execute(request)   # 主线程 exec
        done.set()                               # 唤醒等待的 socket 线程

FBSystem().OnUIIdle.Add(_on_ui_idle)
```

socket 线程投递任务后用 `threading.Event` 等结果：

```python
done = threading.Event()
holder = {}
_task_queue.put((request, done, holder))
if done.wait(timeout):                # 等主线程执行完
    response = holder["response"]
else:
    response = {"ok": False, "error": f"执行超时（>{timeout}s）..."}
```

这个模型的行为特征（使用时要心里有数）：
- MoBu **空闲时**任务几乎即时执行；**播放/渲染/卡死时** OnUIIdle 不触发，任务一直排队直到超时
- 长任务会阻塞 MoBu UI（和在 Python Editor 里直接跑一样）
- 超时只是放弃等待，**任务本身仍会执行**（无法安全终止主线程里的 exec）

### 2.2 代码执行器：exec + 入口函数约定

请求带 `code`（源码）和 `main_function`（入口函数名），执行器 exec 源码后调用入口函数，返回值 repr 回传；stdout 与异常全部捕获：

```python
import io, traceback

def _execute(request):
    captured = io.StringIO()
    import sys
    old_stdout = sys.stdout
    sys.stdout = captured            # 捕获 print 输出
    try:
        namespace = {"__name__": "__mobu_mcp__"}
        exec(compile(request["code"], "<mobu-mcp>", "exec"), namespace)
        fn = namespace.get(request["main_function"])
        if not callable(fn):
            raise NameError(f"入口函数不存在: {request['main_function']}")
        return {"ok": True, "result": repr(fn()), "stdout": captured.getvalue()}
    except Exception:
        return {"ok": False, "error": traceback.format_exc(), "stdout": captured.getvalue()}
    finally:
        sys.stdout = old_stdout
```

**为什么用入口函数约定**而不是直接 exec 表达式：AI 生成的代码天然是"定义函数+辅助逻辑"结构；约定入口函数让返回值语义明确，也方便超时参数按请求传递。

### 2.3 TCP 服务：newline-delimited JSON

```python
协议（每行一个 JSON）:
请求: {"code": "def f():\n    return 1", "main_function": "f", "timeout": 30}
成功: {"ok": true, "result": "1", "stdout": ""}
失败: {"ok": false, "error": "<traceback>", "stdout": "..."}
```

选它的理由：无依赖（json+socket 都是标准库，MoBu 内什么都不用装）、可 telnet 调试、天然支持流式分帧（`buf.split(b"\n", 1)`）。

服务启动/停止封装成全局函数，直接 exec 本文件即启动：

```python
def MOBU_MCP_START():
    _server_socket = socket.socket(...)
    _server_socket.bind(("127.0.0.1", 4600)); _server_socket.listen(4)
    FBSystem().OnUIIdle.Add(_on_ui_idle)
    threading.Thread(target=_server_loop, daemon=True).start()

def MOBU_MCP_STOP():   # Python Editor 里可随时停
    _stop_flag.set(); _server_socket.close()
    FBSystem().OnUIIdle.Remove(_on_ui_idle)
```

⚠️ 安全提醒：这是**任意代码执行**服务，务必只绑 `127.0.0.1`，不要绑 `0.0.0.0`。

## 三、MCP 服务器端

完整源码 `server/mobu_mcp_server.py`（~100 行）。用官方 python-sdk 的 **FastMCP**，把"发 TCP 请求"包装成 MCP 工具：

```python
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("mobu-mcp")

@mcp.tool()
def mcp_run_python_code_in_mobu(python_code: str = DEFAULT_CODE,
                                main_function: str = "get_mobu_python_version",
                                timeout: int = 30) -> str:
    """在 MotionBuilder 中执行一段 Python 代码，并返回执行结果或报错信息。
    ...（docstring 就是 AI 看到的工具说明，要写使用建议）
    """
    response = _send_to_mobu({"code": python_code, "main_function": main_function,
                              "timeout": timeout}, timeout=float(timeout))
    return json.dumps(response, ensure_ascii=False)

@mcp.tool()
def mcp_mobu_status() -> str:
    """检查 MotionBuilder 命令监听器的连接状态与 MoBu 版本信息。"""
    ...

if __name__ == "__main__":
    mcp.run()          # stdio 模式
```

编写要点：

1. **docstring 即提示词**：`@mcp.tool()` 的函数 docstring 会原样呈现给 AI——把使用建议写进去（"先查环境信息再写业务代码"、"修改场景遵循 查询→修改→验证"、"复杂任务分小步"）
2. **默认参数即自检**：`python_code` 默认值是一段查版本的代码，AI 无参调用即可探测环境
3. **错误信息要可操作**：连接拒绝时明确告诉 AI"1. MoBu 是否启动 2. 监听器是否运行"，而不是裸 traceback
4. **再提供一个轻量 status 工具**：探活比跑代码便宜，AI 会先用它确认连通

### 4.4 绕过 MCP 直连 TCP（备用通道）

老会话没加载 MCP 工具、或想在任意脚本里调用时，直接发 TCP：

```python
import json, socket

code = '''
def f():
    from pyfbsdk import FBSystem
    return FBSystem().Version
'''
with socket.create_connection(("127.0.0.1", 4600), timeout=60) as conn:
    conn.sendall(json.dumps({"code": code, "main_function": "f",
                             "timeout": 30}).encode() + b"\n")
    buf = b""
    while b"\n" not in buf:
        buf += conn.recv(65536)
print(json.loads(buf.split(b"\n", 1)[0].decode()))
```

## 五、跨调用状态保持技巧

每次请求的 `namespace` 是新建的，但**同一 MoBu 进程内 sys.modules 是共享的**。两种保持状态的方式：

```python
# 方式1: 正式模块（推荐）——写成 .py 文件后 import，天然常驻
import sys
sys.path.insert(0, r"D:/Code/MoBuMetaHuman")
import mh_face_preview as mhfp        # 后续每次调用都能拿到同一模块实例

# 方式2: 动态挂载临时模块——探索阶段用
G = sys.modules.setdefault("__my_state__", type(sys)("__my_state__"))
G.data = [...]                        # 下次调用 sys.modules.get("__my_state__") 取回
```

⚠️ 配套的坑：**`importlib.reload` 前必须先停掉旧模块挂的所有 OnUIIdle 回调**，否则旧回调对象成为无法 Remove 的幽灵，与新回调同帧打架（表现为关节值在两个数之间跳动）。排查法见 mobu-metahuman-face-preview 技能。

## 七、移植到其他 DCC

本架构可原样套用，只需替换两处：

| DCC | 主线程调度机制 | 替换 OnUIIdle 的方案 |
|---|---|---|
| Maya | `maya.utils.executeDeferred` / `executeInMainThreadWithResult` | 直接用后者，连队列都省了 |
| Houdini | `hdefereval.executeDeferred` | 同上 |
| Blender | `bpy.app.timers.register` | 定时器轮询任务队列 |
| 3ds Max | `pymxs` + `execute_on_main_thread` | 同 Maya |

端口错开（maya-mcp 常用 4500 系，本项目用 4600），MCP 服务器几乎不用改——换个名字和错误提示即可。
