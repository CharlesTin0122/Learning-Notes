`pyfbsdk` 是 Autodesk MotionBuilder 的核心 Python API 库。它是 MotionBuilder C++ SDK 的 Python 封装，允许开发者、技术美术（TA）和动画师通过编写 Python 脚本来自动化任务、操作场景数据、绑定角色、处理动画以及开发自定义工具和用户界面。

下面是对 `pyfbsdk` 及其常用功能的系统介绍：

# 一、 核心架构与基础概念

## 1. 核心继承体系 (The Inheritance Hierarchy)

在 `pyfbsdk` 中，类之间有非常严格的继承关系。当你拿到一个对象时，如果你知道它的父类是谁，你就能知道它可以使用哪些方法。以下是最核心的“族谱”：

- **`FBPlug` (插头/接口)**  
    这是整个架构的最底层基类之一。在 MoBu 中，数据是在不同的节点之间流动的，`FBPlug` 就代表了可以进行“连接”的节点端点。它主要处理数据的输入和输出。
- **`FBComponent` (组件)**  
    继承自 `FBPlug`。这是场景中几乎所有实体的基类。无论是材质、材质球、约束、动画层，还是 3D 模型，它们本质上都是 `FBComponent`。它提供了一个对象的基本属性，比如名字 (`Name`)、描述和是否被选中 (`Selected`)。
- **`FBBox` (功能盒/计算节点)**  
    继承自 `FBComponent`。在 MoBu 的动画节点图（类似于虚幻引擎的蓝图或 Maya 的 Node Editor）中，一个 `FBBox` 代表一个处理数据的黑盒。它可以有多个输入插槽和输出插槽。约束（Constraints）和动画运算节点都继承自它。
- **`FBModel` (3D 模型)**  
    继承自 `FBBox`。这是我们在 3D 视图中能实际看到和操作的对象的基类。它包含了空间变换信息（位移、旋转、缩放），以及显示属性（可见性、颜色）。相机 (`FBCamera`)、灯光 (`FBLight`)、骨骼 (`FBModelSkeleton`) 和几何体 (`FBModelCube` 等) 都是它的子类。

## 2. 属性系统 (FBProperty)

MotionBuilder 中的对象数据几乎都是通过 `FBProperty` 来管理的，而不是普通的 Python 变量。

- **特点**：每个属性都知道自己的数据类型（如浮点数、颜色、字符串），并且可以被标记为“可动画的”（Animatable）。
- **动态访问**：你可以通过 `对象.PropertyList` 遍历一个对象所有的属性。
- **自定义数据**：你可以非常方便地给任何 `FBComponent` 添加自定义属性（Custom Properties），这在开发绑定工具或导出游戏引擎数据时非常常用。

```python
from pyfbsdk import * model = FBFindModelByLabelName("Cube")
# 访问内置属性
model.Visibility.Data = True
# 遍历属性
for prop in model.PropertyList: print(prop.Name)
```

## 3. 连接系统 (Connections / Src & Dst)

由于 MoBu 是一个节点系统，对象之间的关系往往通过**连接（Connection）**来维持，而不是单纯的父子层级。

- **源与目标**：在 API 中，连接分为源（Source/Src）和目标（Destination/Dst）。
- **应用场景**：比如，一个材质 (`FBMaterial`) 是怎么赋给一个模型 (`FBModel`) 的？在底层，实际上是材质作为 `Src` 连接到了模型的 `Dst` 插槽上。约束（Constraint）控制模型也是同理。

```python
# 伪代码：了解连接的逻辑
# objectA.ConnectSrc(objectB)  # 将 B 作为源连接到 A
# objectA.GetSrcCount()        # 获取 A 身上连接了多少个源节点
# objectA.GetSrc(0)            # 获取第一个源节点
```

## 4. 系统的两大入口 (Singletons)

当你需要从宏观层面控制软件时，系统提供了两个全局单例：

- **`FBSystem` (数据入口)**：  
    它管理着当前运行时的所有数据。你找模型、找材质、找动画层、管理场景时间，都要经过它。最重要的属性是 `FBSystem().Scene`，它包含了当前场景里的所有列表（`Scene.Models`, `Scene.Materials`, `Scene.Constraints` 等）。
- **`FBApplication` (软件操作入口)**：  
    它管理软件本身的操作。比如打开文件 (`FileOpen`)、保存文件 (`FileSave`)、新建场景 (`FileNew`)、刷新 UI (`FileRender`) 或执行撤销/重做。

## 5. 时间与求值 (Time & Evaluation)

动画软件的核心是时间。

- **`FBTime`**：这是 MoBu 中表示时间的类。它不是简单的浮点数或帧数，而是一种高精度的内部时间单位。你可以用它来设置帧率、在“帧”和“时间码”之间转换。
- **Scene.Evaluate()**：当你通过脚本修改了模型的位移或打上了关键帧后，视图有时不会立刻更新。因为 MoBu 的计算引擎（Evaluation Engine）还在上一帧的状态。你需要调用 `FBSystem().Scene.Evaluate()` 强制引擎重新计算节点图，从而更新场景状态。

# 二、 核心单例类 (Singleton Classes)

这些类用于获取全局的系统和应用程序状态。

- **`FBSystem()`**: 访问系统级别的资源，如场景(`Scene`)、当前时间、本地时间格式等。
- **`FBApplication()`**: 控制应用程序级别的操作，如新建场景、打开/保存文件、刷新屏幕等。

```python
# 获取系统和应用实例
sys = FBSystem()
app = FBApplication()

# 新建场景
app.FileNew()

# 遍历场景中的所有模型
for model in sys.Scene.Models:
    print(model.Name)
```

# 三、 常用功能与代码示例

#### 1. 场景对象的查找、创建与删除

在 MotionBuilder 中操作对象，最基础的是找到它们或创建它们。

```python
from pyfbsdk import *

# 查找对象 (根据名字)
my_model = FBFindModelByLabelName("Cube") 
if my_model:
    print(f"找到了: {my_model.Name}")

# 创建对象
new_cube = FBModelCube("MyNewCube")
new_cube.Visible = True
new_cube.Show = True

# 删除对象
if my_model:
    my_model.FBDelete()
```

#### 2. 变换操作 (Transformations)

操作对象的位移（Translation）、旋转（Rotation）和缩放（Scaling）。MoBu 使用 `FBVector3d` 来处理三维向量。

```python
from pyfbsdk import *

cube = FBModelCube("MoveCube")
cube.Visible = True

# 设置位移
translation_vector = FBVector3d(10, 50, 0)
cube.SetVector(translation_vector, FBModelTransformationType.kModelTranslation, True)

# 获取旋转
rotation_vector = FBVector3d()
cube.GetVector(rotation_vector, FBModelTransformationType.kModelRotation, True)
print(f"X: {rotation_vector[0]}, Y: {rotation_vector[1]}, Z: {rotation_vector[2]}")
```

_注：`SetVector` 和 `GetVector` 最后的布尔值参数 `True` 代表全局坐标（Global），`False` 代表局部坐标（Local）。_

#### 3. 属性 (Properties) 操作

MotionBuilder 中的对象有许多属性（如可见性、自定义数据等）。

```python
# 访问标准属性
cube.Visibility.Data = False

# 创建自定义属性
prop = cube.PropertyCreate("MyCustomAttr", FBPropertyType.kFBPT_double, "Number", False, True, None)
if prop:
    prop.Data = 99.5
    prop.SetAnimated(True) # 允许为该属性打关键帧
```

#### 4. 动画与关键帧 (Animation & FCurves)

这是 MotionBuilder 的核心。动画数据存储在 `FCurve` 中，通过 `FBAnimationNode` 访问。

```python
from pyfbsdk import *

cube = FBModelCube("AnimCube")
cube.Visible = True

# 激活对象的动画节点
cube.Translation.SetAnimated(True)

# 获取 X 轴的动画节点和 FCurve (函数曲线)
anim_node = cube.Translation.GetAnimationNode()
node_x = anim_node.Nodes[0] # 0=X, 1=Y, 2=Z
fcurve_x = node_x.FCurve

if not fcurve_x:
    # 如果没有 FCurve，新建一个
    fcurve_x = node_x.CreateFCurve()

# 打关键帧
time = FBTime()

# 第 0 帧
time.SetFrame(0)
fcurve_x.KeyAdd(time, 0.0)

# 第 30 帧
time.SetFrame(30)
fcurve_x.KeyAdd(time, 100.0)

# 刷新时间轴以查看动画
FBSystem().Scene.Evaluate()
```

#### 5. 约束与角色绑定 (Constraints & Characters)

`pyfbsdk` 允许创建和管理约束（如 Parent/Child 约束、IK/FK）以及管理 Character 引擎。

```python
from pyfbsdk import *

# 创建父子约束
constraint = FBConstraintManager().TypeCreateConstraint(2) # 2 通常是 Parent/Child 约束类型
constraint.Name = "MyParentConstraint"

# 假设已有 parent_model 和 child_model
# constraint.ReferenceAdd(0, child_model)  # Constrained object
# constraint.ReferenceAdd(1, parent_model) # Source object
# constraint.Active = True
```

# 四、 辅助库：`pyfbsdk_additions`

除了核心的 `pyfbsdk`，MotionBuilder 通常还内置了 `pyfbsdk_additions`。这个库主要用于：

1. **构建自定义 UI**：提供快速创建工具窗口、按钮、列表等界面的类（如 `FBCreateUniqueTool`, `FBButton`）。
2. **便捷操作**：包含一些封装好的高级函数，简化复杂的 API 调用。

# 五、 学习与开发建议

1. **官方文档查阅**：MotionBuilder 的帮助菜单中附带了详细的 Python SDK Help，这是最权威的参考手册（包含完整的类方法和属性列表）。
2. **内置脚本示例**：在 MotionBuilder 的安装目录下（通常是 `C:\Program Files\Autodesk\MotionBuilder <版本号>\bin\config\Scripts`）有大量的官方示例脚本，非常值得学习。
3. **使用 `dir()` 函数**：在 MoBu 的 Python 控制台中，经常使用 `dir(object)` 来查看一个对象有哪些方法和属性，这对于摸索 API 极其有效。
# 五、与maya的对比

这是一个非常经典且重要的问题。对于很多从 Maya 转向 MotionBuilder，或者需要同时开发两款软件工具的技术美术（TA）来说，理解这两者的异同至关重要。

简单来说：**在底层概念上，它们非常相似（都是基于节点的依赖图）；但在编程范式和代码书写习惯上，它们有极大的区别。**

我们可以从以下几个核心维度来对比 `pyfbsdk` 和 Maya 的 API（主要以大家最常用的 `maya.cmds` 为例）：

### 1. 最大的区别：面向对象 (OOP) vs 命令式 (Procedural)

这是两者在使用时最直观的差异。

- **Maya (`maya.cmds`) 主要是命令式和基于字符串的。** 在 Maya 中，你很少直接拿到一个“对象”，你操作的其实是对象名字（字符串）。你需要调用各种全局命令，把名字传进去。
- **MotionBuilder (`pyfbsdk`) 是纯粹的面向对象 (OOP) 的。** 在 MoBu 中，你拿到的是实实在在的 Python 对象实例。你通过访问这个对象的属性和方法来修改它。

**代码对比：移动一个名为 "Cube" 的物体**

- **Maya (`maya.cmds`) 方式：**
    
    ```python
    import maya.cmds as cmds
    # 基于字符串名字进行操作
    cmds.setAttr("Cube.translateX", 10)
    ```
    
- **MotionBuilder (`pyfbsdk`) 方式：**
    
    ```python
    from pyfbsdk import *
    # 先找到对象实例
    cube = FBFindModelByLabelName("Cube")
    # 直接修改对象属性
    cube.Translation.Data = FBVector3d(10, 0, 0)
    ```
    

_注：如果非要找一个 Maya 里跟 `pyfbsdk` 风格类似的库，那应该是 **PyMEL** 或者是底层的 **OpenMaya (API 2.0)**。`pyfbsdk` 在使用体验上，介于 PyMEL 的易用性和 OpenMaya 的底层架构之间。_

### 2. 底层架构的相似点：节点与连接 (Nodes & Connections)

正如前面提到的，两款软件底层都是一个庞大的“依赖图”（Dependency Graph）。

- **Maya**：属性（Attribute）之间通过 `cmds.connectAttr()` 连接。
- **MotionBuilder**：插头（`FBPlug`）之间通过 `Src` 和 `Dst` 连接。

在处理复杂的绑定（Rigging）或约束时，两者的逻辑是互通的：都是让数据从一个节点的输出端，流向另一个节点的输入端。

### 3. 动画与时间轴 (Animation & Time)

这是 MotionBuilder 作为专业动画软件的特色所在，也是两套 API 差异较大的地方。

- **多时间轨系统 (Takes)**：
    - Maya 通常只有一个全局时间轴。
    - MotionBuilder 拥有强大的 **Take** 系统（类似于非编软件的多个剪辑轨道）。在 `pyfbsdk` 中，你需要通过 `FBSystem().Scene.Takes` 来管理不同的 Take，切换 Take 会导致场景动画数据的完全切换。
- **关键帧访问**：
    - Maya 使用 `cmds.setKeyframe()`，非常直接。
    - MotionBuilder 中，你需要先获取对象的动画节点（`FBAnimationNode`），然后再获取具体的函数曲线（`FCurve`），最后才能在 `FCurve` 上添加关键帧。MoBu 的方式更底层，但也提供了更细粒度的控制。

### 4. 角色化引擎 (Characterization)

MotionBuilder 的核心竞争力是它的 HumanIK (HIK) 实时解算引擎。

- 在 Maya 中，虽然也有 HIK，但通过 Python 深入控制 HIK 往往比较繁琐。
- 在 `pyfbsdk` 中，有专门的 `FBCharacter` 类。你可以非常方便地通过代码将一套骨骼映射到 HIK 节点（如 `FBBodyNodeId.kFBHeadNodeId`），并开启或关闭 IK/FK 解算。这在处理动捕数据重定向（Retargeting）时是极其常用的。

### 总结建议

如果你已经熟悉 `maya.cmds`，转向 `pyfbsdk` 时，**需要转换思维方式：从“调用命令处理字符串”转变为“获取对象操作属性”**。

在查阅文档时，不要去寻找类似 `cmds.ls()` 或 `cmds.xform()` 这样的全局函数，而是去思考：“我要找的东西属于哪个类（Class）？它是 `FBModel` 还是 `FBComponent`？我应该访问它的哪个属性（Property）？” 建立了这种面向对象的思维，学习 `pyfbsdk` 就会非常迅速。
