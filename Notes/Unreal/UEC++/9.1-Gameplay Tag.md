# 概述
- **Gameplay标记** 是概念性分层标签，使用用户定义的名称。这些标记可以有任意数量的分层级别，以"."符号分隔，例如，有三个级别的Gameplay标记将采用形式"Family.Genus.Species"，其中"Family"是这个层级中最广泛的标识符，而"Species"是最具体的标识符。"Family.Genus.Species"的存在暗示着"Family.Genus"和"Family"Gameplay标记也存在。
- 单个标记是轻量级的，使用类型[`FGameplayTag`](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/GameplayTags/FGameplayTag?application_version=5.0)。由于游戏对象经常有多个标记，因此提供了 **Gameplay标记容器**（使用类型[`FGameplayTagContainer`](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/GameplayTags/FGameplayTagContainer?application_version=5.0)），它可以处理多种附加查询。
- Gameplay标记（或Gameplay标记容器）可以添加到任意项目，将对象与概念标签关联起来，继而使用标签来为您的项目识别、匹配、分类或过滤对象（根据需要）。
#  创建
Gameplay标记必须添加到中央标记词典，引擎才能知道这些标记的存在。这可以通过编辑器功能，用三种方式来实现。您可以通过三种方式来创建（或删除）标记：

- 在 **项目设置（Project Settings）** 菜单中手动添加或移除。
	- 添加Gameplay标记的最简单方法是在 **项目设置（Project Settings）** 菜单中手动输入。通过选中 **从配置导入标记（Import Tags From Config）** 选项，将会加载`Config/DefaultGameplayTags.ini`，以及`Config/Tags`目录中找到的任何.ini文件中的所有Gameplay标记。这样将出现标有 **添加新Gameplay标记（Add New Gameplay Tag）** 的选项，该选项可以用于向任何现有的Gameplay标记.ini文件（包括默认文件）添加新的Gameplay标记。以这种方式添加的标记还有一个可选字段，用于输入将在编辑器中作为工具提示显示的简短描述。
	- ![](attachments/9.1-Gameplay%20Tag.png)
- 通过在"GameplayTags"文件夹中创建和编辑.ini文件。
	- 要使用您自己的.ini文件添加标记，必须启用 **从配置导入标记（Import Tags From Config）** 选项。然后可以从项目`Config/Tags/`路径下的每个.ini文件加载Gameplay标记，这些文件手动编辑十分容易。如果进行这些编辑时编辑器仍在运行，关闭 **从配置导入标记（Import Tags From Config）** 选项然后再打开，可以重新加载这些文件。
	- ![](attachments/9.1-Gameplay%20Tag-1.png)
- 通过构建数据表资源。
	- 最后，标记可以通过[数据表](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/data-driven-gameplay-elements-in-unreal-engine?application_version=5.0#datatables)资源添加，使用行类型为`GameplayTagTableRow`。这对于从外部源导入Gameplay标记尤其有用，如Excel电子表格文件，但您可以不必导入文件而创建自己的标记，并在编辑器中处理标记。创建资源后，将它添加到 **项目设置（Project Settings）** 菜单中的 **Gameplay标记表的列表（GameplayTagTableList）**，其中包含的所有标记都会添加到 **Gameplay标记管理器（Gameplay Tag Manager）**。请注意，该系统支持列出多个资源，因此您可以将项目标记拆分到不同的电子表格中（如果对您的工作流或组织有益）。
	- ![创建数据表DataTable](attachments/9.1-Gameplay%20Tag-2.png)![](attachments/9.1-Gameplay%20Tag-3.png)![](attachments/9.1-Gameplay%20Tag-4.png)

所有三种方法都在 **项目设置（Project Settings）** 中，打开 **Gameplay标记（Gameplay Tags）** 选项卡，在 **项目（Project）** 部分下设置。
# 管理
- 添加Gameplay标记后，您可以搜索对它们的引用、删除或重命名来进行管理。所有这些操作都可以使用 **项目设置（Project Settings）** 菜单中的标记旁边的插入符号下拉菜单进行访问。如果标记是通过.ini文件添加的（无论是手动编辑还是通过 **项目设置（Project Settings）** 菜单添加），则只能在该菜单中将其删除，且不能被进行任何引用。重命名标记会导致向GameplayTagRedirects列表中添加标记，任何重命名的标记都会在加载时被静默修复。

## 编辑限制
- Gameplay标记编辑器支持根据一列授权用户，限制层级中任意级别的Gameplay标记编辑。要使用Gameplay标记编辑限制，打开 **项目设置（Project Settings）**，并在 **Gameplay标记（GameplayTags）** 部分下面，展开 **高级Gameplay标记（Advanced Gameplay Tags）** 层级。要限制对一组Gameplay标记的编辑，必须先指定.ini文件来存储标记，但不要命名为"DefaultGameplayTags.ini"。还应当指定受限标记的所有者，这样用户想要编辑时就知道可以联系谁。最后，Gameplay标记本身可以添加到"受限标记列表"，在这里标记会标有一个复选框，表示是否允许未列出用户向他们添加子代。如果用户（除列出所有者以外）尝试编辑"受限标记列表"，将会弹出警告，要求用户确认他们获得了所有者的授权。如果用户不选择"是"，则无法进行编辑。
# 测试运算
- 有许多测试运算都基于将标记与其他标记匹配的概念，可以对Gameplay标记和Gameplay容器执行。每个函数将对Gameplay标记或Gameplay标记容器调用，并以单个Gameplay标记或Gameplay标记容器为参数。
- 格式"A.1"表示单个Gameplay标记，而"{A.1}"表示作为Gameplay标记容器一部分的同一个标记。包含多个标记的容器将采用格式"{A.1, B.1}"。

| 源          | 函数/运算                   | 描述          | 输入参数   | 返回值   |
| ---------- | ----------------------- | ----------- | ------ | ----- |
| A.1        | MatchesTag              | 匹配标签        | A      | true  |
| A.1        | MatchesTagExact (or ==) | 精确匹配标签      | A      | false |
| A.1        | MatchesAny              | 容器中任意一个匹配   | {A, C} | true  |
| A.1        | MatchesAnyExact         | 容器中任意一个精确匹配 | {A, C} | false |
| A.1        | MatchesAll              | 全部匹配        | {A}    | true  |
| A.1        | MatchesAllExact         | 全部精确匹配      | {A}    | false |
| {A.1, B.1} | HasTag                  | 是否包含        | A      | true  |
| {A.1, B.1} | HasTagExact             | 是否精确包含      | A      | false |
| {A.1, B.1} | HasAny                  | 容器中任意一个包含   | {A, C} | true  |
| {A.1, B.1} | HasAnyExact             | 容器中任意一个精确包含 | {A, C} | false |
| {A.1, B.1} | HasAll                  | 所有元素包含      | {A, B} | true  |
| {A.1, B.1} | HasAllExact             | 所有元素精确包含    | {A, B} | false |
- 请注意，提供空的或默认的Gameplay标记容器作为输入参数会导致所有运算都返回false，但`HasAll`、`HasAllExact`、`MatchesAll`和`MatchesAllExact`除外。理由是参数容器中没有源集中缺少的标记。
# 查询
可以对Gameplay标记容器执行的封装特定类型测试中的 **Gameplay标记查询** 变量。您可以使用它们以数据驱动测试，在许多地方执行相同的测试，而不必变动及多个变量或多段代码，并通过原生代码执行大部分工作来加速测试。Gameplay标记查询可以执行以下任意三种类型的测试。

- 如果在容器中找到来自查询的至少一个标记，**任何标记匹配** 就会成功。
- 如果查询中没有标记，也没有在容器中没有找到标记，**所有标记匹配** 就会成功。_这包括查询中不存在任何标记的情况。_
- 如果查询中没有标记，而在容器中到了标记，**无标记匹配** 就会成功。_这包括查询中不存在任何标记的情况。_

但是，这些测试可以通过三个更大的表达式合并起来，其中每个表达式包含一个额外表达式或测试的数组：

- 任何一个子表达式或测试成功时，**任意表达式匹配** 就会成功。
- 所有子表达式或测试都成功时，**所有表达式匹配** 就会成功。_这包括查询中不存在子表达式或测试的情况。_
- 子表达式或测试均不成功时，**无表达式匹配** 就会成功。_这包括查询中不存在子表达式或测试的情况。

# 在游戏中使用

要将您创建的标记应用于游戏中的对象，向对象添加Gameplay标记（C++类型`FGameplayTag`）或Gameplay标记容器（C++类型`FGameplayTagContainer`）属性。您还可以根据需要向对象添加 **Gameplay标记查询（Gameplay Tag Queries）**（C++类型`FGameplayTagQuery`），或者可以直接在蓝图或C++代码中使用标记运算。添加这些属性后，可以从代码或编辑器编辑，就像任何其他变量一样。

# 在C++中快速访问

`IGameplayTagAssetInterface`可以在C++中实现。同时覆盖`GetOwnedGameplayTags`函数，将会创建一种蓝图可访问方式，以使用与该对象关联的标记填充Gameplay标记容器。在大多数情况下，这只表示从基类将标记复制到新容器，但类实现可能会从多个容器收集标记，或者调用蓝图函数来访问蓝图声明的标记或者对象需要的任何内容。该接口的好处是使您可以一种标准化方法与多个不同的对象类型互动，这样可以获取对象的标记，而不必显式转换对象类型，然后为每个可能的类型编写自定义代码来获取正确的标记变量（或多个变量）。这对于较大项目尤其有用，可以帮助避免（难以重现的）错误，让代码更简洁、更快速、更易于维护。

# 使用C++定义标签

你可以使用 `NativeGameplayTags.h` 中定义的以下宏，通过C++来定义Gameplay标签：

- `UE_DECLARE_GAMEPLAY_TAG_EXTERN` ：在 `.h` 文件中用于声明 `.cpp` 文件中定义的标签。
- `UE_DEFINE_GAMEPLAY_TAG` ：在 `.cpp` 文件中用于定义 `.h` 文件中声明的标签，不带提示文本注释。
- `UE_DEFINE_GAMEPLAY_TAG_COMMENT` ：在 `.cpp` 文件中用于定义 `.h` 文件中声明的标签，带有提示文本注释。
- `UE_DEFINE_GAMEPLAY_TAG_STATIC` ：在 `.cpp` 文件中用于定义仅对定义文件可用的标签。不同于其他 `DEFINE` 宏，这不应该与 `DECLARE` 宏调用配对。

>你必须将 `GameplayTags` 模块添加到你的项目的 `Build.cs` 文件，才能在C++中访问Gameplay标签功能。

```cpp
//在.build.cs中
PublicDependencyModuleNames.AddRange(new string[] {"Core", "CoreUObject", "Engine", "InputCore", "EnhancedInput","GameplayTags"});

// 在.h文件中
#include "NativeGameplayTags.h"
UE_DECLARE_GAMEPLAY_TAG_EXTERN(Movement_Mode_Walking);

// 在.cpp文件中
UE_DEFINE_GAMEPLAY_TAG_COMMENT(Movement_Mode_Walking, "Movement.Mode.Walking", "Default Character movement tag");
```
# 示例
GameplayTagActor.h
```cpp


#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "NativeGameplayTags.h"//包含GameplayTag头文件
#include "GameplayTagAssetInterface.h"//包含GameplayTag接口头文件

#include "GameplayTagActor.generated.h"


//在 .h 文件中用于声明 .cpp 文件中定义的标签。
UE_DECLARE_GAMEPLAY_TAG_EXTERN(My_Mode_Walking);
UE_DECLARE_GAMEPLAY_TAG_EXTERN(My_Mode_running);

UCLASS()
class QUICKSTART_API AGameplayTagActor : public AActor, public IGameplayTagAssetInterface //继承标签接口
{
	GENERATED_BODY()
	
public:	
	// Sets default values for this actor's properties
	AGameplayTagActor();

protected:
	// Called when the game starts or when spawned
	virtual void BeginPlay() override;

public:	
	// Called every frame
	virtual void Tick(float DeltaTime) override;
	
public:
	//声明 GameplayContainer
	UPROPERTY(BlueprintReadWrite, EditAnywhere, Category = "MyGameplayTag")
	FGameplayTagContainer MyTagContainer;

protected:
	//重写获取拥有的标签函数
	virtual void GetOwnedGameplayTags(FGameplayTagContainer &TagContainer) const override;
};

```

GameplayTagActor.cpp
```cpp



#include "GameplayTagActor.h"

//在 .cpp 文件中用于定义 .h 文件中声明的标签，不带提示文本注释。
UE_DEFINE_GAMEPLAY_TAG(My_Mode_Walking, "My.Mode.Walking");
//在 .cpp 文件中用于定义 .h 文件中声明的标签，带有提示文本注释。
UE_DEFINE_GAMEPLAY_TAG_COMMENT(My_Mode_running, "My.Mode.running", "running tag");


// Sets default values
AGameplayTagActor::AGameplayTagActor()
{
 	// Set this actor to call Tick() every frame.  You can turn this off to improve performance if you don't need it.
	PrimaryActorTick.bCanEverTick = true;

}

// Called when the game starts or when spawned
void AGameplayTagActor::BeginPlay()
{
	Super::BeginPlay();
	
	//在 .cpp 文件中用于定义仅对定义文件可用的标签。不同于其他 DEFINE 宏，这不应该与 DECLARE 宏调用配对。
	UE_DEFINE_GAMEPLAY_TAG_STATIC(My_Mode_Standing, "My.Mode.Standing");
	//容器添加标签
	MyTagContainer.AddTag(My_Mode_Walking);
	MyTagContainer.AddTag(My_Mode_running);
	MyTagContainer.AddTag(My_Mode_Standing);
}

// Called every frame
void AGameplayTagActor::Tick(float DeltaTime)
{
	Super::Tick(DeltaTime);

}
//重写获取拥有的标签函数
void AGameplayTagActor::GetOwnedGameplayTags(FGameplayTagContainer& TagContainer) const
{
	TagContainer.AppendTags(MyTagContainer);
}
```
