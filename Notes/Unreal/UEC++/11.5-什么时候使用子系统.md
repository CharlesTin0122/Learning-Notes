在 **Unreal Engine** 中，`GameInstance` 和 `GameInstanceSubsystem` 都是用来管理游戏中的全局数据和行为的关键类，它们的功能有一定的重叠，但也有不同的适用场景和设计目标。理解它们之间的区别对于如何选择合适的地方来实现游戏逻辑至关重要。

### 1. **GameInstance**

`GameInstance` 是 Unreal Engine 中一个特殊的类，它代表了一个游戏会话的生命周期。`GameInstance` 生命周期贯穿整个游戏（包括游戏的启动和关闭），并且在游戏的不同关卡之间保持持久性。它通常用于存储和管理全局数据或需要跨多个关卡共享的状态。

#### **适合在 `GameInstance` 中实现的功能：**

- **全局游戏设置和管理**： `GameInstance` 是游戏级别的入口点，适合用于存储和管理全局设置。例如，游戏的音量设置、分辨率、语言选择等可以放在 `GameInstance` 中，因为这些设置通常在游戏生命周期内保持不变，并且跨多个关卡都需要访问。
    
- **玩家数据和全局状态**： `GameInstance` 可以存储与玩家相关的全局数据（如玩家的存档数据、经验、得分等），以及与整个游戏状态相关的数据（如是否完成了某个任务、是否解锁了某些成就）。这些数据在整个游戏过程中保持一致，不受关卡切换的影响。
    
- **跨场景共享的数据**： 因为 `GameInstance` 在多个关卡之间保持活跃，因此适合用来管理跨场景的数据。例如，玩家角色的自定义设置（如装备、技能等）通常存储在 `GameInstance` 中。
    
- **网络管理**： 你可以使用 `GameInstance` 来管理与游戏网络相关的功能，比如处理在线多人游戏的连接、网络会话、匹配等。`GameInstance` 在游戏的整个生命周期内保持活动，因此它是处理这些功能的理想位置。
    

**示例：** 在 `GameInstance` 中管理玩家分数

```cpp
// 在 GameInstance 类中实现存储玩家得分的功能
class UMyGameInstance : public UGameInstance
{
    GENERATED_BODY()

public:
    int32 PlayerScore;

    void SetPlayerScore(int32 NewScore) { PlayerScore = NewScore; }
    int32 GetPlayerScore() const { return PlayerScore; }
};
```

#### **GameInstance 的特点：**

- **生命周期长**：`GameInstance` 在游戏开始时创建，直到游戏关闭时销毁，它的生命周期跨越多个关卡。
- **全局可访问**：可以在不同的关卡和场景中访问到它，适合存储全局的数据。
- **通常用于存储与玩家、游戏状态以及全局设置相关的功能**。

---

### 2. **GameInstanceSubsystem**

`GameInstanceSubsystem` 是从 `UGameInstanceSubsystem` 继承的类，它是 Unreal Engine 4.25 引入的。它的设计目的是为了将 `GameInstance` 中的功能进一步模块化，将一些具有特定功能的任务和数据分离到子系统中。它并不像 `GameInstance` 那样持久化存储游戏状态，而是专注于执行某些特定的功能。

#### **适合在 `GameInstanceSubsystem` 中实现的功能：**

- **模块化的功能管理**： `GameInstanceSubsystem` 可以被视为 `GameInstance` 中的功能模块，每个子系统负责一个单独的功能。通过将这些功能分离到独立的子系统中，代码更加模块化，易于维护和扩展。例如，可以创建一个专门管理音频的 `AudioSubsystem` 或一个管理玩家成就的 `AchievementsSubsystem`。
    
- **任务和事件管理**： 如果游戏有一些长期存在但不需要跨关卡保持状态的任务，可以将它们放在 `GameInstanceSubsystem` 中。例如，定时事件的调度、后台的资源加载、成就的跟踪等。
    
- **与其他子系统的交互**： `GameInstanceSubsystem` 提供了一个清晰的机制来将功能分离到不同的子系统中，使得每个子系统可以独立工作。它们之间可以通过 `GameInstance` 进行交互，但每个子系统有自己的初始化和销毁逻辑，确保功能的独立性。
    
- **资源和数据管理**： 如果游戏的某些数据或资源的管理逻辑比较复杂，建议将这些管理逻辑放入 `GameInstanceSubsystem` 中。例如，管理玩家的数据存储和加载，可以将这些操作封装在一个子系统中，便于集中管理。
    

**示例：** 创建一个管理音频设置的子系统

```cpp
// 音频管理子系统的实现
class UAudioSubsystem : public UGameInstanceSubsystem
{
    GENERATED_BODY()

public:
    float VolumeLevel;

    void SetVolume(float NewVolume) { VolumeLevel = NewVolume; }
    float GetVolume() const { return VolumeLevel; }
};
```

#### **GameInstanceSubsystem 的特点：**

- **模块化**：`GameInstanceSubsystem` 是 `GameInstance` 的功能扩展，每个子系统可以处理单独的功能。
- **生命周期**：`GameInstanceSubsystem` 的生命周期与 `GameInstance` 相同，但它只在特定的任务和功能上存活，不会保存全局的状态。
- **用于特定功能**：适合处理有特定目标和功能的模块，如音频、成就、资源加载等。

---

### 3. **`GameInstance` 和 `GameInstanceSubsystem` 的区别**

|特性|**GameInstance**|**GameInstanceSubsystem**|
|---|---|---|
|**用途**|管理游戏的全局状态、设置和跨关卡的数据|管理特定的功能模块，像音频、成就等|
|**生命周期**|从游戏开始到结束，与游戏生命周期一致|与 `GameInstance` 一样，但只处理特定功能的生命周期|
|**存储数据**|存储全局状态、玩家数据等，通常是跨关卡和全局共享的|不存储全局状态，仅负责管理某一特定功能的行为|
|**适用场景**|管理游戏的主要逻辑，如游戏进度、设置、跨关卡数据等|模块化管理特定功能，如资源加载、成就、音频设置等|
|**访问方式**|在 `GameInstance` 中直接访问|通过 `GetSubsystem` 从 `GameInstance` 中访问|

---

### 4. **总结**

- **`GameInstance`**：适合用于存储和管理全局状态、跨关卡的数据、网络连接等长期存在的数据。它是整个游戏生命周期中持久化的数据存储和管理中心。
- **`GameInstanceSubsystem`**：用于将 `GameInstance` 中的功能进行模块化，将特定的功能封装在子系统中，以便更好地组织和扩展游戏逻辑。它让你可以将功能拆分成多个独立的单元，每个单元只关注特定的任务。

总之，`GameInstance` 用于存储和管理跨游戏生命周期的数据，而 `GameInstanceSubsystem` 用于功能的模块化管理，适合存放与游戏的特定功能相关的代码和数据。

# 子系统并非单例

在 **Unreal Engine** 中，`GameInstanceSubsystem` 并不是一个单例，它允许你为游戏中的不同功能实现多个子类。这些子类可以独立地实现各自的功能模块，每个子系统专注于特定的任务，因此你可以创建多个继承自 `GameInstanceSubsystem` 的子类，以满足不同需求。

### 更详细的解释：

#### **GameInstanceSubsystem 不是单例**

`GameInstanceSubsystem` 的设计并不像 `GameInstance` 那样是单例模式（一个类的实例全局唯一）。相反，`GameInstanceSubsystem` 允许在 `GameInstance` 中创建多个不同类型的子系统实例。每个子系统都是独立的，并且可以执行不同的功能。例如，你可以在 `GameInstance` 中拥有多个子系统实例，分别管理音频、成就、资源加载等功能。

#### **可以有多个子系统实例**

每个继承自 `UGameInstanceSubsystem` 的类都可以被视为一个功能模块。你可以在项目中实现多个不同的子系统类，每个子系统专注于特定的任务。比如：

- `UMyAudioSubsystem`：负责管理音频设置、音量等。
- `UMyAchievementsSubsystem`：管理玩家的成就和奖励系统。
- `UMyResourceManagementSubsystem`：处理资源的加载和管理。

这些子系统相互独立，且可以在 `GameInstance` 中同时存在。

#### **如何使用多个子系统**

在 `GameInstance` 中，你可以通过 `GetSubsystem` 方法来访问特定的子系统实例。Unreal Engine 会根据 `UGameInstanceSubsystem` 类自动管理每个子系统的生命周期，所以你不需要手动管理这些实例。

举个例子：

假设你有两个子系统，一个是音频管理，另一个是成就管理：

```cpp
// 音频子系统
class UAudioSubsystem : public UGameInstanceSubsystem
{
    GENERATED_BODY()

public:
    void SetVolume(float NewVolume) { Volume = NewVolume; }
    float GetVolume() const { return Volume; }

private:
    float Volume;
};

// 成就子系统
class UAchievementsSubsystem : public UGameInstanceSubsystem
{
    GENERATED_BODY()

public:
    void UnlockAchievement(FString AchievementName)
    {
        Achievements.Add(AchievementName);
    }

    const TArray<FString>& GetAchievements() const { return Achievements; }

private:
    TArray<FString> Achievements;
};
```

在 `GameInstance` 中，可以通过 `GetSubsystem` 方法访问这两个子系统：

```cpp
// 获取音频子系统
UAudioSubsystem* AudioSubsystem = GetGameInstance()->GetSubsystem<UAudioSubsystem>();
AudioSubsystem->SetVolume(0.5f);

// 获取成就子系统
UAchievementsSubsystem* AchievementsSubsystem = GetGameInstance()->GetSubsystem<UAchievementsSubsystem>();
AchievementsSubsystem->UnlockAchievement("FirstKill");
```

每个子系统都可以独立管理其状态和功能，并且可以跨整个游戏会话生命周期访问。

#### **总结**

- **`GameInstanceSubsystem` 并不是单例**。你可以为不同的功能创建多个 `GameInstanceSubsystem` 子类，每个子系统负责一个独立的功能模块。
- 每个子系统可以独立地管理自己的数据和逻辑，可以与其他子系统共存于同一个 `GameInstance` 实例中。
- 通过 `GetSubsystem` 方法，Unreal Engine 会自动管理这些子系统实例的生命周期，并提供访问接口。

这种设计使得游戏功能的模块化更加容易，避免了将所有功能都堆积在 `GameInstance` 类中的问题，从而提高了代码的组织性和可维护性。
