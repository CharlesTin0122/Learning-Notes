# 创建任务数量过多导致主线程阻塞
```cpp
//创建100个异步任务并将其提交到线程池中，会导致主线程阻塞
void UMyThreadSubsystem::BlockThreadPool()
{
	for (size_t i = 0; i < 100; ++i)
	{
		AsyncTask(ENamedThreads::AnyThread, []() {FPlatformProcess::Sleep(2); });
	}
}
```

```cpp
//并行for在多个线程中分配循环迭代任务100次，会导致主线程阻塞
void UMyThreadSubsystem::BlockThreadPool()
{
	/** ParallelFor:并行For,是一个并行处理工具，提供了一种简洁高效的方法来处理多线程任务。
	* 用于在多个线程中分配循环迭代任务。它允许你以简单的方式将循环分割成多个线程执行，而无需显式管理线程池或同步机制。
	* @param Num; Body的调用次数; Body(0), Body(1)....Body(Num - 1)
	* @param Body; 从多个线程调用的函数
	* @param Flags; 如有需要，用于自定义ParallelFor的行为。
	* 注意：请在适当的地方添加关于并行for的调用和您lambda中的统计信息。不要用长时间运行的任务或阻塞的任务堵塞任务图。
	*/
	ParallelFor(100, 
		[](int32 Index) 
		{
			UE_LOG(LogTemp, Display, TEXT("This is ParallelFor: %d"), Index);
			FPlatformProcess::Sleep(2);
		}
	);
}
```
# 解决方案
- 使用异步编程
```cpp
void UMyThreadSubsystem::InitAsync()
{
	for (size_t i = 0; i < 100; ++i)
	{
		/* 将给定函数异步执行。这种方式可以避免阻塞主线程，从而提高程序的响应性和性能
		* 异步编程 是一种编程范式，它允许程序在等待耗时操作（如文件 I/O、网络请求或数据库查询）完成的同时，继续执行其他任务。
		* @param 使用的执行方法，即在任务图上或在单独的线程中。EAsyncExecution::Thread代表在新的单独线程中执行
		* @param 要执行的函数。
		* @param 完成回调 一个可选的回调函数，当函数执行完成时会被执行。
		* @return 一个 TFuture 对象，将接收来自函数的返回值。
		*/
		Async(EAsyncExecution::Thread,
			[]()
			{
				FPlatformProcess::Sleep(2);
			}
		);
	}

}
```
# 异步编程

在 **Unreal Engine 5** 中，异步编程通过工具和机制来支持复杂的并发操作，例如文件加载、网络请求和后台计算任务。以下是对 **Async**、**TFuture** 和 **TPromise** 的介绍：

---

### **1. Async**

**`Async`** 是一个全局函数，用于在后台线程上运行代码或在游戏主线程上执行任务。

#### **特点**

- 提供了方便的方式来运行并行任务，减轻主线程负担。
- 支持不同线程优先级，例如 **High, Normal, Low**。
- 常见使用场景包括加载资源、计算复杂逻辑，以及异步处理网络或文件操作。

#### **用法**

```cpp
Async(EAsyncExecution::ThreadPool, []() {
    // 在后台线程运行
    FPlatformProcess::Sleep(1.0f); // 模拟长时间任务
    return FString(TEXT("任务完成"));
}, [](FString Result) {
    // 在主线程处理结果
    UE_LOG(LogTemp, Log, TEXT("Async任务结果: %s"), *Result);
});
```

#### **参数**

1. **`EAsyncExecution`**：指定线程类型，如主线程、线程池等。
2. **Lambda任务函数**：在后台线程执行的逻辑。
3. **结果回调函数**（可选）：在主线程执行的结果处理。

#### **优点**

- 简单易用，适合快速实现异步任务。
- 结合其他工具（如 `TFuture` 和 `TPromise`）可以创建更复杂的异步工作流。

---

### **2. TFuture**

**`TFuture`** 是 Unreal 提供的一种模板类，用于表示一个异步操作的结果，它类似于 C++ 标准库中的 `std::future`。

#### **特点**

- 表示异步任务的结果，可以在任务完成后获取值。
- **只读性**：不能修改 `TFuture` 的值。

#### **用法**

```cpp
TFuture<FString> Future = Async(EAsyncExecution::ThreadPool, []() -> FString {
    // 后台线程任务
    FPlatformProcess::Sleep(1.0f); // 模拟延迟
    return FString(TEXT("异步结果"));
});

// 获取结果
if (Future.IsReady())
{
    FString Result = Future.Get();
    UE_LOG(LogTemp, Log, TEXT("Future结果: %s"), *Result);
}
```

#### **常用方法**

1. **`IsReady()`**：检查异步任务是否完成。
2. **`Get()`**：获取异步任务的结果。如果任务未完成，会阻塞线程直到结果返回。

---

### **3. TPromise**

**`TPromise`** 是 `TFuture` 的生产者，用于设置一个异步操作的结果。

#### **特点**

- 提供了一种机制，让开发者手动控制异步结果的设置。
- 与 `TFuture` 搭配使用，`TFuture` 消费由 `TPromise` 生产的结果。

#### **用法**

```cpp
// 创建Promise和对应的Future
TPromise<FString> Promise;
TFuture<FString> Future = Promise.GetFuture();

// 异步任务设置结果
Async(EAsyncExecution::ThreadPool, [&Promise]() {
    FPlatformProcess::Sleep(1.0f); // 模拟耗时任务
    Promise.SetValue(FString(TEXT("Promise的结果")));
});

// 消费结果
Future.Then([](const FString& Result) {
    UE_LOG(LogTemp, Log, TEXT("Promise异步完成: %s"), *Result);
});
```

#### **常用方法**

1. **`SetValue(T Value)`**：设置异步任务的结果。
2. **`EmplaceValue(Args...)`**：直接构造任务结果。
3. **`SetException(TException)`**：设置异常情况（如果任务失败）。

---

### **Async、TFuture 和 TPromise 的关系**

- **`Async`** 是异步任务的快捷工具，可以直接返回 `TFuture`。
- **`TFuture`** 是异步任务的结果容器，表示任务的最终状态。
- **`TPromise`** 是生产 `TFuture` 的机制，用于设置任务结果。

### **使用场景比较**

|工具|适用场景|
|---|---|
|**Async**|快速实现简单异步任务，不需要手动管理结果。|
|**TFuture**|需要获取异步任务结果，并进行后续处理的场景。|
|**TPromise**|更细粒度地控制异步操作结果，或与自定义异步逻辑结合使用的复杂任务。|

---

### **实践建议**

- 对于简单任务，直接使用 **Async**。
- 对于需要管理结果或复杂的任务依赖，结合 **TFuture** 和 **TPromise**。
- 使用线程池时，确保避免过多线程创建导致性能瓶颈。
## 示例
```cpp
void UMyThreadSubsystem::GetAsyncFuture()
{
	//创建异步任务，将整个任务调度到 任意线程（非主线程）中执行。
	AsyncTask(ENamedThreads::AnyThread, 
		[]() 
		{
			//TFuture类型数组用于接收100个任务的返回值
			TArray<TFuture<int32>> FutureResult;
			// 创建 100 个异步任务
			for (size_t i = 0; i < 100; ++i)
			{
				// 添加一个默认值到数组中。
				FutureResult.AddDefaulted();
				// 调用 Async 创建一个新的异步任务在线程池执行。并将任务返回值写入FutureResult的最后一个元素
				FutureResult.Last() = Async(EAsyncExecution::ThreadPool,
					[]() -> int32 
					{
						//生成随机数作为睡眠时间，睡眠并返回随机数
						int32 SleepTime = FMath::RandRange(0, 4);
						FPlatformProcess::Sleep(SleepTime);
						return SleepTime;
					}
				);
			}
			//获取异步任务结果并处理
			for (TFuture<int32>& elem : FutureResult)
			{

				/** Then(),设置一个完成回调，一旦未来完成将被调用,如果已经完成，则立即调用.
				* 当任务完成并生成结果后，Then 的回调函数会被自动调用，并接收任务的结果作为参数
				* 调用 elem.Then 时，回调函数 [](const TFuture<int32>& FutureResult1) 会接收 TFuture 的保存结果，自动传递给 FutureResult1。
				*/
				elem.Then([](const TFuture<int32>& FutureResult1) 
					{ 
						int32 Result = FutureResult1.Get();
						UE_LOG(LogTemp, Log, TEXT("SleepTime: %d"), Result); 
					}
				);
			}
		});

}
```
# Async和AsyncTask之间的区别

在 **Unreal Engine 5** 中，`Async` 和 `AsyncTask` 是两种用于处理异步任务的工具，但它们在实现方式和适用场景上有所不同。以下是它们的区别与用法解析：

---

### **1. Async**

`Async` 是一个函数，允许开发者在特定的线程上执行异步任务。它提供了灵活的线程控制选项，比如运行在游戏线程、后台线程池或高优先级线程池上。

#### **特点**

- **线程灵活性**：可以选择在哪种线程环境中运行（如主线程或线程池）。
- **多线程支持**：适用于复杂的计算任务。
- **回调机制**：可以指定在任务完成后返回主线程处理结果。

#### **用法**

```cpp
#include "Async/Async.h"

Async(EAsyncExecution::ThreadPool, []() {
    // 后台线程任务
    FPlatformProcess::Sleep(1.0f); // 模拟耗时操作
    return FString(TEXT("后台线程任务完成"));
}, [](FString Result) {
    // 主线程处理结果
    UE_LOG(LogTemp, Log, TEXT("结果: %s"), *Result);
});
```

#### **优点**

- 灵活的线程调度（`EAsyncExecution`）。
- 支持复杂的异步操作（如资源加载、后台逻辑）。

#### **适用场景**

- 耗时计算或后台操作，需要避免阻塞主线程。
- 后台处理结果需要在主线程使用。

---

### **2. AsyncTask**

`AsyncTask` 是一个宏，专门用来简化在**游戏主线程**或**线程池线程**中调度任务的实现。与 `Async` 不同的是，`AsyncTask` 默认不会提供线程优先级选项，只支持简单的任务调度。

#### **特点**

- **简化的线程任务**：主要用于调度任务到指定线程（主线程或线程池）。
- **轻量级实现**：适合小型任务，代码简洁明了。
- **立即执行**：不支持复杂的任务依赖。

#### **用法**

```cpp
#include "Async/Async.h"

// 在主线程执行任务
AsyncTask(ENamedThreads::GameThread, []() {
    UE_LOG(LogTemp, Log, TEXT("主线程任务执行中"));
});

// 在线程池中执行任务
AsyncTask(ENamedThreads::AnyBackgroundThreadNormalTask, []() {
    FPlatformProcess::Sleep(1.0f);
    UE_LOG(LogTemp, Log, TEXT("线程池任务执行完成"));
});
```

#### **优点**

- 简单明了，便于小型任务。
- 直接支持切换到主线程或后台线程。

#### **适用场景**

- 简单的任务分派，如将后台线程结果发送到主线程。
- 主线程中的定时任务或轻量计算。

---

### **区别对比**

| 特性        | **Async**                     | **AsyncTask**       |
| --------- | ----------------------------- | ------------------- |
| **线程调度**  | 支持多种线程类型（主线程、后台线程、线程池等）。      | 仅支持主线程和后台线程（预定义类型）。 |
| **线程优先级** | 提供 `EAsyncExecution` 参数设置优先级。 | 无法直接设置优先级，依赖默认调度策略。 |
| **任务复杂性** | 支持复杂任务、依赖和结果处理。               | 更适合简单任务调度和执行。       |
| **回调机制**  | 支持结果回调，在主线程或其他线程处理结果。         | 不支持直接回调，需要手动管理结果处理。 |
| **代码复杂度** | 较高，需要手动设置线程和处理结果。             | 较低，代码清晰适合快速实现。      |

---

### **选择建议**

- 如果需要灵活的线程控制、复杂任务依赖或结果回调，选择 **`Async`**。
- 如果只是需要快速调度任务到主线程或后台线程，选择 **`AsyncTask`**。

---

### **示例场景**

#### 使用 **Async**

```cpp
// 后台加载资源并返回结果到主线程
Async(EAsyncExecution::ThreadPool, []() {
    FPlatformProcess::Sleep(2.0f); // 模拟资源加载
    return FString(TEXT("资源加载完成"));
}, [](FString Result) {
    // 主线程处理
    UE_LOG(LogTemp, Log, TEXT("加载结果: %s"), *Result);
});
```

#### 使用 **AsyncTask**

```cpp
// 主线程更新UI
AsyncTask(ENamedThreads::GameThread, []() {
    UE_LOG(LogTemp, Log, TEXT("UI更新完成"));
});
```

---

### **总结**

- **`Async`** 是功能强大的通用异步工具，适用于复杂和高性能任务。
- **`AsyncTask`** 是轻量级工具，适用于简单任务分派。
