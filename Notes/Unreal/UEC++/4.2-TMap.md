# 概念
- TMap底层结构是一个哈希表，TMap 将数据存储为键值对 (`TPair<KeyType, ValueType>`)，仅使用键进行存储和检索。
# 分类
- TMap：单重映射，不允许Key值重复
- TMultiMap：多重映射，允许Key值重复
# 概述
## TMap
- 在 TMap 中，键值对被视为映射的元素类型，就好像每对都是一个单独的对象一样。在本文档中，元素表示键值对，而各个组件则称为元素的键或元素的值。
- 元素类型是 `TPair<KeyType, ElementType>` ，尽管很少需要直接引用 TPair 类型。
- TMap 键是唯一的。
- 与 TArray 类似，TMap 是同质容器，这意味着它的所有元素都是严格相同的类型。
- TMap 是一种值类型，支持通常的复制、赋值和析构函数操作，以及其元素的强所有权，当映射被销毁时，这些元素也会被销毁。键和值也必须是值类型。
- TMap 是一个哈希容器，这意味着键类型必须支持 GetTypeHash 函数，并提供一个 `operator==` 用于比较键是否相等
## TMultiMap
- 支持存储多个相同的键。
- 当将新的键值对添加到 TMap 且其键与现有键值对匹配时，新的键值对将替换旧的键值对。
- 在 TMultiMap 中，容器存储新对和旧对。
# 特点
- TMap 可以采用可选的分配器来控制内存分配行为。然而，与 TArray 不同的是，它们是集合分配器，而不是标准的 Unreal 分配器，如 FHeapAllocator 和 TInlineAllocator 。 设置分配器 (TSetAllocator)，定义映射应使用多少个哈希桶，以及应使用哪些标准 UE 分配器来存储哈希和元素。
- 最后一个 TMap 模板参数是 `KeyFuncs` ，它告诉映射如何从元素类型中检索键、如何比较两个键是否相等以及如何对键进行哈希处理。它们的默认值返回对键的引用，然后使用 `operator==` 实现相等，并调用非成员 GetTypeHash 函数进行哈希处理。如果您的键类型支持这些功能，您可以将其用作地图键，而无需提供自定义 `KeyFuncs` 。
- 与 TArray 不同，TMap 元素在内存中的相对顺序不可靠或不稳定，并且迭代元素可能会以与添加它们的顺序不同的顺序返回它们。元素不太可能在内存中连续排列。
- 映射的基本数据结构是稀疏数组，它是一个有效支持其元素之间间隙的数组。当元素从映射中删除时，稀疏数组中会出现间隙。然后向数组添加新元素可以填补这些空白。然而，即使 TMap 不打乱元素来填充间隙，指向映射元素的指针仍可能无效，因为整个存储空间已满并且添加新元素时可以重新分配。
# 代码示例
## 使用案例
```cpp
	/*一个由整数键标识的字符串 TMap。我们既没有指定分配器也没有指定 KeyFuncs，可以在编辑器中添加和编辑元素 */
	UPROPERTY(EditAnywhere, Category = MapsAndSets)
	TMap<int32, FString> FruitMap;

	/*添加元素*/
	FruitMap.Add(5, TEXT("Banana"));
	FruitMap.Add(2, TEXT("Grapefruit"));
	FruitMap.Add(7, TEXT("Pineapple"));
	FruitMap.Add(2, TEXT("Pear"));//当插入重复键2时，值被更新为Pear
	FruitMap.Add(4);//可以接受没有值的键。当调用这个重载的 Add 时，该值将被默认构造：	{ Key: 4, Value: ""}
	FruitMap.Emplace(3, TEXT("Orange"));//使用 Emplace 而不是 Add 来避免在插入映射时创建临时对象

	/*附加*/
	TMap<int32, FString> FruitMap2;
	FruitMap2.Emplace(4, TEXT("Kiwi"));
	FruitMap2.Emplace(9, TEXT("Melon"));
	FruitMap2.Emplace(5, TEXT("Mango"));
	/*FruitMap2附加到FruitMap，相当于使用 Add 或 Emplace 单独添加 FruitMap2 的每个元素到FruitMap
	*附加后FruitMap2被清空*/
	FruitMap.Append(FruitMap2);

	/*迭代*/
	// ranged-for迭代
	for (TPair<int32, FString>& Elem : FruitMap)
	{
		/*打印信息*/
		FPlatformMisc::LocalPrint(
			*FString::Printf(
				TEXT("d% : %s \n"),
				Elem.Key,
				*Elem.Value
			)
		);
	}
	//迭代器迭代，CreateIterator 和 CreateConstIterator 函数创建迭代器
	for (auto It = FruitMap.CreateConstIterator(); It; ++It)
	{
		FString Message = FString::Printf(TEXT("d% : %s \n"), It.Key(), *It.Value());
		UE_LOG(LogTemp, Warning, TEXT("%s, %s"), *FString(__FUNCTION__), *Message);
		FPlatformMisc::LocalPrint(*Message);
	}

	/*获取值*/
	//在使用 operator[] 之前，您应该始终检查地图是否包含该键。如果映射不包含密钥，它将断言
	FString Val7 = FruitMap[7];// Val7 == "Pineapple"
	FString Val8 = FruitMap[8];// Assert!

	/*查询*/
	int32 Count = FruitMap.Num();//获取元素数量
	bool bHas7 = FruitMap.Contains(7);//映射是否包含特定键，返回值为布尔
	FString* Ptr7 = FruitMap.Find(7);//如果映射包含该键，则返回指向该元素值的指针；如果不包含该键，则返回空指针。在 const 映射上调用 Find 将返回 const 指针。
	/*为了确保您从查询中收到有效的结果，您可以使用 FindOrAdd 或 FindRef */
	FString& Ref7 = FruitMap.FindOrAdd(7);//对与您提供的键关联的值的引用。如果键不在映射中，FindOrAdd 将返回一个新创建的元素，其中包含您的键和默认构造的值，并将其添加到映射中。
	FString Val6 = FruitMap.FindRef(6);//返回与您的键关联的值的副本，或者如果在映射中找不到您的键，则返回默认构造的值。 FindRef 不会创建新元素，因此可用于 const 和非常量映射。
	/*FindKey 函数根据值反向查找键，返回指向与提供的值配对的第一个键的指针。搜索映射中不存在的值将返回空指针。
	*按值查找比按键查找慢（线性时间）。这是因为映射是按键而不是按值进行散列的。此外，如果映射有多个具有相同值的键，FindKey 可能会返回其中任何一个。*/
	const int32* KeyMangoPtr = FruitMap.FindKey(TEXT("Mango"));
	/*GenerateKeyArray 和 GenerateValueArray 函数分别使用所有键和值的副本填充 TArray。
	在这两种情况下，传递的数组在填充之前都会被清空，因此生成的元素数量将始终等于映射中的元素数量。*/
	TArray<int32>   FruitKeys;
	TArray<FString> FruitValues;
	FruitMap.GenerateKeyArray(FruitKeys);
	FruitMap.GenerateValueArray(FruitValues);

	/*移除*/
	FruitMap.Remove(8);//返回值是已删除的元素数，如果映射不包含任何与键匹配的元素，则返回值可以为零
	FString Removed7 = FruitMap.FindAndRemoveChecked(7);//从映射中删除元素并返回其值。名称中的“checked”部分表示如果键不存在，则映射调用 check。
	//将删除的元素的值复制到引用参数中。如果您指定的键不存在于映射中，则输出参数将保持不变，并且函数返回 false 。
	FString Removed;
	bool bFound2 = FruitMap.RemoveAndCopyValue(2, Removed);
	/*移除所有元素。Empty 可以采用一个参数来指示映射中要留下多少松弛量，而 Reset 总是留下尽可能多的松弛量。*/
	TMap<int32, FString> FruitMapCopy = FruitMap;
	FruitMapCopy.Empty();		// You can also use Reset() here.

	/*排序，可以按键或按值对 TMap 进行排序。
	* 排序后，容器的迭代会按排序顺序显示元素，但这种行为只能保证到您下次修改容器为止。
	* 排序不稳定，因此 TMultiMap 中的等效元素可能以任何顺序出现。
	* 函数都采用指定排序顺序的二元谓词。*/
	FruitMap.KeySort([](int32 A, int32 B) {return A > B; }); // 按键降序排列
	FruitMap.ValueSort([](const FString& A, const FString& B) {return A.Len() < B.Len(); });//按值长度排序

	/*运算符*/
	TMap<int32, FString> NewMap = FruitMap;//使用标准复制构造函数或赋值运算符进行复制
	FruitMap = MoveTemp(NewMap);//移动语义

	/*Slack*/
	//Slack 分配的内存不包含元素。您可以通过调用 Reserve 来分配内存而不添加元素，并且可以通过调用 Reset 或使用 Empty 调用 来删除元素而不释放它们所使用的内存
	FruitMap.Reserve(10);
	for (int32 i = 0; i < 10; ++i)
	{
		FruitMap.Add(i, FString::Printf(TEXT("Fruit%d"), i));
	}
	/*要从 TMap 中删除所有松弛空间，请使用 Collapse 和 Shrink 函数。 Shrink 删除容器末尾的所有松弛，但在中间或开头留下任何空元素。*/
	for (int32 i = 0; i < 10; i += 2)
	{
		FruitMap.Remove(i);//每隔一个元素删除一个元素
	}
	FruitMap.Shrink();//删除容器末尾的松弛空间
	/*Shrink 在上面的代码中只删除了一个无效元素，因为最后只有一个空元素。要消除所有松弛，请首先使用 Compact 函数，以便将空白空间分组在一起，为 Shrink 做准备。*/
	FruitMap.Compact();//将所有有效元素靠前，无效元素靠后为Shrink做准备
	FruitMap.Shrink();//收缩松弛空间
```
## 运算符重载案例
```cpp
/*只要类型具有 operator== 和非成员 GetTypeHash 重载，您就可以将其用作 TMap 的键类型，而无需进行任何更改*/
USTRUCT()
struct FMapInfo
{
	GENERATED_BODY()
	//两个属性，生命值和名字
	FString NPCName = TEXT("None");
	int32 NPCHealth = 0;
	//构造函数
	FMapInfo() {};
	FMapInfo(FString Name, int32 Health) : NPCName(Name), NPCHealth(Health){}
	//重载==运算符，NPC名字是一样的就是同一个NPC
	bool operator==(const FMapInfo& Other) const
	{
		return NPCName == Other.NPCName;
	}
	//GetTypeHash函数用于返回哈希值
	friend uint32 GetTypeHash(const FMapInfo& Other)
	{
		return GetTypeHash(Other.NPCName);
	}
};
//结构体作为键
TMap< FMapInfo, int32> MyNPCMap;
MyNPCMap.Add(FMapInfo(TEXT("BOSS"), 100), 1);
MyNPCMap.Add(FMapInfo(TEXT("NPC1"), 80), 2);
MyNPCMap.Add(FMapInfo(TEXT("NPC2"), 70), 3);
```
## KeyFuncs案例
- 定义
```cpp
	/* KeyFuncs
	* 只要类型具有 operator== 和非成员 GetTypeHash 重载，您就可以将其用作 TMap 的键类型，而无需进行任何更改。
	* 但是，您可能希望使用类型作为键而不重载这些函数。在这些情况下，您可以提供自己的自定义 KeyFuncs 。
	* 要为您的Key类型创建 KeyFunc，您必须定义两个 typedef 和三个静态函数:
		* `KeyInitType` —— 用于传递键的类型。
		* `ElementInitType` —— 用于传递元素的类型。
		* `KeyInitType GetSetKey(ElementInitType Element)`——返回元素的键。
		* `bool Matches(KeyInitType A, KeyInitType B)` —— 如果 `A` 和 `B` 等值将返回 `true`，否则返回 `false`。
		* `uint32 GetKeyHash(KeyInitType Key)`—— 返回 `Key` 的散列值
	*/
//定义简单结构体
struct FMyStruct
{
	//属性
	FString UniqueID;// 唯一标识符，类型是 FString
	float SomeFloat;// 浮点数变量，不影响结构体的唯一性
	//构造函数
	explicit FMyStruct(float InFloat) : UniqueID(FGuid::NewGuid().ToString()), SomeFloat(InFloat) {}
};
//模板结构体 KeyFuncs
template<typename ValueType>
//它继承自 BaseKeyFuncs，为映射中的键值对(TPair<FMyStruct, ValueType>) 定义了键处理逻辑。
struct TMyStructMapKeyFuncs : BaseKeyFuncs<TPair<FMyStruct, ValueType>, FString>
{
private:
	//定义父类类型别名为Super，Super 是 BaseKeyFuncs 的特化模板，描述了键值对(TPair<FMyStruct, ValueType>) 和键类型(FString) 的关系。
	typedef BaseKeyFuncs<TPair<FMyStruct, ValueType>, FString> Super;
public:
	// 定义从父类中继承的类型别名，typename告知编译器后续代码ElementInitType、KeyInitType是类型而非成员变量
	typedef typename Super::ElementInitType ElementInitType;
	typedef typename Super::KeyInitType KeyInitType;
	// 获取键值对中的键 (FString)
	static KeyInitType GetSetKey(ElementInitType Element)
	{
		return Element.Key.UniqueID;// 提取 FMyStruct 中的 UniqueID
	}
	// 比较两个键是否相等
	static bool Matches(KeyInitType A, KeyInitType B)
	{
		return A.Compare(B, ESearchCase::CaseSensitive) == 0;// 比较字符串，区分大小写
	}
	// 获取键的哈希值
	static uint32 GetKeyHash(KeyInitType Key)
	{
		return FCrc::StrCrc32(*Key);// 计算字符串的 CRC32 哈希值
	}
};
```
- 使用
```cpp
//定义TMap：FMyStruct为键，int32为值，FDefaultSetAllocator为分配器，TMyStructMapKeyFuncs<int32>为KeyFunc函数
TMap<FMyStruct, int32, FDefaultSetAllocator, TMyStructMapKeyFuncs<int32>> MyMap;

MyMap.Add(FMyStruct(3.14f), 5);
MyMap.Add(FMyStruct(1.23f), 2);
```
