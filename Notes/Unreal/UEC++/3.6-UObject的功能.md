UObjects 提供的功能

此系统的使用不为强制要求，甚至有时不适合使用，但却存在以下益处：

- 垃圾回收
- 引用更新
- 反射
- 序列化：序列化是指将对象的数据转换为一种可以存储或传输的格式，以便在游戏运行时或跨会话之间保存或还原对象状态。
	- 在 Unreal 引擎中，序列化是通过 `UObject::Serialize` 函数来实现的。`UObject` 类提供了一个虚函数 `Serialize`，允许派生类覆盖此函数来实现自定义的序列化逻辑。
	- `Serialize` 函数通过一个 `FArchive` 对象来读写数据。`Ar` 是一个 `FArchive` 实例，它决定数据的方向（读或写），以及是保存到磁盘、网络，还是加载到内存。
	- Unreal 引擎的 `UPROPERTY` 宏可以帮助标记类成员，以自动实现序列化。这些标记用于指示哪些属性在保存、加载或网络复制时需要被序列化。
	- 如果需要为 `UObject` 子类自定义序列化过程，可以重写 `Serialize` 函数。
- 默认属性变化自动更新：属性发生了修改会自动更新
- 自动属性初始化：挂了`UPROPERTY`宏，变量会自动初始化。
- 自动编辑器整合
- 运行时类型信息可用
- 网络复制

大部分这些益处适用于 [UStruct](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/structs-in-unreal-engine)，它有着和 UObject 一样的反射和序列化能力。UStruct 被当作数值类型处理并且不会垃圾回收GC。更多关于这些系统的细节，请参考 [Unreal Object Handling](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/unreal-object-handling-in-unreal-engine) 文档。

## 虚幻头文件工具

为利用 UObject 派生类型所提供的功能，需要在头文件上为这些类型执行一个预处理步骤，以核对需要的信息。 该预处理步骤由 UnrealHeaderTool（简称 UHT）执行。UObject 派生的类型需要遵守特定的结构。

## 头文件格式

UObject 在源（.cpp）文件中的实现与其他 C++ 类相似，其在头（.h）文件中的定义必须遵守特定的基础结构，以便在虚幻引擎 4 中正常使用。使用编辑器的"New C++ Class"命令是设置格式正确头文件的最简单方法。UObject 派生类的基础头文件可能看起来与此相似，假定 UObject 派生物被称为 UMyObject，其创建时所在的项目被称为 MyProject：

```cpp
	#pragma once
	#include 'Object.h'
	#include 'MyObject.generated.h'

	UCLASS()	
	class MYPROJECT_API UMyObject : public UObject	
	{		
		GENERATED_BODY();
	};
```

虚幻引擎特定的部分如下：

```cpp
	#include "MyObject.generated.h"
```

包含UHT生成的反射文件，此行为此文件中最后一个 `#include` 指令。

```cpp
	UCLASS()
```

`UCLASS` 宏使虚幻引擎能识别 `UMyObject`。此宏支持大量参数[Class Specifiers](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/class-specifiers)，参数决定类功能的开或关。

```cpp
	class MYPROJECT_API UMyObject : public UObject
```

- 如 MyProject 希望将 UMyObject 类公开到其他模块，则需要指定 `MYPROJECT_API`。这对游戏项目将包括的模块或插件十分实用。这些模块和插件将故意使类公开，在多个项目间提供可携的自含式功能。
- 类名称前面要加类型前缀A,U,I

```cpp
	GENERATED_BODY()
```

- `GENERATED_BODY` 宏不获取参数，但会对类进行设置，以支持引擎要求的基础结构。所有 `UCLASS` 和 `USTRUCT` 均有此要求。
- **`GENERATED_BODY()` 并不生成 `.generated.h` 文件**，而是一个指示符，用来将 `.generated.h` 中定义的代码片段插入到类或结构体中。
- **`.generated.h` 文件是由 `Unreal Header Tool (UHT)` 生成的**，并且在编译时自动包含，以支持 Unreal 引擎的功能。

虚幻头文件工具支持最下C++集。当使用自定义 `#ifdefs` 宏包裹 UCLASS 的部分时，UHT 会忽略不包含 `WITH_EDITOR` 或者 `WITHEDITORONLY_DATA` 宏的宏。

属性和方法如果要被蓝图调用，要加上UFUNCTION，UPROPERTY。
## 更新对象

Ticking 代表虚幻引擎中对象的更新方式。所有Actors均可在每帧被 tick，便于您执行必要的更新计算或操作。

Actor 和 Actor组件在注册时会自动调用它们的 Tick 函数，然而，`UObjects` 不具有嵌入的更新能力。在必须的时候，可以使用 inherits 类说明符从 `FTickableGameObject` 继承即可添加此能力。 这样即可实现 `Tick()` 函数，引擎每帧都将调用此函数。

大部分游戏内对象都是[Actors](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/actors-in-unreal-engine)，可以按用户设置的最短间隔tick，而不是每帧tick。

## 销毁对象

对象不被引用后，垃圾回收系统将自动进行对象销毁。这意味着没有任何 `UPROPERTY` 指针、引擎容器、`TStrongObjectPtr` 或类实例会拥有任何对它的强引用。

注意，无论对象是否被垃圾回收，[弱指针](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/weak-pointers-in-unreal-engine)对其都没有影响。

垃圾回收器运行时，寻找到的未引用对象将被从内存中移除。此外，函数`MarkPendingKill()` 可在对象上直接调用。此函数将把指向对象的所有指针设为 `NULL`，并从全局搜索中移除对象。对象将在下一次垃圾回收过程中被完全删除。

[智能指针](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/smart-pointers-in-unreal-engine)不适用于 UObject。

- `Object->MarkPendingKill()` 被 `Obj->MarkAsGarbage()` 所替代。这个新的函数现在仅用于追踪旧对象。如果 `gc.PendingKillEnabled=true` ，那么所有标记为 `PendingKill` 的对象会被垃圾回收器自动清空并销毁。
    
- 强引用会将 UObject 保留。如果你不想让这些引用保留 UObject，那么这些引用应该转换来使用弱指针，或者变为一个普通指针由程序员手动清除（如果对性能有较高要求的话）。
    

你可以用弱指针替换强指针，并且在游戏运作时作为垃圾回收取消引用，因为垃圾回收仅在帧之间运行。

- `IsValid()` 用于检查它是 null 还是垃圾，但是大部分情况下 IsValid 可以被更正规的编程规则替换，比如在调用 `OnDestroy` 事件时将指针清除至 Actor。
    
- 如果禁用了 `PendingKill()`， `MarkGarbage()` 将会提醒对象的所有者该对象将要被销毁，但是对象本身直到所有对它的引用都解除之后才会被垃圾回收。
    
- 对于 Actor，即使 Actor 被调用了 `Destroy()`，并且被从关卡中移除，它还是会等到所有对它的引用都解除之后才会被垃圾回收。
    
- 对于证书持有者的主要区别在于，对花费较大的对象进行垃圾回收的函数 `MarkPendingKill()` 不再起效。
    
- 已有的用于 nullptr 的检查应该被 `IsValid()` 调用所替代，除非你进行手动清除，因为指针不再会被垃圾回收器通过 `MarkPendingKill()` 自动清除。
# UObject实例创建
[在虚幻引擎中创建对象 | 虚幻引擎 5.5 文档 | Epic Developer Community | Epic Developer Community](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/creating-objects-in-unreal-engine)

在Unreal Engine（UE）中，`UObject` 是引擎中的核心基类，所有的UE4对象都直接或间接地继承自它。在编写C++代码时，`UObject`实例的创建方式和常规C++对象不同，主要原因是UE的内存管理、垃圾回收和反射系统的需要。以下是创建和管理`UObject`实例的基本方法和最佳实践：

### 1. 使用`NewObject`创建UObject实例

`NewObject`是创建`UObject`实例的推荐方法。它能确保对象被正确地加入到UE的垃圾回收系统中。这种方式适合创建轻量、临时的对象。

```cpp
// 假设MyClass继承自UObject
UMyClass* MyObject = NewObject<UMyClass>();
```

#### 主要参数：
- **Outer（父对象）**：创建的对象将会被这个父对象拥有。父对象销毁时，子对象也会随之销毁，确保资源管理的高效性。
- **Name（对象名）**：设置实例的唯一标识。虽然通常不需要指定名称，但如果希望在编辑器中有特定名称，或者进行查找，可以设置。
- **Flags（对象标志）**：设置对象的生命周期行为，比如是否在游戏中仅生存一帧，或者是否为持久化对象等。

```cpp
UMyClass* MyObject = NewObject<UMyClass>(ParentObject, TEXT("MyObjectName"));
```

### 2. 使用`ConstructObject`（UE4早期版本）

在Unreal Engine 4的早期版本中，有一种创建对象的方法是使用`ConstructObject`。但从UE4.8开始，`NewObject`取代了它。**建议总是使用`NewObject`**，以确保向前兼容。

### 3. 使用`CreateDefaultSubobject`创建默认子对象

`CreateDefaultSubobject`常用于在构造函数中创建组件。这是创建类属性的一种方式，主要应用在继承自`AActor`的类中，用于创建组件的默认实例，比如碰撞组件、渲染组件等。

```cpp
MyComponent = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("MyMeshComponent"));
```

### 4. 动态分配`UObject`实例的注意事项

- **使用合适的`Outer`**：确保为对象指定适当的`Outer`，例如`AActor`类中的子对象通常以Actor为`Outer`，这样引擎就能管理这些对象的生命周期。
- **不要直接使用`new`**：不要使用标准C++中的`new`关键字创建`UObject`实例，因为这种方式创建的对象不会被引擎的垃圾回收系统跟踪，容易引发内存泄漏。
- **垃圾回收（GC）**：`UObject`实例由UE的垃圾回收系统管理，不再被引用时会自动销毁。创建对象时，务必使用引擎提供的方式，以确保对象能被正确回收。

### 示例：在Actor中创建UObject实例

下面是一个例子，展示在Actor中创建并管理`UObject`实例：

```cpp
#include "MyActor.h"
#include "MyObject.h"

AMyActor::AMyActor()
{
    // 使用NewObject创建UObject实例
    MyObjectInstance = NewObject<UMyObject>(this, TEXT("MyObjectInstance"));
}

void AMyActor::BeginPlay()
{
    Super::BeginPlay();

    // 使用MyObjectInstance的功能
    if (MyObjectInstance)
    {
        MyObjectInstance->SomeFunction();
    }
}
```

### 小结

1. 使用`NewObject`来创建`UObject`实例。
2. 为Actor的子组件使用`CreateDefaultSubobject`。
3. 避免使用`new`关键字。
4. 正确设置`Outer`和标志，以便垃圾回收系统能正确管理生命周期。

# 虚幻Object处理

# # TSubclassOf
[Typed Object Pointer Properties in Unreal Engine | 虚幻引擎 5.5 文档 | Epic Developer Community | Epic Developer Community](https://dev.epicgames.com/documentation/zh-cn/unreal-engine/typed-object-pointer-properties-in-unreal-engine)
在Unreal Engine的C++编程中，`TSubclassOf` 是一个模板类，用于指定某个类的子类类型。它主要用于在代码中声明**类型安全的类引用**，并且常用于类、组件、或蓝图中，特别是在需要动态指定或生成对象类型时。

### TSubclassOf 的主要用途

1. **指定类类型**：`TSubclassOf`可以确保引用的是某个基类（或接口）的子类，而不会误引用其他不兼容的类型。
2. **蓝图和C++的交互**：在蓝图和C++之间传递类时，`TSubclassOf`允许选择基类的子类，并在运行时动态实例化指定的类。
3. **实例化动态对象**：通过`TSubclassOf`和`NewObject`或`SpawnActor`结合，可以在运行时创建基于`TSubclassOf`指定的类的对象。

### TSubclassOf 的基本语法

`TSubclassOf`模板通常定义如下：

```cpp
TSubclassOf<UBaseClass> SubclassVariable;
```

- 其中，`UBaseClass` 是希望引用的基类。`SubclassVariable` 只能引用 `UBaseClass` 的子类。

例如：

```cpp
TSubclassOf<AActor> ActorClass;
TSubclassOf<UUserWidget> WidgetClass;
```

### TSubclassOf 的使用示例

假设我们需要创建一个系统，允许玩家选择敌人类的子类，并在游戏中生成该敌人对象，可以使用`TSubclassOf`来实现。

#### 1. 在类中声明`TSubclassOf`

```cpp
// 在头文件中声明
TSubclassOf<AEnemy> EnemyClass;
```

#### 2. 在编辑器中指定子类

`TSubclassOf` 变量可以在编辑器中暴露给蓝图和关卡设计师，这样可以通过编辑器来指定需要生成的类：

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Enemy")
TSubclassOf<AEnemy> EnemyClass;
```

#### 3. 在运行时实例化指定的子类

在代码中，可以使用`EnemyClass`来动态生成敌人对象，通常结合`SpawnActor`使用。

```cpp
if (EnemyClass)
{
    // 获取当前关卡的世界对象
    UWorld* World = GetWorld();
    if (World)
    {
        // 在指定位置生成敌人
        AEnemy* SpawnedEnemy = World->SpawnActor<AEnemy>(EnemyClass, SpawnLocation, SpawnRotation);
    }
}
```

### 使用TSubclassOf的注意事项

- **类型检查**：`TSubclassOf`确保类型安全，即便子类更改，使用`TSubclassOf`的代码依然安全可靠。
- **动态对象生成**： `TSubclassOf` 通常与 `NewObject` 或 `SpawnActor` 一起使用，以便在运行时实例化。
- **蓝图支持**：在编辑器和蓝图中，通过`TSubclassOf`可以方便地选择类，无需在代码中硬编码。

### 完整示例

以下是一个完整示例，展示如何使用`TSubclassOf`来实现动态生成敌人类。

```cpp
// EnemySpawner.h
#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "Enemy.h"
#include "EnemySpawner.generated.h"

UCLASS()
class MYGAME_API AEnemySpawner : public AActor
{
    GENERATED_BODY()

public:
    // 设置可以在蓝图中指定的敌人类
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Spawning")
    TSubclassOf<AEnemy> EnemyClass;

    // 生成敌人的方法
    void SpawnEnemy();
};
```

```cpp
// EnemySpawner.cpp
#include "EnemySpawner.h"
#include "Engine/World.h"

void AEnemySpawner::SpawnEnemy()
{
    if (EnemyClass)
    {
        UWorld* World = GetWorld();
        if (World)
        {
            FVector SpawnLocation(0.f, 0.f, 100.f);
            FRotator SpawnRotation(0.f, 0.f, 0.f);
            World->SpawnActor<AEnemy>(EnemyClass, SpawnLocation, SpawnRotation);
        }
    }
}
```

### 总结

- `TSubclassOf` 用于指定类的子类类型，使代码更具灵活性和类型安全性。
- 它适合用于在运行时指定和生成子类对象。
- `TSubclassOf` 在蓝图中可视化选择类，有助于提高灵活性。
