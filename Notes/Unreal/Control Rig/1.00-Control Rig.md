# 概述

- **何为control rig**

- 意为控制绑定，是DCC应用程序和游戏引擎中用于操纵角色动画的资产

- **主要原理**

- 正向结算：解算器（Solver）→ 矩阵(matrix) → 控制器（controls）→ 约束 （constraint）→ 骨骼（joint，bone） → 蒙皮（skin） → 模型（geometry）

- 反向结算：骨骼（joint，bone）→ 约束 （constraint）→ 控制器（controls）

- **虚幻control rig 的特点**

- control rig 图表是编译的，编译意味着烘焙所有静态数据，性能极大提升。

- control rig 有事件堆栈（Event Stack），在maya中你不能有循环图表（对象A控制对象B，对象B再控制对象A），而在unreal中你可以这样做，因为对象A控制对象B一旦完成，在另一个事件中，对象B就处在一个新的位置，对象A控制对象B这件事就成为了历史，你可以做对象B再控制对象A。

- **主要节点和使用方法**

- **构造事件（Construction Event）**

- 允许你在运行control rig之前运行Construction Event，允许你指定control rig Class的初始化，可以初始化变量（variable）。可以是你的control rig使用新骨架，相当于Python语言中类的__init__方法。

- **向前解析（Forwards Sovle）**

- ，控制器控制骨骼，常用于手调动画。

- 骨骼控制控制器，常用于动作捕捉中将骨骼动画烘焙至控制器上，使之成为控制器动画。然后再使用正向结算（Forwards Sovle）来修改动画。

# **案例6: FABRIK**

- **原理**

- Forward And Backward Reaching Inverse Kinematics，前后延伸反向运动学

- 0.计算整个关节链长度，是否能达到target位置。

d1+d2+...+dn> 根节点到target位置。

如果不可到达，可以有两种处理方式：

a.根骨骼往target方向移动，直到 d1+d2+...+dn> 根节点到target位置

b.不移动根骨骼，从第二个节点开始，一直往前伸直，形成一条直线，指向target。

如果可以达到Target，那么就可以开始进行FABRIK的处理。

- 1.先从末端骨骼开始计算，先将最末端的骨骼p4移到目标位置t处，此时骨骼p4的位置为p′4。然后，将p3和p′4连成一条直线，通过原有的p3和p4的距离，将现在的p3拉到与p′4同样的距离处p′3。一直处理到根骨骼p0。

- 2.再从根骨骼p′0开始处理。由于根骨骼再整个迭代过程中是默认为不动的，因此再把根骨骼p′′0移到原来的位置p0处，接着使用同样的距离约束，一直处理到尾骨骼p4。

- 3.重复1~2的迭代过程，直到最终的尾骨骼位置与到达目标位置（或与目标位置距离小于某个预定值）停止。此时整个算法结束。

# **案例9：手臂绑定**

- **原理**

- 此部分FKIK切换的精髓在于控制器跟随骨骼（follow）,当绑定为FK时，IK控制器跟随骨骼移动。当绑定为IK时，FK控制器跟随骨骼移动。这样，FK，IK即可无缝实时切换。

- **solver_FK**

- 自定义FK结算器，主要分三部分

- 1.定位FK控制器位置（Construction Event使用）

- 2.FK Follow,使FK控制器跟随骨骼 (用于FKIK切换)

- 3.FK 解算器，控制器控制骨骼

![](attachments/Unreal%20Control%20Rig_image_39.png)

- **solver_IK**

- 自定义IK结算器，主要分三部分

- 1.定位IK控制器位置（Construction Event使用）

- 2.IK Follow,使IK控制器跟随骨骼移动 (用于FKIK切换)

- 3.IK 解算器，控制器控制骨骼

![](attachments/Unreal%20Control%20Rig_image_40.png)

- 自定义IKFK结算器，主要用于IKFK切换

- 1.设置切换时控制器的显示和颜色
