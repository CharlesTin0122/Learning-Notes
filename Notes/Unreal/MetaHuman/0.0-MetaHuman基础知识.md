# ⭐ MetaHuman 全面介绍（技术美术 / 动画 / Rigging 视角）

## 1. MetaHuman 是什么？

**MetaHuman 是 Epic Games 推出的高精度数字人创建、绑定、动画系统**，包含以下组成部分：

### 核心组件

|组件|作用|
|---|---|
|**MetaHuman Creator（MHC）**|基于云端的高精度角色创建器，可调节脸型、身体、材质。|
|**MetaHuman Assets**|标准化拓扑、骨骼体系（Body + Face）、LOD、材质、头发、牙齿等。|
|**MetaHuman Rig**|Maya 插件提供的控制器、面部 FACS-based Rig、身体 Rig。|
|**MetaHuman DNA**|描述角色拓扑、骨骼、BlendShape、RigLogic 的核心数据文件。|
|**RigLogic**|UE + Maya 中的实时变形逻辑系统，驱动面部表情（基于 FACS）。|

**MetaHuman 的核心价值**是让开发者无需重新设计骨架、BlendShape、Skin、面部 Rig，而是直接使用可拓展、工业级的绑定系统。

---

# 2. MetaHuman 的 Rig 架构

## ◆ **身体骨骼（Body Skeleton）**

- 遵循 UE Mannequin，但 MetaHuman 使用 52+ 骨骼
    
- 兼容 IK Retargeter
    
- 带有额外 Twist 骨骼、细分的手指骨骼
    

## ◆ **面部骨骼（Face Skeleton）**

MetaHuman 的面部绑定包括：

- 52+ Face Joints（jaw、tongue、eyes、brows、cheeks...）
    
- 180+ BlendShapes（手游可减少）
    
- 通过 **RigLogic** 将 Controller → LBS（关节）+ 面部 BlendShape 混合
    

## ◆ **控制器（Controls）**

在 Maya 插件中包含：

- 面部控制器：基于 FACS（AU1, AU4, AU12, AU26…）
    
- 身体控制器：IK/FK、Space switching、Twist、Roll

# 3. FACS → MetaHuman 的关系（面部绑定核心）

**MetaHuman 的表情系统基于 FACS（Facial Action Coding System）建模**。

流程是：

### ✔ FACS (AU)

描述真实面肌运动 →

### ✔ BlendShape Library

每个 AU 对应 1~数个 BlendShape →

### ✔ RigLogic

将控制器参数与 BlendShape / Joints 混合 →

### ✔ 最终变形

在 Maya & Unreal 都可实时驱动。

例如：

- **AU12：拉嘴角** → 驱动 cornerPuller、lipSmiler 等 BlendShape
    
- **AU14：拉嘴角下方** → 驱动 cheek dimple + lip compress

# 4. MetaHuman DNA 文件格式

**DNA 文件是 MetaHuman Rig 的核心数据容器**，包含 5 大类信息：

|分类|内容|
|---|---|
|**Definition**|顶点拓扑、BlendShape 编号、骨骼列表|
|**Geometry**|网格的顶点坐标（LOD0~3）|
|**Rig**|面部控制器层级、每个 Controller 的限制|
|**Skin**|骨骼权重（Skin Cluster 数据）|
|**Behavior**|**RigLogic 所需的驱动表、系数矩阵**|

在 Maya 中 MetaHuman for Maya 插件可加载 DNA → 创建完整 Rig  
在 UE 中使用同一个 DNA → 执行 RigLogic（C++ 实现）

👉 **RigLogic 保证 Maya 与 Unreal 的面部结果一致**（不靠 AnimBlueprint）。

# 5. RigLogic——MetaHuman 面部系统的核心

RigLogic 是 Epic 的实时绑定框架，特点是：

### ✔ 不靠 Animation Blueprint

实际是一个 **机算节点网络**：

- Inputs：控制器权重
    
- Outputs：joint transform + BlendShape 权重
    

### ✔ 单向矩阵运算（线性表驱动）

- 采用“层级依赖 + 数学矩阵”
    
- 保证最终结果在 Maya 与 UE 完全一致
    

### ✔ 高性能

RigLogic C++ 实现，可在游戏中 0.2ms 内计算全脸。

### **1）在 MetaHuman Creator 创建角色**

- 选择基础模型或扫描
    
- 调形、调肤色、调眼睛、调发型

- 骨骼
    
- BlendShapes
    
- RigLogic 数据
    
- 材质、LOD 等
    

### **3）（可选）在 Maya 中二次绑定 / 修形**

通过 MetaHuman for Maya 插件可：

- 导出 DNA
    
- 创建面部 Rig + 身体 Rig
    
- 修改 BlendShape、调整权重、修正骨骼
    

### **4）回 UE 重建 DNA**

- 将修改导回 UE
    
- UE 使用 RigLogic 保持一致结果
    

👉 **通常用于扫描人物 → MetaHuman 化** 的工作流程。

# 📁 DNA 文件的大体架构与层 (Layers)

根据 MetaHuman 的官方文档，DNA 文件 (binary) 将数据分为若干“逻辑层 (logical layers)” (Descriptor, Definition, Behavior, Geometry) —— 后续行为/几何均可按需加载。 ([cggroup.readthedocs.io](https://cggroup.readthedocs.io/en/latest/eBooks/MetaHuman/dna.html?utm_source=chatgpt.com "DNA library — CGgroup开发手册 documentation"))

## 各层概览

|层 (Layer)|主要内容 / 含义|
|---|---|
|**Descriptor**|基本元数据 (metadata)：角色名字、年龄 (如果有)、face archetype (face-type 身份属性)、任意键/值字符串 (key/value metadata)，以及版本/兼容性参数。用于标识这个 DNA 与哪种 rig definition (骨架/版本) 兼容。 ([cggroup.readthedocs.io](https://cggroup.readthedocs.io/en/latest/eBooks/MetaHuman/dna.html?utm_source=chatgpt.com "DNA library — CGgroup开发手册 documentation"))|
|**Definition**|静态 / 结构化数据 (静态骨架 + 网格 + rig 定义) — 包含： • 所有 control (GUI controls / sliders / map controls) 名称列表 • 所有 joint (骨骼) 名称 + hierarchy (父子关系) • 所有 blendshape / shape targets 名称 • 所有 animated maps 名称 所有 mesh / sub-mesh / LOD 的名称/ID/映射 /所属 • Joint 的 bind pose (neutral pose) transform (位置/旋转/缩放) • LOD → 哪些 joints / meshes / blendshapes / maps 属于该 LOD 的映射/索引 即 rig 的“骨架 + 组织 + 静态结构”基础。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))|
|**Behavior**|动态 / 驱动数据 (Rig logic 所需) — 包括： • GUI control → raw control channels / internal control values 的映射 (animated-maps, 驱动曲线, remap 等) • 控制通道 (controls) 到 joints (joint transforms) 的映射 (线性或带 corrective 的) • 控制通道到 blendshape 权重的映射 • corrective expressions / shape corrections / wrinkle maps / animated-map 数据 (当多个 control 组合或 special expression 时触发) — 也就是说，Behaviour 层是运行时 “控制器输入 → 最终 pose (joint + blendshape + map)” 的所有规则 / 系数 / mapping 数据。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))|
|**Geometry**|几何网格 + Skin + Blendshape target deltas：即网格顶点 (vertices)、拓扑 (faces)、UV/normal/vertex color/vertex groups (skin weights)；对于每个 LOD，各自独立存储 mesh geometry + skin 数据 + blendshape target deltas (即每个 blendshape 对应的 “delta 顶点偏移”)。形状目标变形 (vertex displacement)（即 blendshape delta）通常 _只在 LOD 0_ 存储 / 使用。 lower LODs (LOD ≥ 1) 通常只有骨骼 skinning (skinning via joints)，不使用 per-vertex morphs。 ([Epic Games Developers](https://dev.epicgames.com/documentation/en-us/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA, Rig Definition, and Rig Operation \| MetaHuman Documentation \| Epic Developer Community"))|

这种 “分层 + 模块化 (layered & modular)” 设计，使得根据用途 (runtime only / full export / geometry editing / rig inspection) 只加载必要部分成为可能。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))

# 🔧 更深 — 关键 Block / Data Segment 与细节

虽然 DNA 是专有 binary 格式 (proprietary binary)，不过通过开源工具 DNACalib / DNAViewer 等，我们可以看到其基本结构和关键 block (chunk) —— 以下是一些重要部分与其作用。

## Definition Layer 关键内容

- **Joint list + hierarchy** — 每个 joint 有名字 + parent index + maybe metadata (joint type: surface vs volume vs corrective) + bind-pose transform (translation, rotation, scale)
    
- **Control list** — 所有 GUI controls / facial controls / sliders / animated-map controls 的名字与标识 (ID / index)
    
- **Blendshape / Shape target list** — 所有 shape targets (morph targets) 名称 + associated mesh / LOD / maybe vertex subsets
    
- **Animated maps** — name + mapping to control(s) / channels (for custom driven maps — e.g. wrinkle maps / texture-driven maps)
    
- **Meshes / LODs** — 对于每 LOD (通常 LOD0~LOD7) 的 mesh definitions：mesh 名称 / ID / LOD index / submesh info / which blendshapes apply / which skin-joints apply / which animated-maps apply
    

这种静态结构使得工具 (例如 DNAViewer) 能够建立完整的 Maya rig + mesh (bind-pose) / skeleton / skinning 基础。 ([epicgames.github.io](https://epicgames.github.io/MetaHuman-DNA-Calibration/index.html?utm_source=chatgpt.com "MetaHuman DNA Calibration — DNA Calibration documentation"))

## Behavior Layer 关键内容 (Rig Logic 映射 / 推理数据)

Behavior 层实际上包含了运行动作 (runtime evaluation) 所需的大量映射/系数。具体包括：

- **控制 → raw 控制通道 (raw control values)** 的 remap 信息 (animated-maps): 可能是 lookup table (LUT)、piecewise-linear 曲线、或样条 /校正曲线，用来将 UI 控制 (例如 “brow up” slider 0–1) 映射到 internal control value (可正负 / 超过 0–1 / 对称等) 以驱动 rig。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    
- **控制 → joint transform / blendshape weight** 的 mapping / coefficient 数据 — 通常是稀疏矩阵 (sparse matrix) + bias/offset +可能 clamp/threshold + corrective shape triggers 。也就是说，RigLogic 在运行时就是加载这些系数 + 输入值 + 做 matrix multiply / accumulation / clamp / then output joint transforms + blendshape weights。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    
- **Correctives / wrinkle maps / animated-map triggers** — 当多个 controls 组合或特定 expressions 时，需要额外的形状校正 (corrective) / 混合 / 动态贴图／材质驱动 (例如皱褶纹理，wrinkle masks)。这些也包含在 Behavior 层 (mapping + data) 中。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    

因为 Behavior 层与 Geometry 层在逻辑上是独立 (decoupled) 的 —— 换句话说，你可以只加载 Behavior (rig + animation) 而不加载 geometry (mesh / skin / blendshape deltas) —— 这对 runtime (游戏中只需要驱动骨骼 + maybe skinning) 非常重要。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))

## Geometry Layer 关键内容 (mesh + skin + blendshape deltas)

Geometry 层包含：

- 对于每 LOD (0..7) 的 mesh geometry：顶点 (vertex positions)、拓扑 (faces / indices)、UVs、normals、vertex colors (如果有)、vertex groups / skin weights (绑定到哪几个 joints + 权重值)
    
- 对于 LOD0 (最高精度) —— blendshape target deltas: 每个 blendshape (shape target) 的 “delta 顶点偏移 (vertex displacement)” 信息 (即 morph target 数据)
    
- (可能) sub-mesh / material / UV map / vertex color / tangent / bitangent / other mesh metadata
    

这个层使得你可以重建一个完整可用的 skin-mesh，用于渲染 / skinning / export (例如导出 FBX 等)，并且因为 blendshape deltas 只在 LOD0，所以 lower LODs 在运行时通常只做骨骼 skinning (skinning + joint transforms)。 ([Epic Games Developers](https://dev.epicgames.com/documentation/en-us/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA, Rig Definition, and Rig Operation | MetaHuman Documentation | Epic Developer Community"))

# ⚠️ 限制 & “为什么不能给出 _每字节_ 说明”

- 虽然 DNA binary 格式已被开源库 (DNACalib) 反序列化/编辑，但 **详细的字节级结构** (即 “header layout + 字节对齐 + padding + 压缩 / 量化 /存储顺序 /版本兼容 + 数据块 offsets + 索引 / lookup tables”) 并 **不** 被官方文档公开全面列出 (至少没有公开 “whitepaper” 列出完整 binary layout) 。官方文档 与开源库更多给出 “逻辑层 + data category + high-level mapping / structure” 描述。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    
- DNA 格式是 **版本化 (versioned)** 的。不同 rig definition (如旧的 “DHI” vs 新的 “MH.4”) 在 joint 数量 / blendshape 数 / maps / animation definitions 上可能不同。开源工具 DNACalib 必须分别对应各版本。 ([GitHub](https://github.com/EpicGames/MetaHuman-DNA-Calibration?utm_source=chatgpt.com "GitHub - EpicGames/MetaHuman-DNA-Calibration"))
    
- 一些数据 (特别是 Behavior layer 的映射系数, animated-map 曲线, corrective shape triggers) 可能被**压缩 / 量化 /稀疏存储** (sparse matrices / LUT / compressed deltas / quantized weights) —— 这使得 “human readable + consistent across versions + 每字节解释” 变得复杂。官方只保证有对应 loader / runtime evaluator (RigLogic) 来正确读取。 ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-5c9f23f7e210.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    

因此，如果你希望 “完全自己手写 loader / parser / inspector /编辑器”，除非你研究 DNACalib 源码 + debug binary + 逆向 mapping，很难单靠公开文档对每一个 byte 给出解释 (尤其是 compressed / quantized parts)。

## ✅ RigLogic 是什么 (定位和作用)

- RigLogic 是 MetaHuman 的 **运行时 (runtime) 绑定／动画 驱动系统 (solver / evaluation system)**。也就是说，它是负责把 “动画师 / 表情输入 / 控制器 (controls)” 映射成 “关节 (joints) 变换 + 顶点形变 (blendshape / morph) + wrinkle／材质贴图 (如果有)” 的那个关键模块。([Epic Games Developers](https://dev.epicgames.com/documentation/en-us/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA, Rig Definition, and Rig Operation | MetaHuman Documentation | Epic Developer Community"))
    
- RigLogic 支持同时驱动身体 (body) 和面部 (face)，但它最出名 / 最重要的是 **面部 (facial rig)**。([Epic Games Developers](https://dev.epicgames.com/documentation/zh-cn/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA、绑定定义以及绑定操作 | MetaHuman 文档 | Epic Developer Community"))
    
- 它是由 3Lateral（后来并入 Epic Games）开发的。([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-zhcn-5860d80f8357.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    
- 在各大支持 MetaHuman 的软件／平台中 (例如 Unreal Engine, Maya, Blender) 都有对应插件／实现，使得无论在 DCC (Maya/Blender) 还是游戏 runtime 下，都能一致地执行表情和骨骼 + 形变。([docs.polyhammer.com](https://docs.polyhammer.com/meta-human-dna-addon/terminology/?utm_source=chatgpt.com "Terminology - Poly Hammer Docs"))
    

**简单一句话**：RigLogic 就是 MetaHuman 的“大脑” — 接收高层语义控制 (笑、皱眉、嘴型…) → 输出骨骼动作 + 面部形变 + wrinkle/morph 材质 → 实现高保真的数字人动画 / 表情 /绑定。

## 🔄 RigLogic 的运作机制 (High‑Level Pipeline)

可以把 RigLogic 的工作流程分为几个阶段／部分：

1. **输入 (Inputs / Controls)**  
    — Animator / 控制面板 (face‑board) 上的若干语义通道 (semantic channels)，比如 “inner brow up/down”, “mouth smile”, “jaw open”, “eye blink”…… hundreds of such control channels. ([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-zhcn-5860d80f8357.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    
2. **Rig Definition + Mapping 数据 (定义 + 映射关系)**  
    — 在对应的 MetaHuman DNA 里，包含了骨骼 (joints) 的 hierarchy + 静态 bind‑pose / neutral‑pose + mesh / skin / blendshape / LOD / geometry + mapping 数据 (controls → joints, controls → blendshapes, controls → wrinkle maps / material parameters) 等。([Epic Games Developers](https://dev.epicgames.com/documentation/en-us/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA, Rig Definition, and Rig Operation | MetaHuman Documentation | Epic Developer Community"))
    
3. **实时评估 (Evaluation)**  
    — RigLogic 在运行时读取控制器输入 + DNA 映射数据 → 计算出每帧 (或每次驱动) 的骨骼变换 (joint transforms) + 面部 / 身体形变 (blendshapes / morphs) + wrinkle /材质通道 (如果有) → 应用到网格 (skinned mesh + morph) 上 → 最终呈现动画 / 表情。([Epic Games Developers](https://dev.epicgames.com/documentation/en-us/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA, Rig Definition, and Rig Operation | MetaHuman Documentation | Epic Developer Community"))
    
4. **LOD / 优化 /扩展**  
    — RigLogic 支持多 LOD (level‑of‑detail)：高精度 LOD (LOD 0) 包含完整形变 (blendshapes + vertex morph)；低 LODs 则可以仅用骨骼 skinning，从而节省性能／内存。([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-zhcn-5860d80f8357.pdf?utm_source=chatgpt.com "RIG LOGIC"))  
    — 同时，因为映射和评估机制是数据驱动 (data‑driven／mapping‑driven)，理论上可以对 DNA 做裁剪 (裁减某些 blendshape / joints / wrinkle maps)，适配不同平台或性能需求。([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-zhcn-5860d80f8357.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    

总结：RigLogic 是一个 **数据驱动 (data‑driven)、跨平台 / 跨工具 (DCC ↔ Engine) 的统一 rig‑solving 框架**。

## ⚠️ 局限 / 注意事项 / 常见问题

不过，RigLogic 并不是“万能 + 完美” — 作为技术美术／绑定师 / TA，你也需要意识到它的一些限制与可能的坑：

- **LOD 切换 / 性能峰值**：有用户 (社区) 反馈，当在 runtime 中切换 LOD（例如距离远近触发 LOD change）时，RigLogic 评估会有明显的性能峰 (spike)，因为 morph / skin / mapping 可能需要重新计算 / 重载。([Epic Developer Community Forums](https://forums.unrealengine.com/t/riglogic-causes-spikes-when-switching-lods-metahuman-face/1330157?utm_source=chatgpt.com "RigLogic causes spikes when switching LODs (Metahuman face) - Character & Animation - Epic Developer Community Forums"))
    
- **Morph / Blendshape 的线性限制**：形变 (vertex displacement / blendshape) 本质是线性混合 (linear interpolation & blending)，在大幅度或极端表情 /变形时，有可能出现不自然 /失真 /塌陷，特别是在低精度 LOD /压缩 /削减后。白皮也提到这一点。([cdn2.unrealengine.com](https://cdn2.unrealengine.com/rig-logic-whitepaper-v2-zhcn-5860d80f8357.pdf?utm_source=chatgpt.com "RIG LOGIC"))
    
- **修改 / 自定义的复杂性**：虽然理论上你可以修改 DNA / geometry / skin / blendshape / LOD，但因为 mapping / solver /各组件耦合紧密，任意不当修改可能导致变形错误、不兼容 RigLogic / Control‑Rig / Animation 系统。需要有经验的人谨慎处理。
    
- **依赖工具 / 插件 / 版本**：RigLogic 是专有技术 + 特定版本 (DNA版本 + engine/plugin 版本) 绑定。不同版本的 RigDefinition / DNA / Engine 可能不兼容。([Epic Games Developers](https://dev.epicgames.com/documentation/zh-cn/metahuman/metahuman-dna-rig-definition-and-rig-operation?utm_source=chatgpt.com "MetaHuman DNA、绑定定义以及绑定操作 | MetaHuman 文档 | Epic Developer Community"))
