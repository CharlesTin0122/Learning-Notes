# OpenRigLogic 是什么

它把此前只随 MetaHuman-DNA-Calibration 仓库半开放（且许可受限）的两个核心库，以 MIT 许可正式开源了：

|组件|内容|
|---|---|
|DNA Library|读写 MetaHuman .dna 文件的 C++ 库（`dna::BinaryStreamReader/Writer`），含 Python 绑定（SWIG）|
|RigLogic|MetaHuman 绑定的实时求解引擎（`rl4::RigLogic`/`RigInstance`），和 UE 内部运行时同一套代码，含 SIMD/AVX/半精度优化，含 Python 绑定|
|docs/design|完整的架构设计文档 + RigLogic 白皮书|
|分支策略|`main` = 实验性，`5.8` = 生产可用（对应 UE 5.8）|

配套的示例资产和 Faceboard Control Rig 在 Fab 上单独免费提供（Fab 标准许可）。

# 对你（绑定 TA）意味着什么

## 1. 最直接：在任意 DCC/自研工具里原生求解 MetaHuman

核心用法就是 `examples/Basic.cpp` 那 30 行：加载 .dna → 设置 raw control（GUI 控制器值）→ `calculate()` → 拿到关节变换、BlendShape 权重、动态贴图权重三路输出。你可以：

- 在 MotionBuilder 里做 MetaHuman 面部实时预览——这是目前生态的空白。用 Python 绑定（pyfbsdk + riglogic pyd）或写个原生 MoBu 插件，把 faceboard 控制器值喂给 RigLogic，输出驱动关节和 BS。以你的 MoBu Rigging 背景，这可能是最有价值的应用
- 给 X12RigAnimTools 加 MetaHuman 面部模块，不依赖 Epic 的 Maya 插件（embeddedRL4 之类闭源 mll）
- 写命令行批处理工具：批量烘焙表情动画 → 关节/BS 曲线，用于导出到任何引擎

## 2. DNA 文件的完全读写自由

上次我们分析过：官方 DNACalib 命令层没有"新增骨骼/BlendShape"的入口，但底层 Writer API 可以。现在这个 Writer 以 MIT 许可完全开放，你可以：

- 自己实现 SuperRiggingEditor 那种"向头部 DNA 加关节/加 BS 通道"的功能（`setJointName`/`setJointHierarchy`/`setBlendShapeChannelName` + behavior 层索引对齐），不再受商业插件的机器码授权约束
- 写 DNA 检查/对比/合并工具（比如 diff 两个角色的 joint group 差异）
- 做任意拓扑 → MetaHuman 的迁移管线中 DNA 生成那一环

## 3. 许可层面的解放（对商业项目最重要）

以前 MetaHuman-DNA-Calibration 的许可把使用范围限制在 MetaHuman/UE 生态内；MIT 意味着你可以把 RigLogic 求解器嵌进任何商业软件、任何引擎、任何平台（README 明确说支持主机和移动端）。Epic 的意图很明显：把 DNA + RigLogic 推成数字角色的行业标准格式，就像 USD 之于场景描述。第三方 DCC（Blender、Houdini 已有官方插件、C4D 等）都可以合法集成。

## 4. 学习价值

`docs/design` 里有完整的设计文档，加上 RigLogic 白皮书，是研究"如何设计一个高性能面部绑定运行时"（PSD 矩阵求解、joint group 分块、LOD 裁剪、SIMD 布局、ML 变形层）的一手资料——对你做自研绑定运行时很有参考价值。

# 实际建议

以你的技术栈，性价比最高的切入点：

1. 先把 Python 绑定编译出来玩（CMake + SWIG，绑 Python 3.10/3.11 就能同时在 Maya 2024 和 MoBu 里用）：克隆 `5.8` 分支 → `cmake .. -DRL_BUILD_WITH_AVX=ON` + 开 Python wrapper 选项 → 得到 `dna` 和 `riglogic` 两个 pyd
2. 用 MetaHuman Creator 的 DCC Export 导出 head.dna/body.dna 作为测试数据
3. 第一个小目标：Python 脚本加载 head.dna，扫一遍 raw controls，打印每个控制器影响的关节和 BS 通道——这一步就能验证整条链路通了
