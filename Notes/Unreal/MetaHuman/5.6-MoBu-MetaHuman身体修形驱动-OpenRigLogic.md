# 5.6 MoBu MetaHuman 身体修形驱动（OpenRigLogic body.dna）

> 在 MotionBuilder 中用 `body.dna` 复现 MetaHuman 身体的 RBF/SwingTwist 修形逻辑，
> 让身体摆姿势时修形关节（correctiveRoot/knee/bulge/twist…）自动联动。
> 与面部同一套 RigLogic 求解管线，唯一区别：输入源从面板控制器换成**驱动关节的旋转**。
> 交付模块：`D:\Code\MoBuMetaHuman\body_corrective.py`
> 相关笔记：[5.4-MoBu面部驱动实战](5.4-MoBu-MetaHuman面部驱动实战-OpenRigLogic.md)、[5.5-FaceBoard面板机制](5.5-MetaHuman-FaceBoard面板机制解析.md)

## 一、要不要先去 Maya 研究修形逻辑？——不用

结论先行：**修形逻辑的"真身"在 `body.dna` 里，不在 Maya 场景里**。Maya 的 `body_rl4Embedded` 只是 RigLogic 宿主，输入全部来自 `驱动关节旋转 → unitConversion → rl4`。与其去 Maya 逆向，不如直接离线审 DNA——所有信息（输入格式、驱动关系、四元数空间）都能从 DNA 读出来并用冒烟测试验证。只有旋转空间出现歧义时，才值得去 Maya 抓 `body_rl4Embedded` 的 unitConversion 输入做 5 分钟对照。

## 二、body.dna 结构（离线审查结论）

| 项 | 值 |
|---|---|
| 关节 | 342 个，4 级 LOD |
| BlendShape | **0**（身体修形纯靠关节，无 BS） |
| Raw controls | **176 = 44 驱动关节 × 四元数 (qx,qy,qz,qw)** |
| GUI controls | 0（身体无 GUI 层，直接吃关节旋转） |
| RBF solvers | **72 个** `*_UERBFSolver`（每驱动关节一个，含 half 变体） |
| SwingTwist | **8 条 twist 链**（upperarm/lowerarm/thigh/calf × 左右） |
| 修形输出 | **258 个被驱动关节**（correctiveRoot/knee/kneeBack/bulge/twist/twistCor + 手指全套） |

### 输入：44 个驱动关节
四肢大关节 + 全部手指关节：calf/clavicle/foot/hand/lowerarm/upperarm/thigh/spine + index/middle/pinky/ring/thumb 各节。
Raw control 命名 `<关节名>.qx/qy/qz/qw`，按关节四连排布（i, i+1, i+2, i+3）。

### SwingTwist 驱动关系（从 DNA 直接读）
**末端关节驱动上游 twist**，与 UE `SwingTwistEvaluator` 一致：
```
hand_l  → lowerarm_twist_01/02_l      foot_l → calf_twist_01/02_l
thigh_l → thigh_twist_01/02_l         upperarm_l → upperarm_twist_01/02_l
```

## 三、四元数空间验证（冒烟测试）

三个疑点用离线冒烟测试全部确认：

1. **Identity 四元数 (0,0,0,1) → 输出增量精确全零** ✅ → 输入是"相对中立的旋转"，无需预变换
2. **calf_l 绕 Y/Z 转 90°**（膝盖弯曲方向）→ 正确激活 `calf_knee_l`、`calf_kneeBack_l`、`calf_correctiveRoot_l`、twistCor 等 6 个修形关节 ✅
3. **calf_l 绕 X 转**（沿骨轴扭转）→ 只激活 correctiveRoot ✅ → 符合"扭转交给 twist 链、摆动交给 RBF"的设计

## 四、⭐ 关键坑：不能直接用 Lcl Rotation 当输入

这是本次最重要的教训，也是第一版驱动 T-pose 下出现 **24 个假修形输出**的根因。

### 现象
`SKM_H10100_AllMesh.fbx` 导入 MoBu 后，骨架对齐校验发现：
- **244 个关节带非零 Pre-Rotation**，中立姿态的旋转由 Pre-Rotation 承载，Lcl Rotation ≈ 0
- **但并非全部**：手臂等约 24 个关节在绑定姿势下 `Lcl Rotation ≠ 0`

所以"直接把 Lcl Rotation 转四元数喂 DNA"对那 24 个关节是错的——它们在 T-pose 就送进了非零旋转，导致假修形。

### 正确公式
喂给 DNA 的必须是**相对 DNA 中立姿态**的旋转：
```
q_rel = q(DNA中立)⁻¹ ∘ q(PreRotation) ∘ q(Lcl Rotation)
```
- 绑定姿势下 `pre ∘ lcl_bind == neutral`（对齐校验 341/341 保证），于是 `q_rel = identity`，T-pose 输出精确归零 ✅
- 每关节 `q_corr = q(DNA中立)⁻¹ ∘ q(PreRotation)` 可在 initialize 时**预缓存**，每帧只需再乘一次 `q_lcl`

### 对齐校验方法（可复用）
逐关节比较 `q(PreRotation) ∘ q(Lcl Rotation)` 与 `q(DNA中立)` 的夹角：
- 只比 Lcl vs 中立 → 244 个不匹配（Pre-Rotation 没算进去）
- 比 pre∘lcl vs 中立 → **341/341 全通过**（夹角 < 0.5°），证明 FBX 骨架与 DNA 中立完全一致

## 五、模块设计（body_corrective.py）

```
initialize(dna_path)   加载DNA + 建立输入/输出映射 + 预缓存 q_corr
drive_once()           读当前姿态驱动一次修形
start_realtime()       OnUIIdle 实时（带脏检查：姿势不变零开销）
stop_realtime()
bake_range(start,end)  身体动画逐帧 → 修形关节TRS关键帧
```

### 输入端
每帧读 44 驱动关节 Lcl Rotation → `q_rel = q_corr ∘ q_lcl` → `setRawControl`（176 个）→ `calculate`。

### 输出端
258 个修形关节：平移 = 中立平移 + 增量；旋转 = 增量直写 Lcl（因中立旋转由 Pre-Rotation 承载，Lcl 基线为 0）。
**驱动关节自身排除出输出集**（`input_joint_names` 过滤），避免覆盖动画/姿势。

### 脏检查
缓存上一帧 176 个输入值，无变化直接跳过 calculate+写场景——这是从面部 FaceBoard 那次"静止仍持续重写导致视口抖动"坑里得到的教训（见 5.5 结尾）。

## 七、缩放输出与颈部 RBF（后续补全，已实机验证）

**缩放**：RigLogic 每关节输出 9 属性 `[t3 r3 s3]`，初版只取了前 6 个。body.dna 实测 **234 个关节带缩放输出**（可变属性 s:702），弯膝时 `calf_kneeBack_l.sx=-0.10`（腘窝压缩）、`calf_knee_l.sx=+0.07`（髌骨隆起）——肌肉体积修形不可丢。应用 `Scaling = 1.0 + ds`，烘焙扩到九通道。head.dna 无缩放输出（s:0），面部模块无需改。

**颈部 RBF**：head.dna 的 12 个非表情输入 `neck_01/neck_02/head.qx~qw` 是其唯一 RBF solver（neckCorr，38 pose）的全部输入（官方 MetaHumanForMaya 把这三关节接进 head RL4，importer.py 的 inputJoints 接线）。只写表情控制时它们恒为全零（退化四元数→RBF 无激活→转头/低头时 186 个 FACIAL_*_Neck* 修形不工作）。已在 mh_face_preview 实装 `feed_neck_inputs()`（公式与身体侧相同），set_expression/faceboard_bridge/mh_full_rig 三处调用点自动重喂。实机锚点：head 转 45° → **18/18 RBF 激活、186 关节联动**，恢复中立无残留。
