# OpenRigLogic 编译指南（Windows / Python 绑定）

> 目标：从源码编译出 `dna` + `riglogic` 两个 Python 扩展模块，供 Maya / MotionBuilder / 独立 Python 使用。
> 本机已于 2026-07 按本指南编译成功（Maya 2024 / Python 3.10 目标）。
> 相关笔记：[RigLogic架构设计](5.1-RigLogic架构设计-OpenRigLogic.md)、[编译结果使用指南](5.3-OpenRigLogic编译结果使用指南.md)

## 一、准备工作

### 1. 获取源码

```bash
# 生产项目用数字分支（对应 UE 版本，immutable 快照）
git clone -b 5.8 https://github.com/EpicGames/OpenRigLogic.git
# 或跟踪最新实验特性
git clone https://github.com/EpicGames/OpenRigLogic.git   # main 分支
```

本机克隆位置：`D:\Code\OpenRigLogic`（5.8 分支）。

### 2. 工具链清单

| 工具 | 要求 | 本机来源 |
|---|---|---|
| C++ 编译器 | C++11+ | Visual Studio 2022 Community（MSVC 19.44） |
| CMake | ≥ 3.14 | scoop（4.3.4） |
| SWIG | 仅编译 Python 绑定时需要 | `scoop install swig`（4.4.1） |
| Python 3 **完整发行版** | 需要 `include/`（头文件）和 `libs/`（导入库） | uv 管理的 CPython |

### 3. ⚠️ 关键：Python 发行版的选择

**不要用 mayapy**——Maya 安装目录里只有 `lib/python310.lib`，**没有 Python.h 头文件**，CMake 的 `find_package(Python3 ... Development)` 会失败。

正确做法：用一个**与目标 DCC 的 Python 版本号完全一致**的独立 CPython 完整发行版。本机 uv 管理的版本可直接用：

```
C:\Users\dalaotian\scoop\persist\uv\python\versions\cpython-3.10.8-windows-x86_64-none\
├── include\      ← 头文件（必需）
├── libs\         ← python310.lib（必需）
└── python.exe
```

版本对照：

| 目标 DCC | Python 版本 |
|---|---|
| Maya 2024 / MotionBuilder 2024 | 3.10 |
| Maya 2025/2026 / MoBu 2025+ | 3.11 |

> 编译出的 .pyd 只依赖 `python310.dll`（随 DCC 自带），同一 Python 小版本的所有宿主通用——一次编译，Maya/MoBu/独立解释器都能用。

## 二、CMake 配置

```bash
cd /d/Code/OpenRigLogic
mkdir -p build && cd build

cmake .. -G "Visual Studio 17 2022" -A x64 \
  -DRL_BUILD_PYTHON_WRAPPER=3.10 \
  -DPython3_ROOT_DIR="C:/Users/dalaotian/scoop/persist/uv/python/versions/cpython-3.10.8-windows-x86_64-none" \
  -DRL_BUILD_TESTS=OFF -DRL_BUILD_BENCHMARKS=OFF -DRL_BUILD_EXAMPLES=OFF
```

### 参数说明

| 参数 | 作用 |
|---|---|
| `RL_BUILD_PYTHON_WRAPPER=3.10` | **核心开关**：填 Python 版本号（EXACT 匹配），同时启用 dna 和 riglogic 两个 wrapper。不填则只编 C++ 库 |
| `Python3_ROOT_DIR` | 指向上文的完整 CPython 发行版根目录 |
| `RL_BUILD_TESTS/BENCHMARKS/EXAMPLES=OFF` | 默认都是 ON；关掉可跳过 GoogleTest/Benchmark 的联网下载，编译更快 |

### 可选性能开关

| 参数 | 说明 |
|---|---|
| `-DRL_BUILD_WITH_SSE=ON` | 强制 SSE 路径（`RL_AUTODETECT_SSE=ON` 为自动探测） |
| `-DRL_BUILD_WITH_AVX=ON` | AVX 关节求解（运行 CPU 需支持） |
| `-DRL_BUILD_WITH_HALF_FLOATS=ON` | 半精度关节存储（需 CPU F16C 指令集），省一半内存 |
| `-DRL_BUILD_WITH_*_ROTATION_ORDER=OFF` | 默认 6 种旋转顺序全开；关掉不用的可减小二进制体积 |

> 即使编译时不开 SSE/AVX，运行时也有 CPU 特性自动探测（`RL_DISABLE_RUNTIME_FEATURE_DETECTION` 默认 OFF），并可在 Python 侧通过 `riglogic.Configuration().calculationType` 选择计算路径。


## 三、编译

```bash
cd /d/Code/OpenRigLogic/build
cmake --build . --config Release --parallel 16
```

- 耗时约 3~5 分钟（16 线程）
- SWIG 阶段会刷一堆 `warning 317/401/315`（模板特化提示），**属正常，可忽略**
- 成功标志：末尾出现
  `py3dna.vcxproj -> ..._py3dna13_2_5.pyd` 和
  `py3riglogic.vcxproj -> ..._py3riglogic13_2_5.pyd`

## 四、收集产物

产物分散在两处（**生成的 .py 包装层不在 Release 目录里**，是个坑）：

```
build/python/dna/dna.py                       ← SWIG 生成的 Python 包装层
build/python/dna/Release/_py3dna13_2_5.pyd    ← C++ 扩展
build/python/riglogic/riglogic.py
build/python/riglogic/Release/_py3riglogic13_2_5.pyd
```

收拢成一个可分发目录：

```bash
cd /d/Code/OpenRigLogic
mkdir -p dist/py310
cp build/python/dna/dna.py            build/python/dna/Release/_py3dna*.pyd \
   build/python/riglogic/riglogic.py  build/python/riglogic/Release/_py3riglogic*.pyd \
   dist/py310/
```

最终就是 **4 个文件**（文件名中的 `13_2_5` 是 RigLogic 库版本号，随分支变化）：

```
dist/py310/
├── dna.py
├── _py3dna13_2_5.pyd
├── riglogic.py
└── _py3riglogic13_2_5.pyd
```

## 六、常见问题（FAQ）

| 问题 | 原因/解法 |
|---|---|
| `find_package(Python3 ... Development)` 失败 | `Python3_ROOT_DIR` 指向的发行版缺 `include/` 或 `libs/`（典型：指向了 mayapy） |
| 找不到 SWIG | `scoop install swig`，或 `-DSWIG_EXECUTABLE=<path>` 手动指定 |
| 换 Python 版本重编 | **删除整个 build 目录**重新 configure（CMake 缓存了 Python 路径） |
| import 时 `DLL load failed` | 运行环境的 Python 小版本与编译目标不一致（如用 3.11 加载 3.10 的 .pyd） |
| 想要 Linux/macOS 版 | 同样流程，把生成器换成默认 make/ninja；产物为 `.so` |
