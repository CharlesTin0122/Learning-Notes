# 5.5 MetaHuman FaceBoard 面板机制解析

> 研究对象：H10100 Maya 绑定场景中的面部控制面板（`headRig_grp > headGui_grp > GRP_faceGUI`）。
> 目的：搞清 FaceBoard 如何操控表情，为把面板动画通过 FBX 导入 MotionBuilder 驱动表情做准备。
> 完整映射表已导出：`D:\Code\MoBuMetaHuman\faceboard_mapping.json`（252 条 GUI→expression 映射 + 4 条眼睛特殊链路）。
> 相关笔记：[RigLogic架构设计](5.1-RigLogic%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1-OpenRigLogic.md)、[MoBu面部驱动实战](5.4-MoBu-MetaHuman%E9%9D%A2%E9%83%A8%E9%A9%B1%E5%8A%A8%E5%AE%9E%E6%88%98-OpenRigLogic.md)

## 一、整体数据流

```
GUI 控制器（174 个 CTRL_* transform，滑条即位移）
    │  translateY / translateX（有 transformLimits 限位）
    ▼
animCurveUU 重映射曲线（252 个，命名 CTRL_expressions_<属性名>）
    │  把控制器位移量重映射为 0~1 表情激活值
    ▼
CTRL_expressions 节点（transform，252 个自定义属性 = raw controls）
    │  browRaiseInL / jawOpen / mouthCornerPullL ...
    ▼
head_rl4Embedded（embeddedNodeRL4，RigLogic 求解节点）
    ▼
面部关节 + BlendShape + 动态贴图
```

**三层结构的意义**：

| 层 | 角色 | 对应 OpenRigLogic API |
|---|---|---|
| `CTRL_*` GUI 控制器 | 动画师交互层（**GUI controls**），滑条位置就是 transform 位移 | `inst.setGUIControl()` |
| animCurveUU 曲线 | GUI→Raw 的重映射（量程/拆分/分段） | `rig.mapGUIToRawControls()` |
| `CTRL_expressions.*` | **Raw controls**（求解器直接输入） | `inst.setRawControl()` |

> 这正是 DNA 文件里 Definition 层 GUI controls 与 raw controls 两套控制器名的场景化身——`reader.getGUIControlName(i)` 返回的就是 `CTRL_L_brow_raiseIn.ty` 这种"控制器.通道"名，`getRawControlName(i)` 返回 `CTRL_expressions.browRaiseInL`。

## 二、GUI 控制器层（174 个）

### 通道使用统计（触摸板式设计）

| 通道组合 | 数量 | 示例 | 说明 |
|---|---|---|---|
| 仅 `translateY` | **151** | CTRL_L_brow_raiseIn、CTRL_L_mouth_cornerPull | 一维滑条（绝大多数） |
| `translateX + translateY` | **14** | CTRL_C_jaw、CTRL_C_eye、CTRL_C_mouth、CTRL_L_nose | 二维摇杆 |
| 全通道 | 4 | CTRL_faceTweakersGUI 等 | 面板布局/分组用，非表情 |
| 无 keyable | 2 | CTRL_rigLogicSwitch、CTRL_GUIswitch | 开关（enum 属性） |

### 限位（transformLimits）

- 单向滑条：`ty ∈ [0, 1]`（如眉毛抬起）
- 双向滑条/摇杆：`tx/ty ∈ [-1, 1]`（如 CTRL_C_jaw 的 tx 左右摆）
- 眼睛注视 CTRL_C_eye/L/R：二维摇杆，经旋转驱动特殊链路（见第四节）

命名规律：`CTRL_<L|R|C>_<部位>_<动作>`，与 CTRL_expressions 属性名的对应关系是**规则化改写**：`CTRL_L_brow_raiseIn.ty → browRaiseInL`（部位+动作驼峰拼接，L/R 后缀）。

## 三、重映射层（252 个 animCurveUU）

每条曲线是 `驱动值→激活值` 的分段线性函数，**这一层就是把"滑条位移"翻译成"表情强度"的全部逻辑**。四种形态（实测统计）：

| 重映射形态 | 数量 | 用途 |
|---|---|---|
| `(0,0)→(1,1)` 恒等 | 168 | 单向滑条直通 |
| `(-1,1)→(0,0)` 负向翻转 | 66 | **双向轴拆分**：一根轴拆两个表情 |
| 分段脉冲（如 `(0,0)→(0.33,1)→(0.66,0)`） | 12 | **相位分解**：一根滑条按行程激活多个 Ph 通道 |
| 角度量程（如 `(0,0)→(40,1)`） | 8 | 眼睛注视角→激活值 |

### 双向轴拆分示例（CTRL_C_jaw.tx）

```
CTRL_C_jaw.tx ──┬── CTRL_expressions_jawRight: (0,0)→(1,1)    tx>0 时激活 jawRight
                └── CTRL_expressions_jawLeft:  (-1,1)→(0,0)   tx<0 时激活 jawLeft
```

69 个 GUI 通道是这种一对多驱动（眨眼、上下眼睑、瞳孔等都是"一轴管两个互斥表情"）。

### 相位分解示例（吞咽/黏唇）

```
CTRL_C_neck_swallow.ty → neckSwallowPh1: (0,0)→(0.2,1)→(0.4,0)
                       → neckSwallowPh2: (0.2,0)→(0.4,1)→(0.6,0)
                       → neckSwallowPh3: (0.4,0)→(0.6,1)→(0.8,0)
                       → neckSwallowPh4: (0.6,0)→(0.8,1)→(1,0)
```

滑条从 0 拉到 1，四个相位通道依次接力激活——一根滑条播完整个吞咽动作序列。`CTRL_L/R_mouth_lipSticky` 同理拆 3 相位。

## 四、眼睛注视的特殊链路

`CTRL_L/R_eye`（二维摇杆）不直接进 CTRL_expressions，而是：

```
CTRL_L_eye.tx → animCurveUA(LOC_L_eyeUIDriver_rotateY) → LOC_L_eyeUIDriver 旋转
CTRL_L_eye.ty → animCurveUA(LOC_L_eyeUIDriver_rotateX) ↗
    然后 LOC 旋转角 → unitConversion → animCurveUU → eyeLookLeftL/RightL/UpL/DownL
    量程：左/下 40°→1.0，上 30°→1.0（上视角行程更小）
```

即摇杆先转一个**注视驱动 locator**（角度空间），再把角度按方向拆成 4 个 look 表情激活值。`CTRL_C_eye` 是双眼联动版（同时驱动 4 条 animCurveUA 到双眼）。另有 `lookAtSwitch`/`eyeParallelLookDirection` 控制注视模式。

## 五、CTRL_expressions 节点（Raw Controls 载体）

- 一个普通 transform，挂 **252 个自定义 float 属性**，全部连接到 `head_rl4Embedded.inputs[i]`（部分经 unitConversion）
- 252 = 头部 DNA 的 raw control 数（比我们在 OpenRigLogic 里数的 263 少了 11 个——那部分是身体/RBF 输入，不走面板）
- 属性分组：brow/eye/eyelashes/jaw/mouth/neck/nose/teeth/tongue + lookAtSwitch 等开关
- `body_rl4Embedded` 是身体求解节点，输入来自身体骨骼旋转（经 unitConversion），与面板无关

## 六、对 MoBu 迁移的关键结论 ⭐

FBX 导出面板时，**animCurveUU/UA 驱动关系链在 MoBu 里不一定存活**（FBX 对 driven-key 类连接支持有限）。但研究结论显示迁移根本不需要还原这些节点：

1. **动画数据的本体在 GUI 控制器的 TRS 曲线上**（174 个 CTRL_* 的 translateX/Y）——FBX 完整保留 transform 动画，导入 MoBu 后曲线都在
2. **重映射逻辑已完整导出为数据**：`faceboard_mapping.json` 252 条记录，每条含 `gui_plug`（如 `CTRL_C_jaw.translateX`）、`expression`（如 `jawRight`）、`remap` 分段线性关键点——在 Python 里 20 行代码即可复现整个翻译层（分段线性插值）
3. **MoBu 侧驱动方案**：每帧读 GUI 控制器位移 → 查映射表做分段线性插值 → 得到 252 个 raw control 值 → `inst.setRawControl()` → 现有 `mh_face_preview.apply_pose()` 输出关节+BS——**与 Maya 场景行为完全一致**
4. 眼睛注视按第四节公式特殊处理（tx/ty → 角度 → 4 个 look 通道），或者直接用 OpenRigLogic 的 `rig.mapGUIToRawControls(inst)` 让 RigLogic 自己做 GUI→Raw（DNA 里带同样的映射数据，可先验证两者一致性）
5. 面板动画的 FBX 往返 = **Maya keyframe GUI 控制器 → FBX → MoBu 读曲线驱动 / MoBu 烘 GUI 曲线 → FBX → Maya/UE**，三端通用同一套控制器命名
