# 5.7 MoBu C++ RigLogic 约束插件（Open Reality SDK）

> 把 [5.6 身体修形驱动](5.6-MoBu-MetaHuman%E8%BA%AB%E4%BD%93%E4%BF%AE%E5%BD%A2%E9%A9%B1%E5%8A%A8-OpenRigLogic.md) 的 OnUIIdle 脚本方案升级为**求值图内 C++ 约束**——
> 对标 Maya 官方 embeddedRL4 节点的架构形态。MoBu 2024 专用。
> 代码：`D:\Code\MoBuRigLogic`（git 管理，MIT 协议）；插件：`<MoBu>/bin/x64/plugins/moburiglogic_2024.dll`
> 开发流程与坑速查：`mobu-cpp-openreality-plugin` 技能；
> 插件如何使用 OpenRigLogic 的原理综述见 [5.9](5.9-MoBu%E6%8F%92%E4%BB%B6%E5%A6%82%E4%BD%95%E4%BD%BF%E7%94%A8OpenRigLogic-%E5%8E%9F%E7%90%86%E8%A7%A3%E6%9E%90.md)

## 一、为什么要 C++ 约束（OnUIIdle 方案的结构性缺陷）

| OnUIIdle + SetVector（脚本旁路） | FBConstraint（求值图内） |
|---|---|
| 写入在求值后，滞后一拍、可能互刷（视口抖动） | 求值顺序正确，无滞后 |
| **播放/渲染时 OnUIIdle 不触发 → 驱动失效** | **播放/scrub/渲染全程工作** ✅ |
| 修形关节属性自由（可误移动/误 setKey） | **属性被约束占用**（UI 灰、Plot 可烘焙）✅ |
| Python 每帧开销 + GIL | C++ 直调，求解 **0.08ms/帧**（Python 版 0.25ms）|

## 二、架构

```
Navigator 创建约束 "RigLogic Body Corrective"
  ├─ DNA Path 属性 → body.dna（FBPropertyPublish, 随FBX序列化）
  ├─ Skeleton Root 引用组 ← 拖 pelvis（自动向上找根、扫全树建映射）
  ├─ 输入: 44 驱动关节 Lcl Rotation（AnimationNodeOutCreate）
  ├─ AnimationNodeNotify: 每 EvaluationID 求解一次
  │     q_rel = q(DNA中立)⁻¹∘q(Pre)∘q(Lcl) → setRawControl×176 → calculate
  └─ 输出: 258 修形关节 Lcl T/R/S（AnimationNodeInCreate, 属性被占用）
        T=中立+增量  R=增量直写  S=1+增量
```

四元数公式与 Python 版 `body_corrective.py` 逐字一致（已跨 Maya/MoBu/C++ 三方逐位验证）。

## 三、开发过程的四个坑（实测踩过）

1. **链接爆炸 → `PRODUCT_VERSION=2024`**：fbsdk 符号在 `ORSDKPRODUCT_VERSION` 命名空间（宏拼接），
   官方 cmake 的 `mobu_target_finalize` 注入此宏；自建工程必须手动加。
2. **属性不出现 → `FBPropertyPublish`**：`FBPropertyString::Init(this,name)` 编译过但不注册；
   必须 `FBPropertyPublish(this, prop, "Name", nullptr, nullptr)`（SDK 样例 constraintdeformer）。
3. **⭐ rest 姿势输出错 → 节点类型是全局空间**：`ANIMATIONNODE_TYPE_ROTATION`("Rotation") 读到**全局**旋转
   （诊断：calf_l 局部 rest 全零，节点却读出 (-81.6, -2.2, 92.5)）。局部量必须用
   `ANIMATIONNODE_TYPE_LOCAL_ROTATION`("Lcl Rotation") 系列（fbdata.h）。此坑不崩溃、纯数值错，最隐蔽。
4. **BS 权重全零 → 网格不在骨架层级下**：从骨架根收集模型找不到 FBX 导入的网格（挂在场景根），
   BS 绑定悄悄为空。修复：补充从 `Scene->RootModel` 收集全部模型。

## 五、使用（动画师视角）

1. 打开含 MetaHuman 身体骨架的场景
2. Navigator → Constraints → **RigLogic Body Corrective**
3. 属性 DNA Path 填 body.dna 路径；pelvis 拖进 Skeleton Root；勾 Active
4. 完事——摆姿势/播动画/Plot 烘焙，修形全自动；场景保存后重开自动恢复

## 六、头部表情约束（RigLogic Head Expression，已完成）

同 DLL 注册的第二个约束类，把 head.dna 的表情+颈部 RBF+BS 全部搬进求值图：

| 项 | 设计 |
|---|---|
| 表情输入 | **双模式**（Input Mode 属性）：0=252 个可 K 帧动态属性；1=**FaceBoard 面板**（DNA GUI 层直连：面板控制器 Lcl Translation → `setGUIControl` → `mapGUIToRawControls`——双向拆分/相位/眼睛量程全在 DNA 里，Maya 的 animCurveUU 翻译层无需还原） |
| 颈部输入 | neck_01/neck_02/head Lcl Rotation 自动读取 → 12 四元数（转头颈部修形自动联动） |
| 关节输出 | 840 FACIAL_* 关节；旋转按 Pre-Rotation 自动选策略（FaceMesh 中立烘在 Lcl → `q中立∘q增量` 合成） |
| BS 输出 | `AnimationNodeInCreate(uid, FBProperty*)` 接网格 shape 属性，×100 量程；PSD 修正通道自动激活 |

实机验证（含 BS 修复后回归）：
- jawOpen=1 → jaw 合成 62.27° + `head_lod0_mesh__jaw_open`=100 ✅
- 微笑+张嘴0.7 → 修正通道 `McornerPull_Jopen_L`=70（PSD 乘积 1.0×0.7）✅
- jawOpen K 帧 0→1→0 播放：40°→62.27°→40° 平滑跟随 ✅
- head 转 45° → FACIAL_C_NeckB 位移（颈部 RBF，与 Python 版逐位一致）✅
- **头身双约束同开**：弯膝+张嘴互不干扰，合计 ~0.45ms/帧 ✅

**FaceBoard 模式实机验证**：
- 面板 CTRL_C_jaw.ty=1 → jaw 62.27° + BS=100（与表情属性模式等价）✅
- jaw.tx=±1 → jaw ry=±6.88（双向轴拆分）；eye.tx=0.5 → 眼球 ry=21.11 ✅
- **面板 K 帧 0→1→0 播放**：jaw 40°→62.27°→40° —— 面板动画在求值图内直接驱动表情 ✅

**多角色 namespace 实机验证**（组合 FBX 以 CharA/CharB 两 namespace merge 模拟）：
- 约束按引用对象的 namespace 隔离：A 面板只动 A 的脸（B 保持中立 40°）✅
- 无约束角色的面板不驱动任何人 ✅
- 双角色双约束同开各自独立（A ty=1→62.27°、B ty=0.5→51.13°）✅
- 关键：`model.Name` 自动剥 namespace，收集必须用 `LongName` 前缀过滤（详见技能）

## 七、约束自定义 Layout（Setup 面板 UI）

给两个约束加了 `FBConstraintLayout`（`riglogic_layouts.h/cxx`），出现在 Navigator 约束的 Setup 页签：

- **Head 面板**：DNA File 编辑框 + Browse...（FBFilePopup 选 .dna）｜Input Mode 下拉（切换即重建绑定）｜Rebuild Bindings / Zero Expressions 按钮｜状态区（三态：未加载→操作指引 / 未绑定→排查提示 / OK→绑定统计+耗时）
- **Body 面板**：简版（Browse + Rebuild + 状态区）
- 状态区经 OnUIIdle 节流自动刷新（标准操作如直接勾 Active 也能反映）

开发踩的三个坑 + 一个关联修复（详见技能 mobu-cpp-openreality-plugin 的 Layout 章节）：
1. ⭐ **AddRegion 参数序 X 前 Y 后**——写反不报错但面板挤成窄条（本项目实际发生，用户肉眼发现）
2. FBLabel 多行 = `WordWrap`，无 Multilines 枚举
3. OnUIIdle 刷新必须 FBDestroy 摘除 + Caption 变化才写（防泄漏/闪烁）
4. **DNA 热切换 bug**：`!mRig && !LoadDna()` 跳过重载 → 记录 mLoadedDnaPath 检测路径变化（双约束都修了，head→body→head 往返实测恢复）

## 八、多版本支持：MoBu 2019（Py2 时代版本）

CMake 多版本化（`-DMOBU_VERSION=2019/2024`），**源码零改动**编译出 `moburiglogic_2019.dll`。
关键认知：**纯 C++ 插件与 MoBu 内嵌 Python 版本无关**（Py2.7 不影响插件），
唯一硬依赖是 fbsdk 的版本命名空间（`ORSDK2019`/`ORSDK2024`）——每个 MoBu 版本编一份。

2019 实机验证结果：

| 项 | 结果 |
|---|---|
| 双约束注册 / DNA 加载 / Active | ✅ |
| jawOpen 锚点（属性模式 + FaceBoard 面板模式） | ✅ 62.27° 与 2024/Maya 逐位一致 |
| 性能 | 0.556ms/帧 ✅ |
| **BS 权重写入** | ❌ 属性节点重载在 2019 运行时不建立连接（关节表情完整，缺皱纹等 BS 细节）|
| **Input Mode 中途切换** | ❌ 不重建绑定——**创建时就设好 Input Mode 再 Active** |

配套：MCP 监听器已 Py2/Py3 双兼容（`execfile` 加载；坑见 `mobu-cpp-openreality-plugin` 技能）。

## 九、工程化改版（2026-07-14，用户主导重构）

代码告一段落后的系统性整理（git 历史 `38a52e3..21831b2`，~19 提交）：

### 9.1 工程结构

- **git 化 + MIT 协议 + 中文 README**（支持范围表、功能概览、构建/安装/使用说明）
- **OpenRigLogic 依赖 vendor 化**：`third_party/OpenRigLogic/`（include + win64 静态库 + LICENSE + VERSION 13.2.5），CMake 带三重存在性校验（header/lib/license 缺一 FATAL_ERROR）——仓库自包含，不再依赖 D:\Code\OpenRigLogic 外部路径
- **收敛支持范围：仅 MoBu 2024**（删除多版本 `-DMOBU_VERSION` 机制，产物固定 `moburiglogic_2024.dll`；2019 支持被移除）
- **新增 `src/riglogic_common.h`**：无 FBSDK 依赖的纯逻辑层（ClampLod / BlendShapeMappingRef / CollectBlendShapeMappings / FindBlendShapePropertyOwner / OutputRoute）——可脱离 MoBu 单元测试

### 9.2 测试基建（CTest）

- `tests/riglogic_common_tests.cpp`：纯逻辑单元测试（LOD 钳制边界、mapping 收集、BS 宿主查找回退）
- `tests/check_source_regressions.cmake`：**源码回归断言**——防止关键修复被改回去（如：断言产物名固定、断言无多版本残留、断言 vendored 路径存在），相当于把"踩过的坑"固化成 CI 检查

### 9.3 功能修复/改进（相对上一版）

| 提交 | 内容 |
