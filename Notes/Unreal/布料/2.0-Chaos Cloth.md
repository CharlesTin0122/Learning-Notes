# 原理
- ChaosCloth的基本原理是基于低多边形的顶点位置通过模拟粒子驱动渲染模型，通过包裹变形器实现物理模型驱动渲染模型
![](attachments/f56c098340bbf06a4c6cf63ba31ff5f9_MD5.jpg)
- Render Mesh：服装的高模
- Simulation Mesh：服装的低模代理模型
- Animated Mesh：Simulation Mesh 绑定到骨骼后的 skinned 版本
- Physical Mesh：真正参与 Chaos 粒子物理模拟的网格。从 Animated Mesh每个顶点模拟粒子计算得到。
- 他们之间的关系为：
    - Simulation Mesh（低模代理模型） -> 蒙皮 -> Animated Mesh（动画模型）->模拟粒子 -> Physical Mesh（物理模型）-> 包裹变形 -> Render Mesh（渲染模型）
    - Simulation Mesh 通过蒙皮生成 Animated Mesh，Animated Mesh 通过顶点模拟粒子生成 Physical Mesh，Physical Mesh就是布料模拟模型，Physical Mesh 通过包裹变形 Render Mesh，使得Render Mesh跟随变形，得到最终看到的布料动态。

# 模拟性能
- 想要提高模拟性能，使模拟低于1ms
	- 200-600模拟顶点，越多的顶点需要越多的迭代和子步，模拟顶点大于1000可以获得更好的模拟效果，但是肯定会超过1ms。
	- PS5平台：350个模拟顶点的情况（巫师4 Ciri 披风）
		- 1迭代次数，1子步数：0.3ms
		- 2迭代次数，2子步数：0.8ms
	- ![](./attachments/image.png)![179](./attachments/image-1.png)
	- mobile/switch平台：200顶点
		- 1迭代次数，1子步数：1ms
- SimulationSolverConfig节点
![](attachments/273dcaf2b65a54f5ac3db40a9d5ce889_MD5.jpg)
- subStep(子步数)和Iterations（迭代次数）	
	- subStep（子步数）是每帧计算布料状态的次数，增加该值可修复缺失身体碰撞，提高收敛性（抗拉伸，抗弯曲），降低阻尼。
	- Iterations（迭代次数）是在每个子步内计算约束和碰撞的次数，增加该值提高收敛性（效果较小但成本更低）
	- 他们共同作用来改善稳定性减少不真实拉伸，同时改善碰撞检测

![|600x667](attachments/7f878493329e6ac0dfa5f4ab454a36c4_MD5.jpg)

![|354x404](attachments/d215d51fce723350289269263d0be988_MD5.jpg)
- 加 NumSubsteps 和 NumIterations = 让约束求解更“彻底” → 约束被强制更好地遵守 → 布料的物理行为更接近“刚性约束” → 整体刚度感知上升（布料会更硬）→ 调整弯曲刚性和阻尼
- Substeps 成本 ≈ Iterations × 1.5～2 倍，所以通常优先堆 Iterations。
- NumSubsteps：3～6（太高吃性能，但稳定性好）
- NumIterations：8～16（最影响“硬度”感知）
- Max Num Iterations：20～30（防低帧率爆炸）

- 使用长距离附着时拓扑结构很重要，因为他是通过最短路径算法找到相应顶点的。

## Bending、Stretch和Mass

![](attachments/19b797fc6c3b4dd6562628131e846645_MD5.jpg)
- 抗弯曲能力
- 弯曲度和拉伸度都支持基于位置的动力学系统PBD,以及扩展版XPBD系统
	- XPBD结算器开销略高，但是不用开启更高的子步数和迭代数。他的数值更有物理意义（420， 200）N/Cm，而不是 0-1.可以将DCC软件（MarvelousDesigner）中创建的模拟数据（弯曲和拉伸属性）以USD格式导入。可以调整阻尼和各向异性
	- PBD结算器值域为 0-1。无法调整阻尼和各向异性。 受到子步数和迭代数的影响更大，越多的迭代，布料越硬。
- BendConfig有两种约束类型：
	- HingeAngle（铰链角度）最真实支持起皱和折叠，原理是在相邻三角面之间强制新的静止角度，并抵抗新静止状态的改变。物理精度更高，开销略大。适合硬质材料。在高强度拉伸下稳定性较差，需要配合AreaConstraint使用（角度约束）
	- FaceSpring（面弹簧）比铰链角度开销小，但物理精度较低，不支持起皱效果。更适合柔性材料。（弹簧约束）
	- ![228](attachments/ee87b511699dc56e09428357b98a21f7_MD5.jpg)
	- 有三个属性：
		- BendingStiffness：控制相邻三角面间的 弯曲抵抗力。高值=布料硬、直、不易折；低值=软、易弯曲/流动。
		- BucklingRatio：褶皱比率，决定布料从“正常弯曲”切换到“屈曲状态”的弯曲角度阈值。折到多大角度开始“啪”一下永久变形。
			- 切换阈值 = BucklingRatio × 静止角（rest angle）。
			- 0 = **从不 buckling**（布料永不塌陷，像硬板）。
			- 1 = **极易 buckling**（轻微弯曲就起皱）。 
			- 超过阈值后，自动从 BendingStiffness **切换到 BucklingStiffness**。
		- BucklingStiffness：褶皱刚度，仅在“buckling”触发后生效。用于压缩/过度弯曲时的 塌陷行为。通常设 低于 BendingStiffness（让褶皱“锁死”），模拟真实布料起皱/折叠。
		- 调整思路：
			- 先把 BendingStiffness 推到想要的“基础抗弯”水平。
			- 再调 BucklingRatio 决定“何时开始塌陷”。
			- 最后调 BucklingStiffness 决定“塌陷后多硬/多软”。
			- 高褶皱比与低褶皱刚度：柔软、飘逸、悬垂性好,有更多细小褶皱丝绸、人造纤维、针织布...
				- BendingStiffness：3.0
				- BucklingRatio：0.9
				- BucklingStiffness：0.5
			- 低褶皱比与高褶皱刚度：(通常仍低于弯曲刚度)更硬挺、更厚实、更脆、更有弹性皮革、羊毛...
				- BendingStiffness：3.0
				- BucklingRatio：0.4
				- BucklingStiffness：2.5

- StretchConfig是抗拉伸能力
	- StretchStiffness（拉伸刚度）：拉伸约束的强度
	- AreaStiffness（区域刚度）：区域刚度的强度
	- 这些数值非常敏感，微调就能产生很大效果
- Mass是质量配置。推荐使用密度

## SkinningBlend
- **`SkinningBlend`（蒙皮融合）节点**是一个非常核心的组件。它主要用于**处理布料的纯物理模拟状态（Dynamic）与骨骼动画蒙皮状态（Kinematic）之间的权重过渡**。
### 1. `SkinningBlend` 节点的核心功能

在Chaos Cloth的计算流中，顶点通常有两种运动模式：

- **Kinematic（运动学）**：完全由角色的Skeletal Mesh蒙皮权重（Skin Weights）计算出的动画位置。
- **Dynamic（动力学）**：由Chaos物理求解器计算出的自由落体、碰撞、随风飘动的位置。

`SkinningBlend` 节点的作用就是获取并计算这两者之间的混合比率。它会将读取到的蒙皮权重数据（或你通过Weight Map绘制的遮罩）映射到物理粒子上，告诉求解器：“哪些顶点应该像钢板一样跟着骨骼动，哪些顶点应该像丝绸一样飘，以及中间的平滑过渡”。

### 2. 节点的前置依赖项（关键点）

在Dataflow中连接此节点时，有一个容易卡住的坑：**它强依赖于 `ProxyDeformer`（代理变形器）节点的数据。**

- 根据Epic的官方规范，即使你没有明确定义复杂的变形器配对逻辑，输入到 `SkinningBlend` 节点的 `ClothCollection`（布料数据集合）上，也**必须提前存在ProxyDeformer的映射数据**。
- **为什么？** 因为Chaos解算通常在低模（Simulation Mesh/Proxy）上进行，而蒙皮动画是在高模（Render Mesh）上进行的。`ProxyDeformer` 建立了这两者顶点之间的包裹/绑定关系，`SkinningBlend` 必须依赖这层关系才能知道如何把蒙皮动画的位移传递给模拟顶点。

# Debug
- 开启布料DEBUG命令行：`p.Chaos.DebugDraw.Enabled 1`
- 绘制碰撞：`p.ChaosCloth.DebugDrawCollision 1`
- 绘制动画网格：`p.ChaosCloth.DebugDrawAnimMeshWired 1`
- 绘制传送重置：`p.ChaosCloth.DebugDrawTeleportReset 1`，如果传送，会显示绿色网格，如果重置绘制红色网格
- 是否在前景绘制：`p.ChaosClothVisualization.DrawInForeground 0`
- 控制播放速度：`t.OverrideFPS 60`
- 重置播放速度：`t.OverrideFPS -1`

# 过场动画
- 镜头开始前永远增加前置pose，使物理结算充分完整后再播放动画
- 时间栏中要对布料属性进行修改（Teleport、Reset...），建议使用EventTracks，在时间栏上剋帧可能不会被评估。
- Teleport/Reset
	- Teleport：效果没有损失。传送会消除任何外力,本质上是暂停当前姿势，然后在传送后以相同姿势恢复。这在大多数情况下都应该有效。不会造成损失。
	- Reset：效果更具戏剧性。重置将根据动画网格姿势重新启动您的模拟。对于动画姿势的重大差异,请使用此功能。请确保您的动画网格姿势良好。
	- 仍然无法正常结算：全局阻尼，创建一个函数，将全局阻尼提升至1，然后逐渐降至0。这本质上是传送,只是有更多的控制。这样做完全合理。
