### 2.5 为什么 Epic 不做织物库：设计取向

`FCollectionClothFabricFacade`（同一个头文件）让**每个 sim pattern 绑定一个 fabric 索引**，
每个 fabric 携带 12 个属性，其中 Bending / Buckling / Stretch Stiffness 都是
`FAnisotropicData{Weft, Warp, Bias}` 三向结构。填充它的代码路径在
`ChaosClothAssetUsdDataflowNodes/.../USDImportNode_v3.cpp`（`Fabric.Initialize(...)`
出现在 940、1361、2382 行）。

也就是说：**Epic 的意图是你在 Marvelous Designer / CLO3D 里用它们的织物库
（那里有几百种实测织物），连同 pattern 一起走 USD 导入，fabric 参数自动落到
ClothCollection 上**。UE 侧不重复维护一份织物库 —— preset 在上游 DCC 里。

附带好处：这条路径支持一件衣服上多种织物（主体棉 + 领口罗纹 + 皮革贴边），
每个 pattern 各自的 fabric，这是手填 Config 节点做不到的。

## 三、动手前必须搞清楚的两个尺度问题

### 3.1 Isotropic 与 Anisotropic 是两套数量级

`SimulationStretchConfigNode` / `SimulationBendingConfigNode` 里，同一概念在两种
`DistributionType` 下默认值差 100 倍，且被 `EditCondition` 互斥隐藏 —— UI 上只会显示其中一套。

| 属性 | Isotropic（XPBD） | Anisotropic（仅 XPBD） |
| --- | --- | --- |
| StretchStiffness | 默认 **1.0**，UIMax 10000，ClampMax 1e9 | Warp/Weft/Bias 各默认 **100** |
| BendingStiffness | 默认 **1.0**，UIMax 10000，ClampMax 1e7 | Warp/Weft/Bias 各默认 **100** |
| BucklingStiffness | 默认 **0.9**，**UIMax 仅 10**，ClampMax 1000 | Warp/Weft/Bias 各默认 **50** |
| BucklingRatio | 默认 0.5，ClampMax 1.0 | `AnisoBucklingRatio` 默认 0.5 |
| Damping | 默认 1.0，UIMax 10 | `*AnisoDamping` 默认 1.0 |

回看幻灯片三列：`BendingStiffness 1/5/20` 与 `BucklingStiffness 0.2/1/15` 明确落在
**Isotropic** 尺度（相对默认 1.0 和 0.9 的合理倍数）；`StretchStiffness 1000/600/400`
虽然数值大，但 Isotropic 分支的 UIMax 就是 10000、ClampMax 1e9，**完全合法**。

**所以幻灯片那张表是一套自洽的 Isotropic XPBD 参数**，本篇织物库沿用同一尺度，
目标配置固定为：

```
SolverType       = XPBD
DistributionType = Isotropic
ConstraintType   = HingeAngles     ← BucklingStiffness/Ratio 仅在此类型下可见
MassMode         = Density
```

> 若要用 Anisotropic（唯一能调 Bias 抗剪的路），把 Bending/Buckling 整体乘 100 量级，
> Stretch 保持不变即可迁移。

### 3.2 BucklingRatio 的真实语义（容易理解反）

源码实现 `PBDBendingConstraintsBase.h:277-282`：

```cpp
bool AngleIsBuckled(const FSolverReal Angle, const FSolverReal RestAngle) const
{
    // Angle is 0 when completely flat. ... Angle' = (PI - |Angle|), which is 0 when completely folded.
    // Consider buckled when Angle' <= BucklingRatio * RestAngle'
    return UE_PI - FMath::Abs(Angle) < (FSolverReal)BucklingRatioWeighted * (UE_PI - FMath::Abs(RestAngle));
}
```

注意 `Angle' = PI - |Angle|`：**完全摊平时 Angle'= PI，完全对折时 Angle'= 0**。
判据是 `Angle' < Ratio × RestAngle'`，即"折到某个程度以下"才算 buckled。所以：

- **Ratio 越大 → 越容易/越早进入 buckled** → 用 BucklingStiffness 的时间更长 → 褶多而细
- Ratio = 0 → **永不 buckle**，全程用 BendingStiffness
- Ratio = 1 → 一离开静止角就 buckle

这与 [2.0-Chaos Cloth](2.0-Chaos%20Cloth.md) 里"高褶皱比 = 柔软飘逸细褶、低褶皱比 = 硬挺粗褶"
的记法一致。**留折痕的料（亚麻、纸）要高 Ratio + 极低 BucklingStiffness**
（早早切换到几乎没有刚度的分支，折痕就留住了）；**不留折痕的料（呢子、潜水料）
要低 Ratio + 高 BucklingStiffness**（很晚才切换，且切换后仍硬，弹回来）。

另外源码注释明确：`Typically, Buckling Stiffness is set to be less than Bending Stiffness.`
本篇 30 种织物全部满足这一条（校验脚本会检查）。

## 六、校准流程（把推理值变成可信值）

**这一章比上面的表更重要。** 四个标准测试场景，做成一个 Level 一次全测完，
比在角色身上瞎调快十倍。前两个直接对应纺织业标准测试，可以拿实物拍照对齐。

| # | 测试 | 做法 | 校准目标 | 判据 |
| --- | --- | --- | --- | --- |
| 1 | **悬臂测试** | 30×5 cm 布条，一端 kinematic 水平固定伸出，静置后测末端下垂长度 | BendingStiffness | 对应纺织业 cantilever bending length 标准测试，可与实物照片对齐 |
| 2 | **Cusick 垂坠测试** | 直径 30 cm 圆布放在直径 18 cm 圆盘上，俯视截图算投影面积比 | 抗剪 / Bias（需 Anisotropic） | drape coefficient：真丝≈0.2、棉平纹≈0.45、帆布≈0.85 |
| 3 | **垂挂伸长测试** | 1 m 布条顶边固定，静置后测长度 | StretchStiffness / Tether | 梭织 ≤2%、针织 5–15%、甲类 ≤0.5%。超了先加 Tether，别先动 k |
| 4 | **对折回弹测试** | 对折压住 30 帧后释放，看回弹幅度与残留折痕 | BucklingStiffness / Ratio | 亚麻/纸应留痕；呢子/潜水料应弹平 |

### 6.1 XPBD 的关键性质：刚度与帧率、substep 无关

这正是 XPBD 相对 legacy PBD 的意义 —— 上表数值跨帧率可移植，不会因为改了 substep
就全部失效。但 `k > 2000` 时低 substep 仍会欠收敛，甲类和欧根纱记得把 SubStep 提到 3–5。

XPBD 刚度上限（源码 `XPBDBendingConstraints.h:19`、`XPBDStretchBiasElementConstraints.h:25`）：
`MaxStiffness = 1e7`；弹簧类 `XPBDSpringConstraints.h:19` 是 `1e9`。超过会被 clamp。

### 6.2 Density 与 StretchStiffness 在 XPBD 里是耦合的

XPBD 约束修正量 `~ C / (∇C·M⁻¹·∇C + 1/(kΔt²))`，质量在分母里真实参与 ——
同一 `k` 下密度翻倍，重力下伸长率就翻倍。所以要看 **k/ρ 比值**，不能单看 k。

幻灯片三列的 k/ρ 是 10000 / 3000 / 667，也就是说**越重的料越会被拉长**。
梭织区间无所谓（有 MaxDistance 和骨骼约束兜着），但针织和甲类要注意：

- 校验脚本对 `k/ρ < 1200` 的织物会告警，本库有 10 种命中（针织类 + 重革类 + 甲类）
- 处理办法：**把 `TetherStiffness` 设为 1.0**（LongRangeAttachment），
  抗重力拉伸靠 tether 才是正解，硬堆 k 会逼你加 substep
- ρ > 0.8 的甲类另按 `k ≥ 4000 × ρ` 给（本库锁子甲 8000 / 鳞甲 9000 即由此而来）

### 6.3 抗剪（Bias）是本表覆盖不到的维度

**面料垂坠感的差异约六成来自 Bias（剪切）而不是弯曲**，而 Isotropic 模式没有 Bias。
需要精细垂坠时切到 Anisotropic，三向倍率（乘在上表基准值上）建议：

| 织物结构 | Warp | Weft | Bias | 说明 |
| --- | ---: | ---: | ---: | --- |
| 平纹梭织（丝、棉、麻） | 1.0 | 1.0 | 0.6 | 通用起点 |
| 斜裁真丝 Bias-cut | 1.0 | 1.0 | **0.15** | 液态垂坠的秘密 |
| 斜纹 / 牛仔 | 1.0 | 0.7 | 0.35 | 纬向更软，斜向易剪 |
| 汗布 Jersey | 1.0 | **0.4** | 0.5 | 横列方向拉伸远大 |
| 罗纹 Rib | 1.0 | **0.15** | 0.5 | 纬向极弹 |
| 皮革 / 无纺 / 潜水料 | 1.0 | 1.0 | **0.9** | 各向同性、抗剪 |
| 欧根纱 / 塔夫绸 | 1.0 | 1.0 | 0.8 | 硬挺抗剪，所以褶大而少 |

只有第 2 项 Cusick 垂坠测试能暴露 Bias 调错。

## 七、脚本用法

三个文件都在同目录 `scripts/` 下。

### 7.1 build_library.py — 生成并校验织物库

纯标准库，编辑器外直接跑。三步输出：验证密度映射 → 生成 30 种 → 按引擎
`UPROPERTY` meta 的 ClampMin/Max、UIMin/Max 逐项校验。

```bash
cd Notes/Unreal/布料/scripts
python build_library.py
```

实测输出（2026-08，UE 5.8）：**ERROR 0 项，WARN 16 项**，退出码 0。
16 条告警分两类，都是"合法但需注意"：

- **10 条 k/ρ 偏低**（针织类、重革类、甲类）→ 按 6.2 加 Tether
- **6 条超 UIMax**（4 个 BucklingStiffness > 10、2 个甲类 Density > 1.0）
  → 滑条拖不到，**在 UI 里手动键入数值即可**，ClampMax 分别是 1000 和无上限

改织物参数就编辑 `FABRICS` 列表里的元组，重跑即可。

### 7.2 apply_fabric_ue.py — 在编辑器内套用

**必须在 UE 编辑器内运行**（Output Log 的 Cmd 切到 Python，或 Tools > Execute Python Script）。
走 `UChaosClothAssetInteractor` 的 Set 接口，API 签名核实自
`ClothAssetInteractor.h:155-203`：

```python
SetFloatValue(PropertyName, LODIndex=-1, Value=0.0)
SetWeightedFloatValue(PropertyName, LODIndex=-1, Value=FVector2D(low, high))
```

`PropertyName` 用的是源码里 `UPROPERTY(..., InteractorName="...")` 的值，脚本里
`FIELD_TO_INTERACTOR` 已逐个核对。`LODIndex = -1` 表示套用到全部 LOD。

```python
import apply_fabric_ue as af
af.list_fabrics()                                   # 列出 30 种可选
af.apply_fabric(my_cloth_component, "Denim 12oz 牛仔")
af.apply_to_selected("Melton Wool 麦尔登呢")          # 套到选中 Actor 的布料组件
af.apply_fabric(None, "Linen 亚麻", dry_run=True)     # 只打印不执行
```

**两个限制必须知道：**

1. **Interactor 只改运行时模拟参数，不写回 Dataflow 图，不落盘。** 要持久化就在
   Dataflow 的 Config 节点上按第四章表格手填。5.8 没有暴露稳定的 Dataflow
   节点属性 Python API，程序化落盘需要 C++。
2. **`NumSubsteps` 和网格边长这两项 Interactor 管不到** —— 前者在
   SolverConfig 节点，后者在建模阶段决定。脚本会在末尾提示建议值。

`dry_run=True` 时不需要 `unreal` 模块，可在编辑器外验证逻辑。脚本 `__main__`
自检已实测通过（加载 30 种 + Denim 12 个属性 dry-run 输出正常）。

> **状态说明**：`apply_fabric` 的实际 Set 调用路径**尚未在编辑器内实测**（撰写时无可用工程）。
> API 签名与属性名均从 5.8 源码逐字核对，但首次执行请先 `dry_run=True` 观察输出。
> 若 `get_cloth_asset_interactor` 方法名不对，在 Output Log 里 `dir(your_component)`
> 查实际名字并补进脚本的 getter 列表。
