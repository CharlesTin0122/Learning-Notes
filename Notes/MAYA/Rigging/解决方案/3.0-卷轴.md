# 1
- I can think of two ways I might approach this.
- 我能想到两种可能的处理方式。

1. There is a trick you can you use with lattices. If you scale some segments to zero, and set the FFD to “All”, you can make a lattice that “eats” geometry as you move it through it. You could set this up before the bending deformation as a way to fake scroll it away.有个关于格点的技巧可以用。如果你将某些段缩放到零，并将FFD设置为“全部”，你可以创建一个晶格，随着几何体的移动而“吞噬”它。你可以在弯曲变形前设置这个，作为假滚动的方式。

And to be game-engine friendly, you could add this effect to a ribbon IK, which carries some follicles and bones, which then deforms a polygon asset. The lattice would just scale the ribbon, and you could bake down the bone results.
为了更友好于游戏引擎，你可以把这个效果加到带有毛囊和骨骼的带状IK上，然后变形多边形资产。格子只是放大丝带，然后你可以烘焙骨骼结果。

![scroll_retract](http://forum.mgear-framework.com/uploads/default/original/2X/f/fc56d54871423a3adfa6e6be17d56d1579d43621.gif)

2. And I think this would be an easier approach, where the ribbon always stays extended, so it is intuitive and easy to animate:我觉得这样会更简单，色带始终保持伸展状态，直观且易于动画化：

Again, using follicles, you could set up a driven key (or whatever) that animates some follicles sliding along the surface, scaling it to zero. The ribbon IK itself wouldn’t scale at all, but the geometry would slide along it. Again, bake out the joints, and it is game-engine ready.
同样，利用毛囊，你可以设置一个驱动键（或其他类似工具），让一些毛囊在表面滑动，并将其缩放到零。丝带IK本身不会缩放，但几何体会沿着它滑动。同样，烘焙关节，游戏引擎就准备好了。
