在 Maya 绑定（rigging）中，最影响**视口实时性能**（playback FPS、拖动控制器时的响应速度）的因素，按严重程度从高到低大致可以排成下面这个顺序（基于 2024–2026 年社区、Autodesk 官方、Rigging Dojo / mGear / Polycount 等实际案例总结）：

| 排名 | 因素                          | 影响程度（大致倍率） | 为什么特别吃性能                                      | 常见优化/规避方式                              |
|------|-------------------------------|----------------------|-------------------------------------------------------|------------------------------------------------|
| 1    | **Expression（表达式）**      | ★★★★★ (最重)        | 每帧强制计算，DG 模式下串行阻塞，非常容易成为瓶颈     | 用 setDrivenKey / utility nodes / nodes 替换；尽量少用或拆分成轻量版 |
| 2    | **太多/复杂的 Deformers**     | ★★★★☆               | blendShape（尤其是 corrective + inbetween 多层）、wrap、lattice、wire、nonlinear 等叠加 | 减少层级；用 parallel blendShape；把 corrective blend 放到 cached 层后 |
| 3    | **Smooth Mesh Preview** (细分预览) | ★★★★☆               | 实时 Catmull-Clark 细分计算特别吃 CPU，尤其高面数模型 | 关掉（Display Level=0）；只在 render 时开；用 proxy mesh 动画 |
| 4    | **大量 Constraints**          | ★★★★                | parent/aim/scale/point/orient + maintain offset 叠加多时，计算链变长 | 用 direct connection 或 SDK 替换部分 constraint；减少 maintain offset |
| 5    | **Follicle + hair/fur systems** | ★★★★                | follicle 计算曲线/表面投影特别重，尤其多个绑定在 mesh 上 | 减少 follicle 数量；动画时隐藏/禁用；用 proxy 曲线 |
| 6    | **SDK / Set Driven Key 数量过多** | ★★★                 | 数量上千时会累积开销（虽比 expression 轻）            | 精简驱动关系；用 driven keys 的 driven keys 嵌套要小心 |
| 7    | **Utility nodes 链过长**      | ★★★                 | multiplyDivide / plusMinusAverage / condition 等串很多层 | 合并节点；用单个 node 做多运算 |
| 8    | **高面数 bind mesh**          | ★★☆                 | 蒙皮 + deform 计算基数大                              | 用低面 proxy 做绑定/动画，最终 mesh reference 或 blend |
| 9    | **nCloth / nHair / Bifrost 等模拟节点** | ★★☆–★★★★           | 即使没 bake，也会每帧尝试计算                        | 动画时完全删除或 disable；用 cached/nCache |
| 10   | **没开 Cached Playback / Evaluation Cache** | ★★★★ (间接)         | 现代 Maya 最重要救命稻草，没开等于自废武功            | 必须开！（尤其是 2019+ 版本）                  |

### 快速排序口诀（最吃性能的前四杀手）
**Expression > Heavy Deformers + Smooth Mesh > Constraints + Follicles > 没开 Cached Playback**

### 实际诊断建议（强烈推荐）
1. **先用 Profiler**（Window → General Editors → Profiler）
   - Category → DG Evaluation / Deform / Draw
   - 录制一小段拖拽控制器或播放，找红色/黄色条最长的 node
   - 通常前三名就是真凶手

2. **Hypergraph / Node Editor** 里搜：
   - expression
   - blendShape
   - follicle
   - wrap / lattice
   - 看它们下游连接了多少 mesh / 输出

3. **最常见“瞬间救命”组合**（很多人做了这几步 FPS 直接翻倍甚至更多）：
   - 打开 Cached Playback（时间轴右下闪电）
   - Evaluation Mode → Parallel
   - 所有 mesh Smooth Mesh → 0（或关掉 Display）
   - 把 facial blendShapes / corrective 层 放到 post-deform cached
   - 动画阶段把不必要的 deformers / expressions disable
