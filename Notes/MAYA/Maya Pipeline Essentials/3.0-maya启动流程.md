● Maya 软件启动工作流程

  作为 TA,理解 Maya
  的启动顺序非常关键——这决定了你的环境变量、插件、自定义脚本和工具会在哪个时机被加载。下面按完整的启动链路梳理。

  ---
  一、整体启动阶段概览

  启动可执行文件 (maya.exe)
     ↓
  1. 读取环境变量 (系统级 / Maya.env)
     ↓
  2. 初始化核心模块 & 解析模块路径 (modules)
     ↓
  3. 加载插件 (自动加载列表 + 模块插件)
     ↓
  4. 初始化 Python/MEL 解释器,扫描脚本路径
     ↓
  5. 执行 userSetup.mel / userSetup.py
     ↓
  6. 构建 UI (主窗口、菜单、Shelf、工具架)
     ↓
  7. 进入主事件循环 (Idle, 等待用户操作)

  ---
  二、各阶段详解

  8. 环境变量加载

  Maya 启动时首先确定一系列关键环境变量,决定后续所有路径的解析:

| 变量                | 作用                          |
| ----------------- | --------------------------- |
| MAYA_APP_DIR      | 用户首选项根目录(默认 Documents/maya) |
| MAYA_MODULE_PATH  | 模块(.mod)搜索路径                |
| MAYA_PLUG_IN_PATH | 插件搜索路径                      |
| MAYA_SCRIPT_PATH  | MEL/Python 脚本搜索路径           |
| PYTHONPATH        | Python 模块搜索路径               |
| XBMLANGPATH       | 图标(Shelf/按钮图标)搜索路径          |
| MAYA_PRESET_PATH  | 预设搜索路径                      |

  Maya.env 文件(位于 MAYA_APP_DIR/<版本号>/Maya.env)在此阶段被解析,可以在这里追加自定义路径,例如:

  MAYA_MODULE_PATH = D:/MyTools/modules
  PYTHONPATH = D:/MyTools/python
  MAYA_PLUG_IN_PATH = D:/MyTools/plugins

  ▎ ⚠️ 注意:Maya.env 里的变量不会自动继承系统已有值,如果要追加而非覆盖,Windows 下需写成 MAYA_MODULE_PATH =%MAYA_MODULE_PATH%;D:/MyTools/modules。

  ---
  9. 模块(Module)解析

  Maya 扫描 MAYA_MODULE_PATH 下的所有 .mod 文件。模块是 TA 部署工具的首选方式,因为它能一次性声明插件、脚本、图标、Python
  包路径,且与版本/平台解耦。

  一个典型 .mod 文件:

  + MyRigTool 1.0 D:/MyTools/MyRigTool
  PYTHONPATH +:= scripts
  MAYA_PLUG_IN_PATH +:= plug-ins
  XBMLANGPATH +:= icons

  模块解析后,其中声明的路径会被合并进对应的环境变量,供后续插件/脚本加载使用。

  ---
  3. 插件(Plug-in)加载

  - Maya 读取首选项中的自动加载插件列表(存储在 pluginPrefs.mel)。
  - 按需加载 .mll(C++)/ .py(Python 插件)等。
  - 模块声明的插件路径也在此参与查找。

  插件加载发生在 userSetup 之前,所以如果你的 userSetup.py
  依赖某个自定义节点/命令插件,要确保该插件在自动加载列表里,或在脚本里显式 cmds.loadPlugin()。

  ---
  4. 脚本解释器初始化 & 路径扫描

  Maya 初始化 MEL 和 Python 环境,并将 MAYA_SCRIPT_PATH / PYTHONPATH 注册到搜索路径中。此时你的自定义 Python 包已经可以
  import。

  ---
  5. userSetup 执行(TA 的核心入口)

  这是技术美术注入自定义逻辑的关键时机:

| 文件            | 语言     | 说明                                  |
| ------------- | ------ | ----------------------------------- |
| userSetup.mel | MEL    | 先于 Python 执行                        |
| userSetup.py  | Python | Maya 会自动 import(注意是 import,不是 exec) |

  重要陷阱:userSetup.py 执行时 UI 尚未完全构建完成。直接在顶层创建窗口、添加 Shelf
  按钮往往会失败或时机错乱。正确做法是用 executeDeferred / evalDeferred 把 UI 操作延迟到主循环空闲时:

  # userSetup.py
  import maya.cmds as cmds
  import maya.utils as utils

  def _setup_tools():
      """Maya UI 就绪后再构建自定义工具菜单。"""
      if not cmds.about(batch=True):  # 非批处理模式才建 UI
          import my_rig_tools.menu
          my_rig_tools.menu.build()

  # 延迟到 Maya 空闲时执行,避免 UI 未就绪
  utils.executeDeferred(_setup_tools)

  ▎ 说明:maya.utils.executeDeferred 比裸 evalDeferred 更安全,能正确处理批处理模式与异常。批处理(mayabatch/mayapy
  ▎ -batch)下应跳过 UI 构建。

  ---
  6. UI 构建

  主窗口、菜单栏、状态栏、工具架(Shelf)、通道盒等被构建。Shelf 从 MAYA_APP_DIR/<版本>/prefs/shelves/ 加载,图标从
  XBMLANGPATH 查找。

  ---
  7. 进入主事件循环

  Maya 进入 idle 状态,开始响应用户输入。此时所有 executeDeferred 排队的回调依次执行。

  ---
  三、TA 视角的部署建议

  1. 优先用 Module(.mod)部署工具,而不是直接改用户的 Maya.env 或
  userSetup.py——模块可热插拔、易于版本管理、不污染用户首选项。
  2. userSetup.py 保持轻量,只做"挂载入口"(注册菜单/回调),不要在里面跑重逻辑,否则拖慢启动并难以排错。
  3. UI 操作一律 executeDeferred,并判断 cmds.about(batch=True) 跳过批处理。
  4. 加 try-except 与日志,防止单个工具初始化失败导致整个 userSetup 中断(一旦 import 报错,后面的代码都不会执行):

  import logging
  logger = logging.getLogger("startup")

  def _safe_init():
      for name, fn in [("rig_menu", build_rig_menu), ("shelf", build_shelf)]:
          try:
              fn()
          except Exception:
              logger.exception("启动工具初始化失败: %s", name)

  5. 多版本共存:不同 Maya 版本的首选项目录(2024/2025 等)互相独立,模块用 1.0 版本号字段或 MAYA_VERSION 条件区分。
