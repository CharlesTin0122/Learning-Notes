[Qt.py](https://github.com/mottosso/Qt.py)

Qt.py 是一个 Python 模块，是由[mottosso](https://github.com/mottosso)（光头佬👨‍🦲）编写的，旨在为 Python 开发者提供一种一致的方式来使用 Qt 框架（PyQt 或 PySide）开发图形用户界面（GUI）应用程序。它通过动态选择可用的 Qt 绑定（PySide6、PyQt6、PySide2 或 PyQt5）来简化跨不同 Qt 绑定的兼容性问题，开发者无需为特定的 Qt 绑定（如 PyQt5 或 PySide6）重写代码。以下是对 Qt.py 模块的详细介绍及其用法。

---

### **1. Qt.py 模块简介**
- **作用**：Qt.py 是一个轻量级兼容层，允许开发者编写与 PyQt 和 PySide 兼容的代码。它通过统一的 API 调用底层 Qt 绑定，减少因不同绑定（PyQt 和 PySide）之间的 API 差异而带来的麻烦。
- **支持的绑定**：Qt.py 会自动检测并优先选择以下绑定（按优先级顺序）：
  1. PySide6
  2. PyQt6
  3. PySide2
  4. PyQt5
- **特点**：
  - 跨绑定兼容性：开发者无需为不同 Qt 绑定调整代码。
  - 自动选择可用绑定：根据环境中安装的模块动态加载。
  - 轻量：Qt.py 本身不包含 Qt 的功能，仅作为绑定选择器和兼容层。
  - 开源：基于 MIT 许可证，适合个人和商业项目。
- **适用场景**：
  - 开发跨平台的 GUI 应用程序。
  - 需要在不同环境中运行代码，且不确定目标环境中安装了哪种 Qt 绑定。
  - 希望简化 PyQt 和 PySide 之间的迁移或兼容性管理。

---

### **2. 安装 Qt.py**
要使用 Qt.py，需要先安装 Qt.py 模块以及至少一个支持的 Qt 绑定（PySide6、PyQt6、PySide2 或 PyQt5）。可以通过 pip 安装 Qt.py：

```bash
pip install Qt.py
```

然后安装一个 Qt 绑定，例如 PySide6：

```bash
pip install PySide6
```

或 PyQt6：

```bash
pip install PyQt6
```

Qt.py 会自动检测环境中安装的绑定，无需手动指定。

---

### **3. Qt.py 的基本用法**
Qt.py 的核心思想是让开发者以一致的方式调用 Qt 的功能，而无需关心底层绑定是 PyQt 还是 PySide。以下是一个简单的示例，展示如何使用 Qt.py 创建一个基本的 GUI 窗口：

#### **示例代码：创建简单窗口**
```python
import sys
from Qt import QtWidgets, QtCore

# 创建应用程序
app = QtWidgets.QApplication(sys.argv)

# 创建主窗口
window = QtWidgets.QMainWindow()
window.setWindowTitle("Qt.py 示例窗口")
window.resize(400, 300)

# 创建一个标签
label = QtWidgets.QLabel("Hello, Qt.py!", window)
label.setAlignment(QtCore.Qt.AlignCenter)
label.resize(200, 50)
label.move(100, 100)

# 显示窗口
window.show()

# 运行应用程序
sys.exit(app.exec_())
```

**说明**：
- **导入 Qt 模块**：通过 `from Qt import QtWidgets, QtCore` 导入 Qt.py 提供的模块，而不是直接从 PyQt6 或 PySide6 导入。
- **兼容性**：代码在 PySide6、PyQt6、PySide2 或 PyQt5 环境下均可运行，Qt.py 会自动选择可用的绑定。
- **执行逻辑**：创建一个简单的窗口，包含一个居中的标签，显示 "Hello, Qt.py!"。

运行以上代码时，Qt.py 会检查环境中可用的 Qt 绑定，并动态加载相应的模块。

### **4. Qt.py 的核心功能**
Qt.py 提供了一些特性来简化开发：

1. **统一的命名空间**：
   - Qt.py 将 PyQt 和 PySide 的模块统一到 `Qt` 命名空间下。例如，`QtWidgets.QApplication` 替代 `PySide6.QtWidgets.QApplication` 或 `PyQt6.QtWidgets.QApplication`。
   - 这消除了不同绑定间 API 名称的差异（如 `exec_` vs `exec`）。

2. **自动绑定选择**：
   - Qt.py 按优先级加载绑定（PySide6 > PyQt6 > PySide2 > PyQt5）。
   - 如果环境中安装了多个绑定，可以通过环境变量 `QT_API` 强制指定，例如：
     ```bash
     export QT_API=pyside6
     ```

3. **兼容性修复**：
   - Qt.py 修复了 PyQt 和 PySide 之间的一些细微差异，例如信号/槽机制、枚举值处理等。
   - 例如，PyQt5 使用 `QtCore.Qt.AlignCenter`，而 PySide2 使用 `QtCore.Qt.AlignmentFlag.AlignCenter`，Qt.py 统一了这些调用。

4. **模块映射**：
   - Qt.py 提供了模块别名，确保开发者使用一致的模块名称。例如，`QtGui`、`QtCore` 等模块名称在所有绑定中保持一致。

### **5. 兼容性**

Qt.py 还为不同绑定的关键功能提供了兼容性包装器，这些可以在添加的 `QtCompat` 子模块中找到。

| Attribute 属性                                                          | Returns 返回 | Description 描述                                                                                                         |
| :-------------------------------------------------------------------- | :--------- | :--------------------------------------------------------------------------------------------------------------------- |
| `loadUi(uifile=str, baseinstance=QWidget)`                            | `QObject`  | PyQt4.loadUi 和 PySide 等效物的最小包装器                                                                                        |
| `translate(...)`                                                      | `function` | [QCoreApplication.translate](https://doc.qt.io/qt-5/qcoreapplication.html#translate)QCoreApplication.translate 的兼容性包装器 |
| `wrapInstance(addr=long, type=QObject)`                               | `QObject`  | 包装器为 `shiboken2.wrapInstance` 和 PyQt 等效项。                                                                              |
| `getCppPointer(object=QObject)`                                       | `long`     | 包装器为 `shiboken2.getCppPointer` 和 PyQt 等效项。                                                                             |
| `isValid(object=QObject)`                                             | `bool`     | 包装器为 `shiboken2.isValid` 和 PyQt 等效项。                                                                                   |
| `dataChanged(topLeft=QModelIndex, bottomRight=QModelIndex, roles=[])` | `None`     | 包装 `QtCore.QAbstractItemModel.dataChanged.emit`                                                                        |

**Example **

```python
>>> from Qt import QtCompat
>>> QtCompat.loadUi
```
在 Qt4 和 Qt5 之间，有许多类和类成员已经过时了。在 Qt.QtCompat 下，有许多类的名称与它们提供的兼容函数类相匹配。这些将与 PySide2 命名约定匹配。
```python
from Qt import QtCore, QtWidgets, QtCompat
header = QtWidgets.QHeaderView(QtCore.Qt.Horizontal)
QtCompat.QHeaderView.setSectionsMovable(header, False)
movable = QtCompat.QHeaderView.sectionsMovable(header)
```

### **6. Qt.py 的局限性**
- **依赖底层绑定**：Qt.py 本身不提供 GUI 功能，必须安装 PySide 或 PyQt。
- **性能开销**：由于动态绑定选择，可能会引入微小的性能开销（通常可忽略）。
- **不完全兼容**：虽然 Qt.py 解决了大部分兼容性问题，但某些高级功能或绑定特有的 API 可能仍需单独处理。
- **调试复杂性**：如果环境中安装了多个绑定，可能需要通过环境变量明确指定以避免冲突。

### **7. 常见问题与解决方案**
1. **如何指定特定的 Qt 绑定？**
   设置环境变量 `QT_API`，例如：
   ```bash
   export QT_API=pyqt6
   ```
   或在代码中设置：
   ```python
   import os
   os.environ["QT_API"] = "pyqt6"
   ```

2. **如何检查当前使用的绑定？**
   ```python
   from Qt import __binding__
   print(__binding__)  # 输出当前使用的绑定，例如 "PySide6"
   ```

3. **Qt.py 是否支持 Qt Designer？**
- Qt.py 本身不直接与 Qt Designer 交互，但可以通过 PyQt 或 PySide 的工具（如 `pyside6-uic` 或 `pyuic6`）将 `.ui` 文件转换为 Python 代码，并与 Qt.py 结合使用。
- 通过 `pyside2-uic` 编译的 `.ui` 文件本质上包含 PySide2 的痕迹 - 例如行 `from PySide2 import QtGui` ..
- 为了将它们与 Qt.py 或任何其他绑定一起使用，必须首先擦除此类跟踪并用交叉兼容的代码替换它们。
```
$ pyside2-uic my_ui.ui -o my_ui.py
$ python -m Qt --convert my_ui.py
# Creating "my_ui_backup.py"..
# Successfully converted "my_ui.py"
```
- 现在您可以像往常一样使用该文件，Qt.py
- PyQt4 和 PyQt5 的 `uic.loadUi` 函数以及 PySide/PySide2 的 `QtUiTools.QUiLoader().load` 函数映射到便利函数 `loadUi` .。
```python
import sys
from Qt import QtCompat, QtWidgets

app = QtWidgets.QApplication(sys.argv)
ui = QtCompat.loadUi(uifile="my.ui")
ui.show()
QtCompat.QApplication.exec_()
```

`loadUi` 有两个参数，而不是 PyQt 附带的倍数。有关详细信息，请参阅此处 - 简而言之，PyQt 和 PySide 之间的这些参数以不兼容的方式有所不同。第二个参数是 `baseinstance`，它允许将 ui 动态加载到现有的 QWidget 实例上。`uifile` 是要加载的 UI 文件的字符串路径。
```python
QtCompat.loadUi(uifile="my.ui", baseinstance=QtWidgets.QWidget)
```

如果 `baseinstance` 是 `None` ，则将创建顶级小组件的新实例。否则，用户界面将在给定的 `baseinstance` 中创建。在这种情况下，`baseinstance` 必须是要加载的 UI 文件中顶级小部件类的实例或其子类。换句话说，如果您在设计器中创建了 `QMainWindow` 接口，则 `baseinstance` 也必须是 `QMainWindow` 或其子类。您无法将普通 `QWidget` 的 `QMainWindow` UI 文件加载为 `baseinstance` .。

如果提供了 `baseinstance`，则 `loadUi` 返回 `baseinstance`。否则，它将返回新创建的用户界面实例。
