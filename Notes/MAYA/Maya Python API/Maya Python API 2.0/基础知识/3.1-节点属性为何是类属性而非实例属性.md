在 Autodesk Maya 的 Python API 2.0（`maya.api.OpenMaya`）中，编写自定义节点类（`MPxNode` 的子类）时，节点的属性（如通过 `MFnAttribute` 创建的属性）通常定义为**类属性**（class attributes），而不是**实例属性**（instance attributes）。你的疑问非常合理：既然一个 Maya 场景中可以创建多个节点实例，每个实例需要独立的属性值，为什么不将属性定义为实例属性？答案在于 Maya 依赖图（Dependency Graph）的架构设计以及 `MPxNode` 的工作方式。以下是对这个问题的详细解释，包括设计原因、实现机制、属性存储原理以及为什么类属性是更合适的选择。

---

### 1. **为什么节点属性定义为类属性？**

#### **1.1 Maya 依赖图的属性定义机制**
- **属性是节点类型的元数据**：
  - 在 Maya 中，节点属性（如 `translateX`、`radius`）是节点类型（node type）的元数据，而不是单个节点实例的数据。属性定义了节点类型的结构（例如有哪些输入/输出属性、它们的类型和默认值），而每个节点实例存储这些属性的具体值。
  - 类属性用于定义节点的“模板”或“蓝图”，包括属性的名称、类型、默认值和连接规则。这些元数据在节点类型注册时由 Maya 的依赖图系统管理。
  - 示例：对于 `transform` 节点，`translateX` 是一个属性，定义在节点类型级别，所有 `transform` 节点实例共享这个属性定义，但每个实例有自己的 `translateX` 值。

- **类属性定义节点结构**：
  - 在 `MPxNode` 的子类中，属性通过 `MFnAttribute` 创建并存储为类属性（`classmethod` 或静态变量），以便在节点类型注册时传递给 Maya。
  - 这些类属性在 `initialize` 方法中配置，并通过 `MFnPlugin.registerNode` 注册到 Maya。
  - 示例：
    ```python
    class CustomNode(om.MPxNode):
        node_id = om.MTypeId(0x80000)
        input_attr = om.MObject()  # 类属性

        @staticmethod
        def initialize():
            n_attr = om.MFnNumericAttribute()
            CustomNode.input_attr = n_attr.create("input", "in", om.MFnNumericData.kFloat, 0.0)
            CustomNode.addAttribute(CustomNode.input_attr)
    ```

- **实例属性值的存储**：
  - 虽然属性定义是类级别的，但每个节点实例的属性值存储在 Maya 的依赖图中，由 `MDataBlock` 管理。每个节点实例有自己的数据块，保存独立的属性值。
  - 因此，尽管 `input_attr` 是类属性，Maya 确保每个节点实例（如 `customNode1` 和 `customNode2`）的 `input` 属性值是独立的。

#### **1.2 性能和一致性**
- **性能优化**：
  - 定义属性为类属性避免了在每个节点实例创建时重复分配和初始化属性的开销。属性元数据（如名称、类型）只需定义一次，存储在节点类型中，供所有实例共享。
  - Maya 的依赖图在运行时高效地管理属性值，每个实例的 `MDataBlock` 存储具体值，无需在 Python 层面为每个实例创建属性对象。

- **一致性保证**：
  - 类属性确保所有节点实例共享相同的属性定义（名称、类型、默认值等），避免了因实例属性定义不一致导致的错误。
  - 如果属性是实例属性，可能导致不同实例的属性定义不一致（例如不同的默认值或类型），这会破坏 Maya 依赖图的一致性。

#### **1.3 插件注册的需要**
- **节点类型注册**：
  - 在注册自定义节点时，Maya 的 `MFnPlugin.registerNode` 需要节点类型的属性定义。这些定义通过类属性提供，并在 `initialize` 方法中配置。
  - 示例：
    ```python
    def initializePlugin(mobject):
        plugin = om.MFnPlugin(mobject)
        plugin.registerNode("customNode", CustomNode.node_id, CustomNode.creator, CustomNode.initialize)
    ```
  - `initialize` 方法使用类属性（如 `CustomNode.input_attr`）来添加属性到节点类型，实例属性无法满足这种注册需求。

- **静态初始化**：
  - `MPxNode.initialize` 是静态方法，运行在节点类型注册时，而不是实例创建时。因此，属性必须作为类属性存在，以便在 `initialize` 中访问。

#### **1.4 Maya 的属性存储机制**
- **属性值与实例绑定**：
  - 每个节点实例在 Maya 的依赖图中有一个 `MDataBlock`，用于存储该实例的属性值。`MDataBlock` 是一个运行时数据结构，与节点实例绑定，而非 Python 的实例属性。
  - 在 `MPxNode.compute` 方法中，开发者通过 `MDataBlock` 访问和修改属性值：
    ```python
    def compute(self, plug, data):
        if plug == CustomNode.output_attr:
            input_handle = data.inputValue(CustomNode.input_attr)
            input_value = input_handle.asFloat()
            output_handle = data.outputValue(CustomNode.output_attr)
            output_handle.setFloat(input_value * 2)
            data.setClean(plug)
    ```
  - 这里，`input_attr` 和 `output_attr` 是类属性，用于标识属性，但 `input_value` 是实例特定的值，从 `MDataBlock` 获取。

- **实例无关的属性定义**：
  - 属性定义（如 `MObject` 类型的 `input_attr`）是节点类型的元数据，不随实例变化。Maya 使用这些元数据来管理节点的连接、计算和存储。

### 2. **为什么不用实例属性？**
你提到“每个节点都有自己的属性，应该写成实例属性”，这个想法直观上合理，但以下原因解释了为什么实例属性不适合 Maya 的节点属性：

#### **2.1 属性定义的共享性**
- 节点的属性定义（如名称、类型、默认值）是节点类型级别的，所有实例必须共享相同的定义。
- 如果使用实例属性，每个节点实例都需要在创建时定义自己的属性对象，这会导致：
  - **重复定义**：增加内存和性能开销。
  - **不一致性**：不同实例可能定义不同的属性，导致依赖图行为不可预测。
- 类属性确保属性定义只存在一份，供所有实例共享。

#### **2.2 实例属性值的存储由 Maya 管理**
- 节点实例的属性值（如 `translateX = 5.0`）存储在 Maya 的 `MDataBlock` 中，而不是 Python 的实例属性中。
- 开发者无需在 Python 层面为每个实例存储属性值，只需在 `compute` 或其他方法中通过 `MDataBlock` 访问即可。
- 示例：
  ```python
  data_handle = data.inputValue(CustomNode.input_attr)
  value = data_handle.asFloat()  # 每个实例的值不同
  ```

#### **2.3 插件注册的限制**
- Maya 的 `registerNode` 过程要求在节点类型注册时提供属性定义，这发生在插件加载时，而不是实例创建时。
- 实例属性在节点实例创建时才会初始化，无法满足 `initializePlugin` 和 `initialize` 方法的静态要求。

#### **2.4 动态属性的例外**
- Maya 支持动态属性（dynamic attributes），可以在运行时通过 `MFnAttribute` 添加到特定节点实例：
  ```python
  node = om.MObject()  # 假设已有节点
  n_attr = om.MFnNumericAttribute()
  dynamic_attr = n_attr.create("dynamicAttr", "da", om.MFnNumericData.kFloat)
  node_fn = om.MFnDependencyNode(node)
  node_fn.addAttribute(dynamic_attr)
  ```
- 动态属性是实例特定的，但它们仍然通过 Maya 的 API 添加，而不是作为 Python 的实例属性。这种机制与自定义节点类型的静态属性定义不同。

### 3. **典型实现示例**
以下是一个完整的自定义节点示例，展示如何使用类属性定义节点属性：

```python
import maya.api.OpenMaya as om

class CustomNode(om.MPxNode):
    node_id = om.MTypeId(0x80000)
    input_attr = om.MObject()  # 类属性
    output_attr = om.MObject()  # 类属性

    @staticmethod
    def creator():
        return CustomNode()

    @staticmethod
    def initialize():
        # 创建输入属性
        n_attr = om.MFnNumericAttribute()
        CustomNode.input_attr = n_attr.create("input", "in", om.MFnNumericData.kFloat, 0.0)
        n_attr.writable = True
        n_attr.storable = True
        CustomNode.addAttribute(CustomNode.input_attr)

        # 创建输出属性
        CustomNode.output_attr = n_attr.create("output", "out", om.MFnNumericData.kFloat, 0.0)
        n_attr.writable = False
        n_attr.storable = False
        CustomNode.addAttribute(CustomNode.output_attr)

        # 定义属性依赖
        CustomNode.attributeAffects(CustomNode.input_attr, CustomNode.output_attr)

    def compute(self, plug, data):
        if plug == CustomNode.output_attr:
            input_handle = data.inputValue(CustomNode.input_attr)
            input_value = input_handle.asFloat()
            output_handle = data.outputValue(CustomNode.output_attr)
            output_handle.setFloat(input_value * 2)
            data.setClean(plug)

def initializePlugin(mobject):
    plugin = om.MFnPlugin(mobject)
    plugin.registerNode("customNode", CustomNode.node_id, CustomNode.creator, CustomNode.initialize)

def uninitializePlugin(mobject):
    plugin = om.MFnPlugin(mobject)
    plugin.deregisterNode(CustomNode.node_id)
```

**运行效果**：
- 注册节点后，可以通过 `maya.cmds.createNode("customNode")` 创建多个节点实例。
- 每个实例的 `input` 和 `output` 属性值独立存储在 `MDataBlock` 中，但属性定义（`input_attr`, `output_attr`）是类级别的，共享于所有实例。

**验证独立属性值**：
```python
import maya.cmds as cmds
node1 = cmds.createNode("customNode", name="node1")
node2 = cmds.createNode("customNode", name="node2")
cmds.setAttr("node1.input", 5.0)
cmds.setAttr("node2.input", 10.0)
print(cmds.getAttr("node1.output"))  # 输出: 10.0
print(cmds.getAttr("node2.output"))  # 输出: 20.0
```

### 4. **类属性 vs. 实例属性的对比**
| 特性                  | 类属性（当前设计）                              | 实例属性（假设使用）                            |
|-----------------------|-----------------------------------------------|-----------------------------------------------|
| **定义位置**          | 在类级别，定义节点类型的属性结构              | 在实例级别，每个节点实例定义自己的属性         |
| **存储方式**          | 属性定义存储在类中，值存储在 `MDataBlock`      | 属性定义和值都存储在实例中                    |
| **性能**              | 高效，属性定义只存储一次                      | 低效，每个实例重复定义属性                    |
| **一致性**            | 所有实例共享一致的属性定义                    | 可能导致属性定义不一致                        |
| **注册支持**          | 适合 `initializePlugin` 的静态注册流程         | 不支持静态注册，需动态添加属性                |
| **撤销支持**          | 通过 `MDataBlock` 和依赖图支持撤销             | 需要额外机制管理撤销                          |

### 5. **回答你的疑问**
你提到“一个 Maya 场景可以创建多个节点，每个节点有自己的属性，应该写成实例属性”。以下是具体解答：

- **属性值的独立性**：
  - 每个节点实例的属性值（如 `input = 5.0` 或 `input = 10.0`）是独立的，存储在 Maya 的 `MDataBlock` 中，而不是 Python 的实例属性中。
  - 类属性（如 `input_attr`）仅定义属性的元数据（名称、类型、默认值），不存储具体值，因此不会导致实例间属性值混淆。

- **为什么不用实例属性**：
  - 如果将属性定义为实例属性（如在 `__init__` 中创建 `self.input_attr`），每个节点实例都会有自己的属性对象，这会导致：
    - **内存浪费**：每个实例重复存储属性元数据。
    - **注册问题**：`initialize` 方法是静态的，无法访问实例属性，导致无法在节点类型注册时定义属性。
    - **不一致性**：不同实例可能定义不同的属性，破坏节点类型的统一性。
  - 类属性确保属性定义在节点类型级别统一，值在实例级别独立，符合 Maya 依赖图的设计。

- **动态属性的替代**：
  - 如果需要实例特定的属性，可以使用动态属性（通过 `MFnAttribute` 和 `MFnDependencyNode.addAttribute` 添加）。
  - 但动态属性通常用于运行时扩展，不适合定义节点类型的核心结构。

---

### 6. **总结**
在 Maya Python API 2.0 中，节点属性定义为类属性（而非实例属性）是因为：
1. **属性是节点类型的元数据**：类属性定义了节点类型的结构（名称、类型、默认值），供所有实例共享。
2. **性能和一致性**：类属性避免了重复定义，提高了性能并确保属性定义一致。
3. **插件注册需求**：节点类型通过静态的 `initialize` 方法注册，类属性便于在注册时访问。
4. **属性值独立性**：每个节点实例的属性值存储在 `MDataBlock` 中，确保实例间值的独立性，无需实例属性。
