# 算法思想
- 希尔排序 Shell Sort 是[10.3-插入排序](10.3-插入排序.md)的一种更高效的改进版本。使通过分组插入排序数据逐渐趋于有序，调高排序效率。
- 将整个数组切按照一定的间隔取值划分为若干个子数组，每个子数组分别进行插入排序。然后逐渐缩小间隔进行下一轮划分子数组和对子数组进行插入排序。直至最后一轮排序间隔为 1，对整个数组进行插入排序。
# 算法步骤

- 假设数组的元素个数为 size 个，则希尔排序的算法步骤如下：

- **初始化步长 `gap`**：
    
    - 初始步长为数组长度的一半，即 `gap = size / 2`。随后每次迭代时，步长减半 (`gap /= 2`)，直到步长变为1为止。
- **内层循环（插入排序部分）**：
    
    - 对数组进行插入排序，但不是直接相邻元素间进行，而是按当前 `gap` 的距离进行。
    - `for (int i = gap; i < size; ++i)` 中从 `gap` 开始遍历每个元素，`val` 保存当前元素，`j` 是当前元素前面 `gap` 距离的元素索引。
- **比较与插入操作**：
    
    - 向左依次比较间隔为 `gap` 的元素，如果发现前面的元素 `arr[j]` 比 `val` 大，就将 `arr[j]` 后移到 `arr[j + gap]`，让出位置。
    - 当找到正确位置（即 `arr[j] <= val`），或达到数组左边界时，将当前元素插入到正确的位置。
- **重复缩小步长**：
    
    - 步长 `gap` 逐步减小，每次都在更小的步长上进行类似插入排序。当 `gap = 1` 时，算法退化为标准的插入排序，但此时由于之前的大跨度移动，效率较插入排序更高。

# 代码
```cpp
void shellSort(int arr[], int size)
{
    // 1. 计算初始 gap（步长），gap 初始为数组长度的一半
    for (int gap = size / 2; gap > 0; gap /= 2)
    {
        // 2. 从索引 gap 开始遍历数组，执行插入排序
        for (int i = gap; i < size; ++i)
        {
            int val = arr[i]; // 将当前元素保存到 val
            int j = i - gap;  // 找到 gap 之前的元素
            // 3. 向左扫描 gap 步长，插入排序子数组
            for (; j >= 0; j -= gap)
            {
                // 如果 gap 前面的元素大于当前元素，继续移动元素
                if (arr[j] <= val)
                {
                    break; // 找到合适位置时退出
                }
                arr[j + gap] = arr[j]; // 向后移动 gap 长度的元素
            }
            arr[j + gap] = val; // 将当前元素 val 插入到正确的位置
        }
    }
}
```
# 算法分析
希尔排序（Shell Sort）是一种**不稳定**的排序算法，其时间复杂度和性能表现取决于所选的**步长序列**。以下是关于其时间复杂度、性能表现及分析的详细信息。

### 1. **时间复杂度**

希尔排序的时间复杂度主要受到步长序列的影响，不同的步长序列会导致不同的复杂度。

- **最差情况时间复杂度**：
    
    - 如果使用简单的步长序列（如 `gap = n/2, n/4, ..., 1`），希尔排序的最坏情况时间复杂度为 **O(n²)**，接近插入排序。
    - 对于更优化的步长序列（如 Hibbard、Sedgewick 或 Knuth），最坏情况下的时间复杂度可以降低到 **O(n^(3/2))** 或更好。
- **最佳情况时间复杂度**：
    
    - 当数组几乎有序时，希尔排序表现非常好。使用步长序列 `gap = n/2, n/4, ..., 1` 时，最佳情况的时间复杂度接近 **O(n log n)**，因为此时插入排序部分需要的元素移动次数很少。
- **平均情况时间复杂度**：
    
    - 平均情况下，希尔排序的复杂度依然依赖于步长序列，通常会在 **O(n log² n)** 和 **O(n^(3/2))** 之间波动。

#### 不同步长序列的时间复杂度：

|步长序列|平均时间复杂度|最坏时间复杂度|
|---|---|---|
|Shell 原始序列 (n/2, n/4, ..., 1)|O(n²)|O(n²)|
|Hibbard (1, 3, 7, ..., 2^k - 1)|O(n^(3/2))|O(n^(3/2))|
|Knuth (1, 4, 13, 40, ...)|O(n^(3/2))|O(n^(3/2))|
|Sedgewick (1, 5, 19, 41, ...)|O(n log² n)|O(n^(4/3))|

### 2. **空间复杂度**

希尔排序的**空间复杂度**为 **O(1)**，因为它是**原地排序算法**，不需要额外的空间来存储辅助数组。只需几个辅助变量。

### 3. **性能分析**

希尔排序通过减少较大的逆序对来提高排序效率，尤其在插入排序时，靠近开头的元素可能需要多次移动，希尔排序通过缩小步长，在早期阶段消除这些问题。

- **步长序列的选择**：步长序列的选择对于希尔排序的性能至关重要。较小的步长在数组几乎有序时非常高效，但较大的步长帮助在早期阶段将元素快速移动到相对接近正确的位置。
    
- **稳定性**：希尔排序是**不稳定排序**。即在排序过程中，可能会打乱相同元素的相对顺序。因为相同值的元素可能分到不同的组中。
    
- **适用场景**：
    
    - 对于中小规模的数据集（数百到数千个元素），希尔排序可以比 O(n²) 的算法如插入排序和选择排序快得多。
    - 它适用于不希望额外使用内存的场景，因为它是原地排序。
    - 不适合非常大的数据集，因为现代更高效的排序算法如快速排序（Quick Sort）和归并排序（Merge Sort）可以在 O(n log n) 的时间复杂度下完成。

### 4. **与其他排序算法的比较**

- **相比[插入排序](10.3-插入排序.md)**：希尔排序可以看作是插入排序的改进版。通过步长序列，希尔排序在初期阶段通过更大的步长交换消除了大量的逆序对，使得插入排序部分更加高效。
    
- **相比快速排序**：希尔排序的平均时间复杂度通常比快速排序略差，尤其在大规模数据集上，快速排序的 O(n log n) 时间复杂度表现更优。
    
- **相比堆排序**：希尔排序的表现可能比堆排序稍好，尤其是使用合适的步长序列时。然而，堆排序的时间复杂度始终为 O(n log n)，更为稳定
### 总结：

- **最坏情况时间复杂度**：取决于步长序列，通常为 **O(n²)** 或 **O(n^(3/2))**。
- **最佳情况时间复杂度**：几乎有序的数组时，接近 **O(n log n)**。
- **平均情况时间复杂度**：**O(n log² n)** 到 **O(n^(3/2))**。
- **空间复杂度**：**O(1)**（原地排序）。
- **适用场景**：中小型数组，步长序列的选择对性能影响显著。
