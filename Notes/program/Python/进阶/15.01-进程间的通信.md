在 Python 中，子进程之间（以及父子进程之间）是**完全独立的内存空间**，它们之间不能像线程那样直接共享变量。要通信，必须使用操作系统提供的**进程间通信（IPC，Inter-Process Communication）** 机制。

Python 的 `multiprocessing` 模块把底层最常用、最可靠的 IPC 方式全部封装好了，几乎可以满足 99% 的需求。下面按实际使用频率和场景，逐一解释每种方法的原理、优缺点和典型用法。

| 通信方式               | 是否共享内存 | 速度      | 可以传什么数据                  | 典型场景                              | 推荐指数 |
|-----------------------|-------------|----------|--------------------------------|-------------------------------------|---------|
| Queue（队列）           | 否（pickle 传递）| 中等      | 几乎任意 Python 对象              | 最常见的任务分发、结果收集                | 5 星     |
| Pipe（管道）            | 否（pickle 传递）| 快       | 几乎任意 Python 对象              | 父子进程一对一双向通信                   | 5 星     |
| Manager                 | 否（通过代理）   | 慢       | 任意 Python 对象（list、dict 等）   | 需要共享可变对象（如共享字典、列表）          | 3 星     |
| shared_memory (共享内存)| 是           | 极快      | 数值、numpy array、bytes         | 大数据（如图片、视频、深度学习特征）零拷贝传输 | 5 星（Python 3.8+） |
| Value + Array（旧共享内存）| 是        | 快       | 单个基本类型或固定长度数组           | 简单数值共享（已逐渐被 shared_memory 取代） | 2 星     |
| Event、Lock、Semaphore 等同步原语 | 是   | 极快      | 仅用于同步，不传数据                | 进程间协调、互斥                         | 5 星     |

### 1. Queue（最最常用！）

```python
from multiprocessing import Process, Queue
import time


def write(q):
    for value in ["a", "b", "c"]:
        print(f"Task1 putting {value}")
        q.put(value)
        time.sleep(1)


def read(q):
    for _ in range(3):
        while not q.empty():
            value = q.get()
            print(f"Task2 got {value}")
            time.sleep(1)


if __name__ == "__main__":
    # 必须把子进程代码写在主程序守卫后面
    q_data: Queue = Queue(3)

    p_write = Process(target=write, args=(q_data,))
    p_read = Process(target=read, args=(q_data,))

    p_write.start()
    p_read.start()

    p_write.join()
    p_read.join()

    print("All tasks completed.")

```

底层实现：
- Unix：使用匿名 pipe + pickle + 一个专门的“feeder”线程
- Windows：通过 localhost 的 socket + pickle
- 完全自动序列化/反序列化，线程安全，对开发者最友好

适用场景：生产者-消费者模型、任务池、爬虫结果收集、机器学习数据加载等。

### 2. Pipe（管道，速度最快的一对一通信）

```python
from multiprocessing import Pipe, Process

parent_conn, child_conn = Pipe()  # 双向管道

def child(conn):
    conn.send({'status': 'ok'})
    conn.close()

p = Process(target=child, args=(child_conn,))
p.start()
print(parent_conn.recv())   # {'status': 'ok'}
p.join()
```

- 底层 Unix 用 pipe，Windows 用 socket
- 比 Queue 更快，因为没有队列管理开销
- 适合父进程 ↔ 单个子进程的双向通信

### 3. shared_memory（Python 3.8+，大数据神器）

```python
from multiprocessing import shared_memory
import numpy as np

# 主进程创建一块共享内存
shm = shared_memory.SharedMemory(create=True, size=100_000_000)  # 100MB
buffer = shm.buf

# 把 numpy array 放进去（零拷贝！）
arr = np.ndarray((10_000_000,), dtype=np.int32, buffer=shm.buf)
arr[:] = 123

# 子进程直接访问同一块内存
def worker(name):
    existing_shm = shared_memory.SharedMemory(name=name)
    arr_child = np.ndarray((10_000_000,), dtype=np.int32, buffer=existing_shm.buf)
    print(arr_child[0])  # 直接看到 123
    existing_shm.close()

p = Process(target=worker, args=(shm.name,))
p.start()
p.join()

# 记得清理
shm.close()
shm.unlink()
```

优势：真正零拷贝，10GB 数据也只需传一个名字（几十字节），速度比 pickle 快几十到几百倍。

### 4. Manager（共享复杂对象，但慢）

```python
from multiprocessing import Manager, Process

manager = Manager()
shared_dict = manager.dict()
shared_list = manager.list()

def worker(d, l):
    d['count'] = 100
    l.append(42)

p = Process(target=worker, args=(shared_dict, shared_list))
p.start()
p.join()

print(shared_dict)  # {'count': 100}
print(shared_list)  # [42]
```

底层是通过一个独立的 Manager 进程（本质是一个小型服务器）实现的，所有操作都要走网络（即使是本地 loopback），非常慢。只在实在没办法的情况下才用。

### 5. 同步原语（Lock、Event 等）

```python
from multiprocessing import Lock, Process

lock = Lock()

def worker(l):
    with l:
        print("我获取到了锁")

p = Process(target=worker, args=(lock,))
p.start()
p.join()
```

这些不传输数据，只用来协调多个进程的执行顺序。

### 总结：实际项目中怎么选？

| 需求场景                           | 推荐方式                     |
|----------------------------------|----------------------------|
| 任务分发 + 结果收集（最常见）          | Queue                     |
| 父子进程快速双向对话                  | Pipe                      |
| 传大 numpy array、图像、音频、模型特征等   | shared_memory（首选）         |
| 需要多个进程同时读写同一个 dict/list    | Manager（慎用）或自己用 shared_memory + Lock |
| 只需要共享几个数字、状态标志             | shared_memory 或 Value/Array |
| 进程间需要互斥、等待、信号               | Lock / Event / Semaphore   |

记住一句话：
**99% 的场景，用 Queue 就够了；传大块数据，用 shared_memory；其他情况再考虑别的。**

这就是 Python 子进程间通信的全部核心方法了。
