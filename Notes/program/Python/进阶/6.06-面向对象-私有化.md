Python 语言中的**面向对象编程（OOP）**支持**私有化**（encapsulation 的重要机制），用于隐藏类的内部实现细节，防止外部直接访问或修改某些属性或方法。

---

### 一、Python 中的“私有”概念

> **Python 没有真正的私有（private）**，但通过**命名约定**和**名称改写（name mangling）**机制实现了“伪私有”。

---

### 二、私有化的两种方式

#### 1. **单下划线 `_var` —— 约定式私有（protected 风格）**

- **约定**：以单个下划线开头的变量或方法，**应该被视为“受保护的”**，不建议外部直接访问。
- **实际效果**：**不会阻止访问**，只是告诉开发者“这是内部使用的”。

```python
class Person:
    def __init__(self):
        self._name = "Alice"  # 受保护属性

    def _greet(self):         # 受保护方法
        print("Hello")

p = Person()
print(p._name)      # 可以访问 → Alice
p._greet()          # 可以调用 → Hello
```

> 推荐用于：类内部或子类中使用，外部“请勿随意访问”。

---

#### 2. **双下划线 `__var` —— 名称改写（真正“私有”）**

- **机制**：Python 解释器会将 `__var` **自动改写为** `_类名__var`
- **效果**：外部无法通过原名直接访问，实现了“私有化”

```python
class Person:
    def __init__(self):
        self.__age = 18       # 私有属性

    def __secret(self):       # 私有方法
        print("这是秘密")

p = Person()

# 直接访问会报错
# print(p.__age)      # AttributeError
# p.__secret()        # AttributeError
```

但你可以通过改写后的名字访问（不推荐，仅用于调试）：

```python
print(p._Person__age)     # → 18
p._Person__secret()       # → 这是秘密
```

> 这就是 **名称改写（Name Mangling）**，目的是避免子类意外覆盖父类的私有属性。

---

### 三、为什么用双下划线？（典型场景）

```python
class Animal:
    def __init__(self):
        self.__species = "Unknown"

class Dog(Animal):
    def __init__(self):
        super().__init__()
        self.__species = "Canine"  # 不会覆盖父类的 __species

dog = Dog()
print(dog._Animal__species)  # Unknown
print(dog._Dog__species)     # Canine
```

> 两个 `__species` 是**独立存储**的，避免命名冲突。

---

### 四、@property 结合私有属性（推荐做法）

更 Pythonic 的方式：**用私有属性 + property 控制访问**

```python
class Person:
    def __init__(self):
        self.__name = ""

    @property
    def name(self):
        return self.__name

    @name.setter
    def name(self, value):
        if not value:
            raise ValueError("名字不能为空")
        self.__name = value

p = Person()
p.name = "Bob"
print(p.name)  # Bob
```

---

### 五、总结对比

| 写法         | 名称              | 能否外部访问 | 名称改写 | 用途场景 |
|--------------|-------------------|--------------|----------|---------|
| `var`        | 公有              | 是           | 否       | 正常使用 |
| `_var`       | 受保护（约定）     | 是（不推荐）  | 否       | 内部使用、子类 |
| `__var`      | 私有（名称改写）   | 否（间接可）  | 是       | 隐藏实现、避免冲突 |
| `@property`  | 属性封装          | 受控访问      | 常配合 `__var` | 推荐的封装方式 |

---

### 六、建议（Pythonic 方式）

```python
class BankAccount:
    def __init__(self, balance):
        self._balance = balance  # 受保护

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, amount):
        if amount < 0:
            raise ValueError("余额不能为负")
        self._balance = amount
```

> 使用 `_balance` + `@property` 是最推荐的封装方式！

---

**结论**：  
Python 的“私有”靠**约定**和**名称改写**实现，推荐使用 `_var` + `@property` 实现真正安全的封装。
