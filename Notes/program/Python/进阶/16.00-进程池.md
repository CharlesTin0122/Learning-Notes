### Python 进程池（Process Pool）详尽介绍

进程池是 Python 多进程编程中最常用、最重要的工具，它能帮你一次性管理多个进程，避免手动一个个创建、启动、回收进程的麻烦，极大提升代码简洁度和性能。

Python 中提供进程池的模块主要有两种（功能几乎一样，选择其一即可）：

| 模块                   | 类名                    | 特点                |
| -------------------- | --------------------- | ----------------- |
| `multiprocessing`    | `Pool`                | 最经典、最多人用          |
| `concurrent.futures` | `ProcessPoolExecutor` | 更现代的写法，与线程池接口完全统一 |


### 1. multiprocessing.Pool（最常用）

```python
from multiprocessing import Pool
import time
import os


def work(x):
    print(f"任务 {x} 开始，进程ID: {os.getpid()}")
    time.sleep(1)  # 模拟耗时操作
    return x**2


if __name__ == "__main__":
    # 创建一个拥有 4 个进程的进程池（一般设为 CPU 核心数）
    with Pool(processes=4) as pool:
        # 方法1：apply_async + 异步回调（适合需要实时处理结果的场景）
        async_results = [
            pool.apply_async(work, (i,), callback=print) for i in range(10)
        ]
        results = [r.get() for r in async_results]

    # 方法2：map —— 最常用！自动把数据切分给各个进程
    # results = pool.map(work, range(10))

    # 方法3：imap（惰性版 map，返回迭代器，适合超大数据集）
    # for r in pool.imap(work, range(100)):
    #     print(r)

    # 主进程等待进程池执行完毕，再继续执行
    pool.join()
    print("所有任务结束，结果:", results)
    # 输出: [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
```

#### Pool 常用方法对比
|方法|功能|是否阻塞|返回值|最适合场景|推荐指数|
|---|---|---|---|---|---|
|pool.map(func, iterable, chunksize=None)|最常用！自动把 iterable 切块，分发给各个进程，按原顺序返回结果|阻塞|普通 list|数据量不大～中等，想简单并行拿到有序结果|★★★★★|
|pool.imap(func, iterable, chunksize=1)|惰性版 map，返回一个迭代器，按提交顺序逐个产出结果|可迭代时逐步阻塞|迭代器（有序）|数据量很大，想边计算边处理（节省内存）|★★★★★|
|pool.imap_unordered(func, iterable, chunksize=1)|同 imap，但谁先算完先返回（通常更快）|可迭代时逐步阻塞|迭代器（乱序）|不在乎顺序，只想尽快拿到结果|★★★★★|
|pool.apply_async(func, args=(), kwds={}, callback=None, error_callback=None)|异步提交单个任务|不阻塞|AsyncResult 对象|需要动态提交、配合 callback 实时处理|★★★★☆|
|pool.starmap(func, iterable, chunksize=None)|map 的加强版，支持多个参数：func(*item)|阻塞|list|每个任务需要传多个参数时用|★★★★☆|
|pool.starmap_async(...)|starmap 的异步版|不阻塞|AsyncResult|同上，但想异步提交|★★★☆☆|
|pool.map_async(func, iterable, chunksize=None, callback=None)|map 的异步版|不阻塞|AsyncResult|想提交后立刻干别的事，最后再取结果|★★★★☆|
|pool.close()|禁止再提交新任务|不阻塞|None|用完异步提交后必须调用|必须配对|
|pool.join()|等待所有子进程结束并回收|阻塞|None|配合 close() 使用|必须配对|

### 2. concurrent.futures.ProcessPoolExecutor（现代推荐写法）

Python 中的 concurrent 指的是“并发”编程，而 Python 标准库提供了一个非常好用的包叫 concurrent.futures，它位于 concurrent 模块之下，是现代 Python 并发编程的首选高层接口（Python 3.2+ 引入）。

```python
from concurrent.futures import (
    ThreadPoolExecutor,    # 线程池
    ProcessPoolExecutor,   # 进程池
    as_completed,          # 按完成顺序取结果
    wait,                  # 等待所有任务完成
)
```

它把底层复杂的线程/进程管理全部封装好，你只管提交任务就行。

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor, as_completed
import time

def task(n):
    time.sleep(2)          # 模拟 IO 或计算
    return f"任务 {n} 完成"

# 1. 用线程池（IO密集型推荐）
with ThreadPoolExecutor(max_workers=5) as executor:
    futures = [executor.submit(task, i) for i in range(10)]
    
    # 方法1：按提交顺序取结果
    for future in futures:
        print(future.result())
    
    # 方法2：谁先完成先取（推荐）
    for future in as_completed(futures):
        print(future.result())

# 2. 用进程池（CPU密集型推荐）
with ProcessPoolExecutor(max_workers=4) as executor:
    results = executor.map(task, range(10))  # 最简洁写法，返回顺序结果
    for r in results:
        print(r)
```

优点：接口和 ThreadPoolExecutor 完全一样，前后端切换只要改一行代码。
- 常用方法总结

|方法|说明|返回值|
|---|---|---|
|submit(fn, *args)|提交单个任务|Future 对象|
|map(fn, iterable)|类似内置 map，自动分配任务，保持顺序|结果迭代器（按输入顺序）|
|as_completed(fs)|按完成顺序返回 Future|Future 迭代器|
|future.result()|阻塞等待结果（可设置 timeout）|函数返回值|
|future.done()|是否已完成|True/False|
|future.cancel()|尝试取消（未开始才可能成功）|True/False|
### 进程池的关键注意事项

1. 必须在 `if __name__ == '__main__':` 保护下使用（Windows 必写，Linux/macOS 也建议写）
   - 否则会无限递归创建进程导致崩溃！

2. 被池执行的函数以及传递的参数必须是“可 pickle”（可序列化）的
   - 不能传 lambda 函数（Python 限制）
   - 不能传局部函数、方法、文件句柄、数据库连接等

   正确做法：把函数定义在模块顶层
   ```python
   # good
   def square(x):
       return x * x
   ```

3. 进程池会自动帮你回收进程，无需手动 join

4. 不要在 work 函数里再创建新的 Pool，会导致死锁或性能灾难

5. 进程池适合“任务数量 >> 进程数量”的场景
   - 典型：几千到几十万条数据，每条处理 0.1~10 秒

### 典型使用场景举例

```python
# 1. 大批量图片处理
with Pool(8) as p:
    p.map(process_image, image_path_list)

# 2. 爬虫突破频率限制（每个进程独立连接）
with Pool(10) as p:
    p.map(crawl_page, url_list)

# 3. 科学计算并行
with ProcessPoolExecutor() as executor:
    results = executor.map(monte_carlo_pi, [10**7] * 20)
```

### 总结：什么时候用进程池？

用一句话概括：
“只要你有大量 CPU 密集型、相互独立的小任务，就直接上进程池！”

推荐优先级：
1. `multiprocessing.Pool` → 最成熟、文档最多
2. `concurrent.futures.ProcessPoolExecutor` → 接口更优雅、未来趋势

两者选一个即可，功能完全覆盖 99% 的多进程需求。祝你玩得开心，CPU 跑满满！
