### Python 进程池（Process Pool）详尽介绍

进程池是 Python 多进程编程中最常用、最重要的工具，它能帮你一次性管理多个进程，避免手动一个个创建、启动、回收进程的麻烦，极大提升代码简洁度和性能。

Python 中提供进程池的模块主要有两种（功能几乎一样，选择其一即可）：

| 模块                          | 类名                     | 特点                                 |
|-------------------------------|--------------------------|--------------------------------------|
| `multiprocessing`             | `Pool`                   | 最经典、最多人用                     |
| `concurrent.futures`          | `ProcessPoolExecutor`    | 更现代的写法，与线程池接口完全统一   |

下面分别介绍它们的用法和核心概念。

### 1. multiprocessing.Pool（最常用）

```python
from multiprocessing import Pool
import time
import os

def work(x):
    print(f"任务 {x} 开始，进程ID: {os.getpid()}")
    time.sleep(1)          # 模拟耗时操作
    return x ** 2

if __name__ == '__main__':
    # 创建一个拥有 4 个进程的进程池（一般设为 CPU 核心数）
    with Pool(processes=4) as pool:
        # 方法1：map —— 最常用！自动把数据切分给各个进程
        results = pool.map(work, range(10))
        
        # 方法2：apply_async + 异步回调（适合需要实时处理结果的场景）
        # results = [pool.apply_async(work, (i,), callback=print) for i in range(10)]
        
        # 方法3：imap（惰性版 map，返回迭代器，适合超大数据集）
        # for r in pool.imap(work, range(1000000)):
        #     print(r)

    print("所有任务结束，结果:", results)
    # 输出: [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
```

#### Pool 常用方法对比

| 方法                  | 是否阻塞 | 返回值                              | 适用场景                         |
|-----------------------|----------|-------------------------------------|----------------------------------|
| `map(func, iterable)`     | 阻塞     | 直接返回 list（按输入顺序）          | 最常用，简单粗暴                 |
| `map_async()`             | 非阻塞   | 返回 AsyncResult 对象               | 需要继续干其他事                 |
| `apply(func, args)`       | 阻塞     | 只执行一次任务                      | 基本不用                         |
| `apply_async()`           | 非阻塞   | 返回 AsyncResult，可加 callback     | 需要回调处理结果时               |
| `imap(func, iterable)`    | 惰性     | 返回迭代器（按完成顺序）            | 数据量极大，怕一次性占满内存     |
| `imap_unordered()`        | 惰性     | 返回迭代器（谁先好返回谁）          | 不在乎顺序，只想尽快拿到结果     |

#### 进程池默认进程数量
```python
Pool()                  # 不写参数时，默认使用 cpu_count() 个进程
Pool(4)                 # 手动指定 4 个
Pool(processes=None)    # 同样使用 cpu_count()
```

获取 CPU 核心数：
```python
import os
os.cpu_count()   # 例如返回 8
```

### 2. concurrent.futures.ProcessPoolExecutor（现代推荐写法）

```python
from concurrent.futures import ProcessPoolExecutor, as_completed
import time

def task(n):
    time.sleep(1)
    return n * n

if __name__ == '__main__':
    with ProcessPoolExecutor(max_workers=4) as executor:
        # 方式1：map（和 Pool.map 完全一样）
        results = executor.map(task, range(10))
        print(list(results))

        # 方式2：submit + as_completed（最灵活）
        futures = [executor.submit(task, i) for i in range(10)]
        for future in as_completed(futures):
            print("有一个任务完成了:", future.result())
```

优点：接口和 ThreadPoolExecutor 完全一样，前后端切换只要改一行代码。

### 进程池的关键注意事项

1. 必须在 `if __name__ == '__main__':` 保护下使用（Windows 必写，Linux/macOS 也建议写）
   - 否则会无限递归创建进程导致崩溃！

2. 被池执行的函数以及传递的参数必须是“可 pickle”（可序列化）的
   - 不能传 lambda 函数（Python 限制）
   - 不能传局部函数、方法、文件句柄、数据库连接等

   正确做法：把函数定义在模块顶层
   ```python
   # good
   def square(x):
       return x * x
   ```

3. 进程池会自动帮你回收进程，无需手动 join

4. 不要在 work 函数里再创建新的 Pool，会导致死锁或性能灾难

5. 进程池适合“任务数量 >> 进程数量”的场景
   - 典型：几千到几十万条数据，每条处理 0.1~10 秒

### 典型使用场景举例

```python
# 1. 大批量图片处理
with Pool(8) as p:
    p.map(process_image, image_path_list)

# 2. 爬虫突破频率限制（每个进程独立连接）
with Pool(10) as p:
    p.map(crawl_page, url_list)

# 3. 科学计算并行
with ProcessPoolExecutor() as executor:
    results = executor.map(monte_carlo_pi, [10**7] * 20)
```

### 总结：什么时候用进程池？

用一句话概括：
“只要你有大量 CPU 密集型、相互独立的小任务，就直接上进程池！”

推荐优先级：
1. `multiprocessing.Pool` → 最成熟、文档最多
2. `concurrent.futures.ProcessPoolExecutor` → 接口更优雅、未来趋势

两者选一个即可，功能完全覆盖 99% 的多进程需求。祝你玩得开心，CPU 跑满满！
