在 Python 中，使用 `multiprocessing` 模块创建进程池（`Pool`）时，每个进程都是独立的操作系统进程，彼此之间没有共享内存。因此，进程池之间的通信（准确地说是主进程与池中子进程之间，或子进程相互之间）必须通过 IPC（进程间通信）机制进行。

常用的通信方式有以下几种：

### 1. 最常用的方式：函数返回值（推荐）
Pool 最简单、最常用的通信方式就是通过 `apply_async`、`map_async` 等方法获取子进程的执行结果。

```python
from multiprocessing import Pool

def worker(x):
    return x * x

if __name__ == '__main__':
    with Pool(4) as p:
        results = p.map(worker, [1, 2, 3, 4, 5])  # 同步阻塞获取结果
        print(results)  # [1, 4, 9, 16, 25]

        # 或者异步方式
        async_result = p.apply_async(worker, (10,))
        result = async_result.get()  # 等待结果
        print(result)  # 100
```

优点：简单、高效、自动序列化返回值  
这是 Pool 最推荐的通信方式。

### 2. 使用 Queue（进程安全的队列）
可以通过 `multiprocessing.Queue` 或 `Manager().Queue()` 在主进程和子进程间传递消息。
- 注意两者的区分
	- multiprocessing.Queue：**性能高、本地专用**，适合大多数普通多进程程序（尤其是配合 Pool）。
	- Manager().Queue()：**灵活、可跨任意进程共享**，但性能差、资源占用高，只有在确实需要“把队列传给后来动态创建的进程”时才用。
#### 什么情况下必须用 Manager().Queue()？

1. 你在运行时动态创建进程，需要把队列传给“孙子进程”或“后来启动的进程”。
2. 你在不同模块/不同脚本之间需要共享同一个队列（通过返回值或全局 Manager）。
3. 你使用了 forkserver 或 spawn 启动方式，且需要在子进程里再创建子进程并传递队列。
4. 你想把队列对象通过网络共享给其他机器（用 manager = Manager(address=('ip', port), authkey=...)）。

否则，99% 的情况下都应该优先使用 multiprocessing.Queue，性能差距非常明显。

```python
from multiprocessing import Pool, Manager

def worker(task_id, q):
    result = f"任务 {task_id} 完成"
    q.put({task_id: result})  # 子进程把结果放入队列

if __name__ == '__main__':
    manager = Manager()
    q = manager.Queue()  # 或者直接用 multiprocessing.Queue()

    with Pool(4) as p:
        for i in range(10):
            p.apply_async(worker, args=(i, q))
        
        p.close()
        p.join()

    # 主进程收集所有结果
    results = {}
    while not q.empty():
        results.update(q.get())
    print(results)
```

注意：`multiprocessing.Queue` 性能比 `Manager().Queue()` 更高，推荐使用前者。

### 3. 使用 Pipe（管道）
适合一对一或少量通信，性能最高。

```python
from multiprocessing import Pool, Pipe

def worker(conn):
    conn.send("子进程发来问候")
    conn.close()

if __name__ == '__main__':
    parent_conn, child_conn = Pipe()
    
    with Pool() as p:
        p.apply_async(worker, (child_conn,))
        p.close()
        p.join()
    
    print(parent_conn.recv())  # 子进程发来问候
```

### 4. 使用 Manager（共享对象）
可以共享 list、dict、Value、Array 等复杂数据结构，但性能较差，仅适合少量数据。

```python
from multiprocessing import Pool, Manager

def worker(d, i):
    d[i] = i * i

if __name__ == '__main__':
    manager = Manager()
    shared_dict = manager.dict()

    with Pool(4) as p:
        for i in range(10):
            p.apply_async(worker, (shared_dict, i))
        p.close()
        p.join()

    print(dict(shared_dict))
```

缺点：速度慢，容易成为性能瓶颈，一般不推荐在 Pool 中大量使用。

### 5. 使用共享内存（shared_memory）—— Python 3.8+
适用于大块数据（如 NumPy 数组）的高效共享。

```python
from multiprocessing import Pool, shared_memory
import numpy as np

def worker(shm_name, shape):
    shm = shared_memory.SharedMemory(name=shm_name)
    arr = np.ndarray(shape, dtype=np.int64, buffer=shm.buf)
    arr[:] *= 2  # 直接修改共享内存
    shm.close()

if __name__ == '__main__':
    arr = np.array([1, 2, 3, 4, 5], dtype=np.int64)
    shm = shared_memory.SharedMemory(create=True, size=arr.nbytes)
    shared_arr = np.ndarray(arr.shape, dtype=arr.dtype, buffer=shm.buf)
    shared_arr[:] = arr[:]  # 复制数据

    with Pool(2) as p:
        p.apply(worker, (shm.name, arr.shape))
        p.close()
        p.join()

    print(shared_arr)  # [2 4 6 8 10]
    shm.close()
    shm.unlink()
```

### 总结对比

| 方式                  | 适用场景                         | 性能   | 推荐度    |
|-----------------------|----------------------------------|--------|-----------|
| 函数返回值（map/apply）| 获取计算结果                     | ★★★★★ | 强烈推荐  |
| Queue                 | 子进程主动发送多条消息           | ★★★★  | 推荐      |
| Pipe                  | 一对一双向通信                   | ★★★★★ | 推荐      |
| Manager               | 共享 dict/list 等复杂结构        | ★★    | 不推荐    |
| shared_memory         | 大型数组、NumPy 数据共享         | ★★★★★ | 高性能场景推荐 |

### 最佳实践建议：
1. 优先使用 `Pool.map` / `apply_async().get()` 获取结果
2. 需要子进程主动报告进度或多结果 → 用 `Queue`
3. 传递大数组 → 用 `shared_memory`
4. 尽量避免使用 `Manager()`，性能太差

这样就能在进程池中高效、安全地进行通信了。
