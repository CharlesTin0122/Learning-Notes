### 1. 普通引用（强引用，Strong Reference）—— 默认的引用方式

在 Python 中，几乎所有变量都是“强引用”。  
当一个对象被至少一个强引用指向时，它的引用计数（reference count）大于 0，Python 的垃圾回收器就不会回收它。

```python
a = object()      # 创建一个对象，引用计数 = 1
b = a             # b 也指向同一个对象，引用计数 = 2
del a             # 删除 a，引用计数变成 1
del b             # 删除 b，引用计数变成 0 → 对象被销毁
```

**特点：**
- 只要有强引用存在，对象就“活着”。
- 最常见、最直观的引用方式。
- 会导致循环引用问题（见下文）。

### 2. 循环引用问题（强引用导致的内存泄漏）

```python
list1 = []
list2 = []
list1.append(list2)   # list1 → list2
list2.append(list1)   # list2 → list1，形成循环引用
del list1
del list2
# 即使外部已经没有变量指向它们，两个列表的引用计数仍然是 1，无法被回收！
```

Python 其实有“分代垃圾回收器”（gc 模块）可以检测并回收这种循环垃圾，但性能开销更大，而且某些情况下（比如对象实现了 `__del__` 方法）循环垃圾仍然无法被回收。

### 3. 弱引用（Weak Reference）—— 不增加引用计数

弱引用就是“不会阻止对象被垃圾回收”的引用。  
使用 `weakref` 模块创建。

```python
import weakref

obj = object()                    # 强引用，引用计数 = 1
weak = weakref.ref(obj)           # 创建弱引用，不增加引用计数

print(weak())                     # <object object at 0x...> 还能拿到对象
del obj                           # 删除唯一强引用，对象被销毁
print(weak())                     # None，已经被回收了
```

**常用弱引用类型：**

| 类型                  | 用法示例                              | 典型场景                     |
|-----------------------|---------------------------------------|------------------------------|
| `weakref.ref`         | `w = weakref.ref(obj)`                | 普通对象弱引用               |
| `weakref.WeakKeyDictionary`    | `d = weakref.WeakKeyDictionary()`     | 以对象为 key 的字典，key 可自动消失 |
| `weakref.WeakValueDictionary`  | `d = weakref.WeakValueDictionary()`   | 缓存：值对象无人使用时自动删除 |
| `weakref.WeakSet`     | `s = weakref.WeakSet()`               | 弱引用集合                   |

### 4. 最经典的实际应用场景

#### 场景1：对象缓存（WeakValueDictionary）

```python
import weakref

class ExpensiveObject:
    def __init__(self, name):
        self.name = name
        print(f"创建了 {name}")

cache = weakref.WeakValueDictionary()

def get_expensive(name):
    if name not in cache:
        obj = ExpensiveObject(name)
        cache[name] = obj          # 放入缓存
    else:
        print(f"缓存命中 {name}")
    return cache[name]

a = get_expensive("A")   # 创建
b = get_expensive("A")   # 缓存命中
del a
del b
# 此时 ExpensiveObject("A") 已经没有任何强引用，会被回收
c = get_expensive("A")   # 重新创建
```

#### 场景2：避免循环引用（尤其是观察者模式、父子关系）

```python
import weakref

class Node:
    def __init__(self, name):
        self.name = name
        self.parent = None          # 强引用父节点会导致循环引用
        self.weak_parent = None     # 改用弱引用

    def set_parent(self, parent):
        self.parent = parent
        self.weak_parent = weakref.ref(parent)  # 只保留弱引用

# 这样即使父子互相引用，子对象被删掉后父对象仍能正常回收
```

#### 场景3：监听对象生命周期而不阻止销毁

```python
import weakref

def callback(weak_ref):
    print("对象已经被销毁了！")

obj = object()
weak = weakref.ref(obj, callback)   # 注册回调
del obj                             # 输出：对象已经被销毁了！
```

### 5. 总结对比表

| 特性                  | 强引用（普通引用）           | 弱引用（weakref）                  |
|-----------------------|------------------------------|------------------------------------|
| 是否增加引用计数      | 是                           | 否                                 |
| 是否阻止对象被回收    | 是                           | 否                                 |
| 取对象方式            | 直接使用变量                 | 调用 `weak()`，可能返回 None       |
| 典型用途              | 正常持有对象                 | 缓存、观察者模式、避免循环引用     |
| 是否可能出现 None     | 不会                         | 会（对象被回收后返回 None）        |
| 常见容器              | list、dict、set 等           | WeakKeyDictionary、WeakValueDictionary、WeakSet |

### 6. 常见面试题

1. Python 的垃圾回收主要是引用计数，为什么还需要弱引用？  
   → 为了解决循环引用导致的内存泄漏，以及实现缓存、观察者等设计模式。

2. `weakref.ref(obj)` 和 `weakref.proxy(obj)` 有什么区别？  
   → `ref(obj)` 返回一个可调用对象，调用后得到原对象或 None；  
   → `proxy(obj)` 返回一个代理对象，可以像普通对象一样直接使用（属性访问、方法调用），但如果原对象被销毁会抛 `ReferenceError`。

```python
proxy = weakref.proxy(obj)
proxy.some_method()   # 直接用，对象没了会抛 ReferenceError
```
