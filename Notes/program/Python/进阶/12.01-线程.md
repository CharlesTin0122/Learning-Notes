### Python中的多线程（Multithreading）详解

Python 多线程主要通过标准库的 `threading` 模块实现（旧的方式还有 `_thread` 模块，但不推荐使用）。
#### 0. 主线程
- **主线程**就是 Python 程序启动时由解释器自动创建的第一个线程（名字永远是 `MainThread`），它结束时如果没有存活的非守护子线程，整个程序就会立刻退出。
	- PyQt/PySide：GUI 框架只能在主线程操作界面和场景
	- maya/Houdini：所有 API 必须在主线程
#### 1. 为什么Python多线程“看起来不太快”？
这是最常见的问题，答案在于 **GIL（Global Interpreter Lock，全局解释器锁）**。

- CPython（官方实现）中，**同一时刻只允许一个线程执行Python字节码**。
- GIL 会导致：**CPU密集型任务无法通过多线程获得真正的并行加速**，性能甚至可能比单线程还差（因为线程切换开销）。
- 但 **I/O密集型任务**（网络请求、文件读写、数据库操作等）可以显著受益，因为线程在等待I/O时会释放GIL，其他线程就能执行。

| 任务类型         | 多线程是否有效          | 推荐方案                  |
|------------------|-------------------------|---------------------------|
| CPU密集型（如计算） | 基本无效（受GIL限制）   | 多进程（multiprocessing）或多线程+使用C扩展释放GIL |
| I/O密集型（如爬虫、Web服务） | 非常有效                | 多线程或异步（asyncio）   |

#### 2. 基本用法示例

```python
import threading
import time

def worker(name, delay):
    for i in range(5):
        print(f"{name} - {i}")
        time.sleep(delay)

# 方法1：直接用Thread类
t1 = threading.Thread(target=worker, args=("线程A", 1))
t2 = threading.Thread(target=worker, args=("线程B", 0.5))
# 开始执行
t1.start()
t2.start()
# 主线程等待子线程结束，防止主线程提前结束把子线程杀掉。我等你干完再走。
t1.join() 
t2.join()
print("所有线程执行完毕")
```

#### 3. 面向对象的方式（推荐）

```python
class MyThread(threading.Thread):
    def __init__(self, name, delay):
        super().__init__()
        self.name = name
        self.delay = delay
    
    def run(self):
        for i in range(5):
            print(f"{self.name} - {i}")
            time.sleep(self.delay)

t1 = MyThread("自定义线程A", 1)
t2 = MyThread("自定义线程B", 0.5)
t1.start()
t2.start()
t1.join()
t2.join()
```
- 自定义类继承threading.Thread类
- 重写覆盖run方法
#### 4. 线程同步常用工具

因为多个线程共享内存，需要防止数据竞争（race condition）。

| 工具            | 作用                              | 示例 |
|-----------------|-----------------------------------|------|
| `threading.Lock()`      | 互斥锁，最常用的同步原语          | 保护共享变量 |
| `threading.RLock()`     | 可重入锁，同一个线程可以多次acquire |      |
| `threading.Event()`     | 线程间信号通知                    | 一个线程等待另一个线程发信号 |
| `threading.Condition()` | 条件变量                          | 生产者-消费者模型 |
| `threading.Semaphore(n)`| 信号量，限制同时访问资源的最大线程数 | 限制连接池大小 |
| `queue.Queue`   | 线程安全的队列（推荐用于生产者消费者） | 最常用 |

```python
# Lock 示例
lock = threading.Lock()
counter = 0

def increment():
    global counter
    for _ in range(100000):
        with lock:        # 自动acquire和release
            counter += 1

threads = [threading.Thread(target=increment) for _ in range(10)]
for t in threads: t.start()
for t in threads: t.join()
print(counter)   # 一定是1000000
```

#### 5. 线程池（推荐用于大量短任务）

Python 3.2+ 提供了 `concurrent.futures` 模块，写法更简洁：

```python
from concurrent.futures import ThreadPoolExecutor
import time

def task(n):
    time.sleep(1)
    return f"任务{n}完成"

with ThreadPoolExecutor(max_workers=5) as executor:
    futures = [executor.submit(task, i) for i in range(10)]
    for future in futures:
        print(future.result())
```

#### 6. 守护线程（Daemon Thread）

```python
t = threading.Thread(target=worker, daemon=True)  # 设为守护线程
t.start()
# 主线程结束时，守护线程会被强制终止
```

#### 7. 常见面试题总结

1. Python 的 GIL 是什么？为什么多线程CPU密集型任务不加速？
2. 什么时候用多线程？什么时候用多进程？
   - I/O密集 → 多线程或异步
   - CPU密集 → 多进程（multiprocessing）
3. ThreadLocal 有什么用？
   ```python
   local_data = threading.local()
   local_data.value = 123  # 每个线程独有一份
   ```

#### 8. 替代方案对比（2025年常用选择）

| 方案                 | 并行类型     | 是否受GIL影响 | 适用场景               |
|----------------------|--------------|---------------|------------------------|
| threading            | 并发         | 是            | I/O密集型任务          |
| multiprocessing      | 真正并行     | 否            | CPU密集型任务          |
| asyncio（async/await）| 并发         | 是（单线程）  | 高并发I/O（如Web服务） |
| concurrent.futures   | 并发/并行    | 取决于线程/进程池 | 简化线程/进程管理      |

总结一句话：
**在Python里，I/O密集型任务优先考虑多线程或异步，CPU密集型任务优先考虑多进程。**
