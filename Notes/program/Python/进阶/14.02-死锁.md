### 什么是死锁（Deadlock）？

死锁就是：**多个线程互相抱着对方需要的锁不放，大家谁都走不动，就像两条路口两辆车互相堵着，谁也不肯先倒车。**

经典生活例子（也是教科书例子）：

- 线程 A 拿到了锁1，想拿锁2  
- 线程 B 拿到了锁2，想拿锁1  
- A 等 B 放锁2，B 等 A 放锁1  
- 两个线程永远卡死，谁也进行不下去

在 Python 里经常这样写出来：

```python
import threading

lock1 = threading.Lock()
lock2 = threading.Lock()

def thread_a():
    with lock1:
        print("A 拿到了 lock1")
        with lock2:                # 在这里卡住，等 thread_b 放 lock2
            print("A 拿到了 lock2")

def thread_b():
    with lock2:
        print("B 拿到了 lock2")
        with lock1:                # 在这里卡住，等 thread_a 放 lock1
            print("B 拿到了 lock1")

# 很大概率死锁！
threading.Thread(target=thread_a).start()
threading.Thread(target=thread_b).start()
```

### 死锁发生的四个必要条件（必须同时满足才死锁）

| 条件          | 解释                                     |
|---------------|------------------------------------------|
| 1. 互斥       | 锁只能被一个线程持有（这是锁的本质）      |
| 2. 持有并等待 | 线程已经拿着至少一个锁，还想再拿别的锁    |
| 3. 不可抢占   | 别的线程不能强行抢走你手里的锁           |
| 4. 循环等待   | 形成一个等待环：A等B的锁，B等A的锁…      |

只要破坏其中任意一个条件，死锁就不可能发生。

### 最实用的 6 种避免死锁方法（按推荐程度排序）

| 排名 | 方法                              | 是否彻底避免 | 推荐指数 | 说明 + 代码示例 |
|------|-----------------------------------|--------------|----------|-----------------|
| 1    | 全局统一锁的获取顺序              | 彻底避免     | ★★★★★    | 所有代码永远先拿编号小的锁，再拿编号大的锁 |
| 2    | 只用一把大锁（粗粒度锁）          | 彻底避免     | ★★★★☆    | 简单粗暴，性能差一点但永远不会死锁 |
| 3    | 使用带超时的 try-lock + 全部释放重试 | 彻底避免     | ★★★★☆    | 稍微复杂，但很灵活 |
| 4    | 完全不用锁，用线程安全的数据结构  | 基本避免     | ★★★★★    | 现代 Python 最推荐方式（Queue、concurrent 等） |
| 5    | 把“嵌套锁”改成“先全部拿到再操作”  | 彻底避免     | ★★★☆☆    | 适用于必须拿多把锁的场景 |
| 6    | 死锁检测 + 强制解锁（很少用）     | 不能彻底避免 | ★☆☆☆☆    | 太复杂，几乎不用 |

### 具体做法（直接抄就行）

#### 1. 全局锁顺序（99% 项目都用这个）

```python
import threading

lock_a = threading.Lock()
lock_b = threading.Lock()
lock_c = threading.Lock()

# 规定全局顺序：永远先拿 a → b → c，绝不反过来！

def func1():
    with lock_a:
        with lock_b:
            # do something
            pass

def func2():
    with lock_a:          # 永远先拿 a
        with lock_b:      # 再拿 b
            with lock_c:
                pass

def func3():
    with lock_a:
        with lock_c:      # 虽然跳过了 b，但还是先拿 a，没问题
            pass
```

#### 2. 只用一把大锁（最保险）

```python
global_lock = threading.Lock()
balance = 0
orders = []

def any_function():
    with global_lock:
        # 所有共享变量的操作都放这里
        balance += 100
        orders.append(123)
```

#### 3. 完全不用锁，用线程安全的数据结构（现代 Python 推荐）

```python
from queue import Queue
from collections import defaultdict
import threading
import concurrent.futures

# 1. 用 Queue（内部已经线程安全）
q = Queue()
def producer(): q.put(666)
def consumer(): print(q.get())

# 2. 用线程池（完全不用自己管锁）
with concurrent.futures.ThreadPoolExecutor() as pool:
    pool.submit(task1)
    pool.submit(task2)

# 3. 用原子整数（Python 3.12+ 才有，旧版本用第三方）
# from atomicinteger import AtomicInteger
# counter = AtomicInteger(0)
# counter.increment()
```

#### 4. 超时获取锁（防止永远等）

```python
import threading import Lock
import time

class TimeoutLock:
    def __init__(self):
        self._lock = Lock()

    def acquire(self, timeout=5):
        end = time.time() + timeout
        while time.time() < end:
            if self._lock.acquire(blocking=False):
                return True
            time.sleep(0.001)
        return False

lock1 = TimeoutLock()
lock2 = TimeoutLock()

def safe_func():
    while True:
        if lock1.acquire(timeout=2):
            try:
                if lock2.acquire(timeout=2):
                    try:
                        # 正常操作
                        print("成功拿到两把锁")
                        return
                    finally:
                        lock2._lock.release()
            finally:
                lock1._lock.release()
        else:
            # 超时就重试（或者换顺序）
            time.sleep(0.01)
```
