Maya 中的多线程编程主要依赖于两个核心工具：

1. **Python 的 threading / concurrent.futures 模块**（最常用、最推荐）
2. **Maya C++ API 提供的 MThreadAsync / MThreadPool 等原生线程工具**（性能最高，但写法复杂）

下面分别详细介绍这两种方式在 Maya 中的实际用法、注意事项和最佳实践。

### 一、Python 多线程（99% 的情况下都用这个）

Maya 从 2016 开始已经将主线程切换为真正的 pthread（Linux/macOS）或 Windows 线程，Python 的 threading 模块可以安全使用，但必须严格遵守以下规则：

#### 核心铁律（违反就会崩溃或死锁）：
- 绝不能在子线程中直接调用任何 Maya Commands（mel、cmds、api 1.0 的 doCommand 等）
- 只能在子线程做纯计算、文件 IO、网络请求、numpy/pandas 等科学计算
- 所有修改场景、创建节点、查询节点的操作必须放回主线程执行

#### 推荐的正确姿势（2020 年后主流写法）：

```python
import maya.cmds as cmds
from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def heavy_calculation(data):
    # 这里可以疯狂计算、读写硬盘、调用 numpy、requests 等
    time.sleep(2)  # 模拟耗时操作
    return sum(data) * 2

def main_thread_callback(result):
    # 必须在主线程执行的操作
    print("结果回来了：在主线程创建节点", result)
    cmds.polyCube(n=f"resultCube_{result}")

def run_multithread():
    datas = [list(range(1000000)) for _ in range(20)]  # 20 个大任务
    
    # 方法1：ThreadPoolExecutor + OpenMaya 回调（推荐）
    from maya import OpenMaya
    
    def callback(future):
        result = future.result()
        OpenMaya.MGlobal.executeCommandOnIdle(f'maya.scriptJob -runOnce true "python(\"main_thread_callback({result})\")"')
    
    with ThreadPoolExecutor(max_workers=8) as executor:
        futures = [executor.submit(heavy_calculation, data) for data in datas]
        for future in as_completed(futures):
            future.add_done_callback(callback)

    # 方法2：使用 cmds.evalDeferred（更简单）
    with ThreadPoolExecutor(max_workers=8) as executor:
        futures = []
        for data in datas:
            fut = executor.submit(heavy_calculation, data)
            futures.append(fut)
        
        for future in as_completed(futures):
            result = future.result()
            cmds.evalDeferred(lambda r=result: main_thread_callback(r))
```

#### 常用主线程回传方式对比：

| 方式                         | 优点                            | 缺点                          |
|------------------------------|---------------------------------|-------------------------------|
| cmds.evalDeferred            | 最简单，无需额外导入             | 轻微延迟，顺序不保证           |
| OpenMaya.MGlobal.executeCommandOnIdle | 更精确控制                    | 写法复杂                      |
| om.MGlobal.executeCommandInMainThreadWithResult | 同步等待结果（慎用）      | 可能阻塞子线程                |
| scriptJob -runOnce           | 可靠                           | 字符串拼接麻烦                |

### 二、C++ API 原生多线程（只在极致性能时使用）

```cpp
#include <maya/MThreadPool.h>
#include <maya/MThreadAsync.h>

struct TaskData {
    int start, end;
    float* result;
};

void taskFunc(void* data, MThreadRootTask root) {
    TaskData* p = (TaskData*)data;
    // 这里可以安全调用部分 API（如 MFnMesh 的 getPoints 等只读操作）
    // 但仍然不能创建/删除节点！
}

void parallelCompute() {
    MThreadPool::init();
    std::vector<TaskData> tasks(32);
    MThreadPool::newParallelRegion(taskFunc, tasks.data(), tasks.size());
    MThreadPool::shutdown();
}
```

注意：即使在 C++ 原生线程中，创建节点、undo、修改 DG 等操作仍然必须在主线程！

### 三、实际生产中常见的正确架构

```python
# 典型大型工具架构
def heavy_task(args):
    # 子线程：只计算
    return compute_something_expensive(args)

def ui_callback(results):
    # 主线程：更新 UI、创建节点
    for r in results:
        create_node_from_result(r)

# 启动
future = executor.submit(heavy_task, big_data)
future.add_done_callback(lambda f: cmds.evalDeferred(lambda: ui_callback(f.result())))
```

### 四、常见错误写法（会导致 Maya 直接崩溃）

```python
# 错误！子线程直接操作 Maya
def bad():
    def worker():
        cmds.polyCube()  # 崩溃！
    threading.Thread(target=worker).start()
```

### 总结：Maya 多线程黄金法则

1. 子线程只做纯计算、IO
2. 所有 cmds、api 操作必须回主线程（evalDeferred 最方便）
3. 用 ThreadPoolExecutor 代替老旧的 threading.Thread
4. 需要极致性能时才考虑 C++ MThreadPool
5. 永远不要在子线程里碰 DG（依赖图）

这样写既能充分利用多核 CPU，又不会让 Maya 崩溃，是目前所有大型工作室（ILM、Weta、国内大部分外包公司）的标准做法。
