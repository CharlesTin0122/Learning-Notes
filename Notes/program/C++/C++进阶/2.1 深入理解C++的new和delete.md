`malloc`和`free`，是C语言的库函数
`new`和`delete`，是C++语言的运算符
# new和malloc的区别
在C++中，`new` 和 `malloc` 都可以用于动态内存分配，但它们有一些显著的区别：

### 1. **类型安全性**：
   - `new` 是类型安全的。它不仅分配内存，还会调用对象的构造函数来初始化对象，并且返回一个正确类型的指针。
   - `malloc` 是 C 语言的函数，它只分配内存，并返回 `void*` 类型的指针。你需要手动将它转换为需要的类型，并且它不会调用构造函数来初始化对象。

   ```cpp
   int* arr = new int[5];       // 使用 new，自动初始化
   int* arr = (int*)malloc(5 * sizeof(int));  // 使用 malloc，需要手动转换
   ```

### 2. **对象初始化**：
   - `new` 会调用类或结构体的构造函数来初始化分配的内存。
   - `malloc` 只分配内存，不进行初始化。

   ```cpp
   class MyClass {
   public:
       MyClass() { /* 构造函数逻辑 */ }
   };

   MyClass* obj = new MyClass();  // 构造函数被调用
   MyClass* obj = (MyClass*)malloc(sizeof(MyClass));  // 仅分配内存，构造函数不被调用
   ```

### 3. **内存释放**：
   - `new` 配合 `delete` 使用，`delete` 不仅释放内存，还会调用对象的析构函数，完成对象的清理工作。
   - `malloc` 配合 `free` 使用，`free` 只释放内存，不调用析构函数。

   ```cpp
   delete obj;  // 调用析构函数并释放内存
   free(obj);   // 仅释放内存，不调用析构函数
   ```

### 4. **分配失败时的行为**：
   - `new` 分配失败时会抛出 `std::bad_alloc` 异常。
   - `malloc` 分配失败时返回 `NULL` 指针。

   ```cpp
   try {
       int* arr = new int[1000000000];
   } catch (std::bad_alloc& e) {
       std::cout << "Allocation failed: " << e.what() << '\n';
   }

   int* arr = (int*)malloc(1000000000 * sizeof(int));
   if (!arr) {
       std::cout << "Allocation failed\n";
   }
   ```

### 5. **可自定义分配器**：
   - `new` 可以被重载，允许自定义内存分配逻辑。
   - `malloc` 是标准库函数，不能被重载。

### 总结：
- **`new/delete`**：C++特有，支持对象的构造和析构，类型安全，支持异常处理。
- **`malloc/free`**：C语言风格的内存管理，只进行内存分配和释放，没有对象构造和析构功能。

因此，在C++中，推荐使用 `new` 和 `delete`，特别是当涉及到对象时。
# delete和free的区别
在 C++ 中，`delete` 和 `free` 都用于释放动态分配的内存，但它们有以下显著的区别：

### 1. **作用范围**：
   - `delete` 主要用于释放通过 `new` 分配的内存，并且不仅仅释放内存，还会调用对象的析构函数。
   - `free` 主要用于释放通过 `malloc`、`calloc` 或 `realloc` 分配的内存，它仅仅释放内存空间，不涉及对象的析构。

   ```cpp
   int* arr = new int[5];
   delete[] arr;  // 正确，释放 new 分配的内存

   int* arr2 = (int*)malloc(5 * sizeof(int));
   free(arr2);  // 正确，释放 malloc 分配的内存
   ```

### 2. **析构函数调用**：
   - **`delete`** 调用对象的析构函数。这对于类类型的对象非常重要，因为析构函数可能会包含清理操作（如关闭文件、释放资源等）。
   - **`free`** 只释放内存，不调用析构函数。如果对象是通过 `malloc` 分配的，使用 `free` 时不会有任何额外的清理操作。

   ```cpp
   class MyClass {
   public:
       ~MyClass() { std::cout << "Destructor called\n"; }
   };

   MyClass* obj = new MyClass();
   delete obj;  // 调用析构函数并释放内存

   MyClass* obj2 = (MyClass*)malloc(sizeof(MyClass));
   free(obj2);  // 仅释放内存，不调用析构函数
   ```

### 3. **适用的内存分配方式**：
   - `delete` 和 `delete[]` 必须与 `new` 和 `new[]` 配合使用。`delete` 不能用于释放 `malloc` 分配的内存。
   - `free` 必须与 `malloc`、`calloc` 或 `realloc` 配合使用，不能用于释放 `new` 分配的内存。

   ```cpp
   int* arr = new int[5];
   delete[] arr;  // 正确
   // free(arr);  // 错误，不能使用 free 释放 new 分配的内存

   int* arr2 = (int*)malloc(5 * sizeof(int));
   free(arr2);  // 正确
   // delete[] arr2;  // 错误，不能使用 delete 释放 malloc 分配的内存
   ```

### 4. **数组释放**：
   - 当使用 `new[]` 分配数组时，必须使用 `delete[]` 来释放数组。这会确保每个数组元素的析构函数都被正确调用。
   - `free` 没有专门处理数组的机制，它只根据传入的指针释放内存。

   ```cpp
   int* arr = new int[10];
   delete[] arr;  // 正确释放数组

   int* arr2 = (int*)malloc(10 * sizeof(int));
   free(arr2);  // 正确，但没有调用析构函数（如果是对象数组的话）
   ```

### 5. **内存泄漏和未定义行为**：
   - 如果使用 `free` 来释放通过 `new` 分配的内存，或使用 `delete` 来释放通过 `malloc` 分配的内存，会导致未定义行为。这可能导致内存泄漏或程序崩溃。
   - 因此，必须严格遵循：`new` 和 `delete` 配对使用，`malloc` 和 `free` 配对使用。

### 6. **可重载性**：
   - 在 C++ 中，`new` 和 `delete` 操作符可以被重载，使得用户可以自定义内存分配和释放的行为。
   - `malloc` 和 `free` 是 C 标准库函数，无法在 C++ 中进行重载。

### 总结：
- **`delete`**：C++专用，用于释放 `new` 分配的内存，调用析构函数，支持对象的清理。
- **`free`**：C/C++通用，用于释放 `malloc` 分配的内存，不调用析构函数，只释放内存。

在 C++ 中，建议使用 `new`/`delete` 处理对象的动态分配和释放，使用 `malloc`/`free` 主要用于低级的内存操作或与 C 代码交互时。
# calloc 和 realloc
在 C 语言和 C++ 中，`calloc` 和 `realloc` 是用于动态内存分配和调整的标准库函数。它们都属于 C 标准库中的 `<stdlib.h>` 头文件。

### 1. **`calloc` (Contiguous Allocation)**

`calloc` 用于分配一块连续的内存区域，并且初始化所有分配的内存为零。

#### **语法**：
```c
void* calloc(size_t num, size_t size);
```

- **参数**：
  - `num`：要分配的元素个数。
  - `size`：每个元素的大小（以字节为单位）。
- **返回值**：返回指向已分配内存的指针。如果分配失败，返回 `NULL`。

#### **特点**：
- `calloc` 会分配 `num * size` 字节的内存，并将所有字节初始化为零。
- 和 `malloc` 不同的是，`calloc` 确保内存中的所有位都初始化为 0。这对于需要清零的数组等场景非常有用。

#### **示例**：
```c
int* arr = (int*)calloc(5, sizeof(int));  // 分配并初始化 5 个整数
if (arr == NULL) {
    // 处理内存分配失败
}
```

### 2. **`realloc` (Reallocation)**

`realloc` 用于调整已分配的内存块的大小。如果原内存块中的数据比调整后的大小小，它保留现有数据；如果新大小超过原大小，则新分配的内存未初始化。

#### **语法**：
```c
void* realloc(void* ptr, size_t new_size);
```

- **参数**：
  - `ptr`：指向先前通过 `malloc`、`calloc` 或 `realloc` 分配的内存指针。如果 `ptr` 为 `NULL`，则 `realloc` 的行为类似于 `malloc`。
  - `new_size`：要调整的内存块的新大小。
- **返回值**：返回指向调整后新内存块的指针。如果分配失败，返回 `NULL`，原指针所指向的内存不会被释放。

#### **特点**：
- 如果新大小大于原大小，`realloc` 可能会移动内存块到新的位置，并将数据复制到新分配的内存块中。
- 如果新大小为 0，`realloc` 的行为类似于 `free`，释放内存。
- 调整大小时，`realloc` 保留旧数据，但新分配的部分数据不进行初始化。

#### **示例**：
```c
int* arr = (int*)malloc(5 * sizeof(int));  // 分配 5 个整数
if (arr == NULL) {
    // 处理内存分配失败
}

// 调整内存大小，增加到 10 个整数
int* new_arr = (int*)realloc(arr, 10 * sizeof(int));
if (new_arr == NULL) {
    // 处理内存分配失败，原来的 arr 不会自动释放
} else {
    arr = new_arr;  // 更新指针
}
```

### 3. **`malloc` vs `calloc` vs `realloc` 对比**：

| 特性         | `malloc`                   | `calloc`                                | `realloc`                            |
|--------------|----------------------------|-----------------------------------------|--------------------------------------|
| 内存分配     | 分配指定字节数的内存         | 分配指定个数的元素，并初始化为 0         | 调整已有内存块的大小                 |
| 初始化       | 内存未初始化（随机数据）     | 内存初始化为 0                          | 新分配的内存未初始化（保留旧数据）   |
| 使用场景     | 当只需分配内存且无需初始化   | 需要分配并初始化为 0 的内存块            | 调整已分配内存块的大小               |

### 总结：
- **`calloc`**：适用于需要初始化为 0 的内存分配场景，分配多个元素并确保所有字节都初始化为 0。
- **`realloc`**：用于调整已分配内存块的大小，保留现有数据并重新分配内存，适合需要动态调整内存大小的场景。

这两个函数与 `malloc` 搭配使用，提供了更灵活的内存管理。
