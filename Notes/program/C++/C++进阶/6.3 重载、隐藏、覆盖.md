在继承过程中的成员方法我们经常用三种关系来描述，分别是重载，隐藏和覆盖。
```cpp
#include <iostream>

// 基类/父类
class Base
{
public:
    Base(int val = 10) : ma(val) {}
    // 基类方法
    void show() { std::cout << "Base::show()" << std::endl; }
    void show(int) { std::cout << "Base::show(int)" << std::endl; }

protected:
    int ma;
};

// 派生类/子类，类B继承自类A
class Derive : public Base
{
public:
    // Base(val)调用基类构造函数进行初始化，ma(val);
    Derive(int val = 20) : Base(val), mb(val) {}
    // 派生类方法
    void show() { std::cout << "Derive::show()" << std::endl; }

private:
    int mb;
};

int main()
{
    Derive d; // 派生类实例化对象

    d.show();         // 调用派生类自身show方法
    d.Base::show(30); // 调用基类show方法

    return 0;
}
```
# 重载关系
- 一组函数要重载，必须处在同一个作用域下，函数名相同，参数列表不同。处在不同的作用域下是不构成函数重载，会优先调用处在同一作用域下的函数。
	- `Base::show()`和`Base::show(int)`是重载关系，他们在同一作用域下，函数名相同，参数列表不同。
	- `Base::show()`和`Derive::show()`不是重载关系，他们作用域不同
# 隐藏关系
- 在继承结构当中，派生类的同名成员将基类的同名成员给隐藏掉了。隐藏指的是作用域的隐藏。
	- 派生类的同名方法`Derive::show()`将基类的同名方法`Base::show()`和`Base::show(int)`给隐藏了。派生类对象调用`show`方法，肯定是调用的自身用`show`方法。
	- 此时，派生类对象如果要调用基类方法。要加作用域`d.Base::show(30)`。派生类对象优先调用自身的方法，没有找到才回去基类中查找。
# 覆盖关系
- 基类和派生类的方法、返回值、函数名以及参数列表都相同，而且基类的方法是虚函数，那么派生类的方法就自动处理成虚函数，他们之间成为覆盖关系。
# 基类和派生类对象之间的类型转化
```cpp
    Base base(10);     // 基类对象
    Derive derive(20); // 派生类对象
    // 派生类 转化为 基类,类型从下到上的转化，是可以的。狗是一种动物
    base = derive;
    // 基类 转化为 派生类,类型从上到下的转化，是错误的。动物不是一种狗。
    derive = base;
    // 基类指针（引用）指向 派生类对象,类型从下到上的转化，是可以的。狗是一种动物
    // 基类指针只能调用基类的成员，无法调用派生类的成员。要调用派生类成员，要做类型强转`((Derive*)p) -> show()`
    Base *p = &derive;
    // 派生类指针（引用） 指向 基类对象，类型从上到下的转化，是错误的。动物不是一种狗。
    Derive *q = &base;
```
- 派生类对象向基类对象转化
	- 类型从下到上的转化，是可以的。狗是一种动物
- 基类对象到派生类对象的转化
	- 类型从上到下的转化，是错误的。动物不是一种狗。
- 基类指针（引用）指向派生类对象
	- 类型从下到上的转化，是可以的。狗是一种动物
- 派生类指针（引用）指向基类对象
	- 类型从上到下的转化，是错误的。动物不是一种狗。

总结：我们把继承结构说成是从上（基类）到下（派生类）的结构。在继承结构中进行上下游的类型转换，默认只支持从下到上的类型转换。狗是一种动物，动物不是一种狗。
