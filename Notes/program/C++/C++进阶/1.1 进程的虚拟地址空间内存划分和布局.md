# **虚拟地址空间概念**
进程的虚拟地址空间（Virtual Address Space，VAS）是现代操作系统中的一项关键技术，用于抽象出物理内存的复杂性，让每个进程有其自己的内存视图。通过虚拟内存机制，操作系统能够为每个进程提供一个独立、连续的地址空间，尽管物理内存可能是分散的、共享的或有限的。
# 特点：

1. **隔离性**：每个进程都有其独立的虚拟地址空间，不同进程的地址空间相互隔离。这意味着一个进程无法直接访问或修改另一个进程的内存，增加了系统的稳定性和安全性。
2. **线性化和连续性**：从进程的角度看，内存地址是连续的，即便在物理内存中，这些地址对应的物理页是分散的。虚拟内存可以让程序员无需关心物理内存的分配情况。
3. **大小可扩展**：虚拟地址空间的大小一般比实际的物理内存要大。例如，32位系统的虚拟地址空间最大可达 4 GB，64位系统的虚拟地址空间则更为广泛，甚至可以达到数TB甚至PB的范围。
4. **共享内存**：尽管每个进程都有其独立的虚拟地址空间，操作系统仍然可以通过内存映射（如共享库或文件映射）将同一块物理内存映射到多个进程的虚拟地址空间中，从而允许不同进程共享数据。
5. **页表映射**：虚拟地址需要通过页表转换为物理地址。页表是操作系统维护的一个结构，负责记录虚拟地址到物理地址的映射关系。当进程访问内存时，CPU通过页表查询相应的物理内存地址。页表转换由内存管理单元（MMU）完成。
# 结构：

通常情况下，虚拟地址空间被划分为多个不同区域，典型的有以下几种：

### 1. **代码段（Text Segment / Code Segment）**

- **作用**：存储进程执行的程序代码，即指令集。
- **特点**：
    - 通常是只读的，以防止程序在运行时修改自己的代码。
    - 可以被多个进程共享，尤其是在执行相同的程序时，这有助于节省内存。例如，多个用户运行同一个程序时，代码段只需要在内存中存储一次。
- **内容**：机器指令，函数定义。

### 2. **数据段（Data Segment）**

- **作用**：存储全局变量和静态数据，这些数据在整个程序执行过程中保持存储在内存中。
- **特点**：
    - 分为**初始化数据段**和**未初始化数据段（BSS 段）**：
        - **初始化数据段（Initialized Data Segment）**：存储已被初始化的全局变量或静态变量。
        - **BSS 段**（Block Started by Symbol）：存储未初始化的全局变量或静态变量，程序启动时这些变量默认初始化为0。
- **内容**：全局变量、静态变量。
- 程序启动时构造，程序结束时析构

### 3. **堆段（Heap Segment）**

- **作用**：用于动态分配内存。程序运行时可以通过调用如 `malloc()`（C 语言）或 `new()`（C++/Java）等函数，向堆段申请动态内存。
- **特点**：
    - 堆的大小不是固定的，会根据程序的需求动态增长或缩小。
    - 堆通常是从低地址向高地址方向增长的。
    - 程序员负责手动管理堆内存的分配和释放（如 `free()` 或 `delete()`），否则会导致内存泄漏。
- **内容**：动态分配的内存块，如对象实例、动态数组。
- new的时候构造，delete的时候析构

### 4. **栈段（Stack Segment）**

- **作用**：用于存储函数调用过程中创建的临时数据（如局部变量、函数参数、返回地址等），以及维护函数调用栈（Call Stack）。
- **特点**：
    - 栈是自动管理的，每当一个函数调用时，会自动分配栈帧；函数返回时，栈帧会被自动释放。
    - 栈通常是从高地址向低地址方向增长的。
    - 栈内存有严格的大小限制，如果程序递归调用过多或使用过多局部变量，可能会导致栈溢出（Stack Overflow）。
- **内容**：局部变量、函数参数、返回地址、保存的寄存器值。
- 进入函数到他定义的时候构造，出了函数作用域析构

### 5. **内存映射段（Memory-Mapped Segment / Mapped Files）**

- **作用**：用于内存映射文件（Memory-Mapped Files）或动态库（如 `shared libraries`）的加载。
- **特点**：
    - 通过内存映射，文件的内容可以直接映射到进程的虚拟地址空间中，进程可以像访问内存一样访问文件，读取和写入操作速度较快。
    - 动态链接库（如 `.dll` 或 `.so` 文件）也通过这种方式加载，多个进程可以共享这些库，节省内存。
- **内容**：动态库、共享库、内存映射文件的数据。

### 6. **内核空间（Kernel Space）**

- **作用**：操作系统保留的一部分地址空间，用于内核代码和数据的存储。
- **特点**：
    - 普通用户进程无法直接访问内核空间，以保护操作系统的稳定性和安全性。
    - 内核空间中存储着操作系统的核心代码和全局数据，处理诸如内存管理、硬件设备管理等低级任务。
- **内容**：操作系统内核代码、内核模块、内核数据结构。
### 7.只读数据段（.rodata）

- 作用：`.rodata` 段是程序中的**只读数据段**，它是编译时由编译器生成的一个特殊内存区域，主要存储程序中使用的**只读常量**和**不可修改的数据**。这个段通常位于代码段附近，与可执行指令一起加载到内存中，但由于它的内容是只读的，因此在程序运行过程中不能被修改。
- 特点：
	- 只读属性：
		- `.rodata` 段在程序运行时是只读的，任何试图修改 `.rodata` 段的内容都会导致段错误（segmentation fault）。
		- 这种只读特性有助于防止程序中的关键数据被意外或恶意修改，增强了程序的安全性。
- 内容：
	- **字符串常量**：比如 C 语言中的字符串字面量，如 `"Hello, World!"` 这样的常量。
	- **数值常量**：包括全局或局部作用域内的只读数值变量或常量，如 `const int x = 42;`。
	- **只读数组**：如果声明了只读的数组或表格数据，如 `const int array[] = {1, 2, 3};`，也会存放在 `.rodata` 段中。


- 任何编程语言编写的代码只能产生两种东西：指令和数据。
- C++语言编写的代码在编译链接之后生成二进制可执行程序（.exe文件)，储存在磁盘当中，要运行程序时，将程序加载到内存当中执行。

## 代码案例
```cpp
#include <iostream>

// 全局变量,都为数据。
int data1 = 10; // 初始化不为0，放在.data段
int data2 = 0;  // 初始化为0，放在.bss段
int data3;      // 未初始化，放在.bss段
// 静态全局变量
static int data4 = 11; // 初始化不为0，放在.data段
static int data5 = 0;  // 初始化为0，放在.bss段
static int data6;      // 未初始化，放在.bss段

int main()
{
    // 局部变量，编译后产生mov指令,指令放在.text段
    // 函数运行后，系统内核会在栈上为函数开辟栈帧，指令运行时会在栈上分配一个4字节空间来存放12这个值。
    int a = 12; // 初始化不为0
    int b = 0;  // 初始化为0
    int c;      // 未初始化
    // 静态局部变量，放在数据段，但是程序启动时不初始化，运行到当前行时进行初始化
    static int d = 13; // 初始化不为0，放在.data段
    static int e = 0;  // 初始化为0，放在.bss段
    static int f;      // 未初始化，放在.bss段

    std::cout << c << std::endl; // 栈上的无效值
    std::cout << f << std::endl; // 0，f存放在.bss段，系统内核会置0

    return 0;
}
```
- 每一个进程的用户空间时私有的，但是内核空间时共享的。
# 工作机制：

1. **虚拟地址到物理地址的映射**：虚拟内存通过页表将虚拟地址映射到物理地址。每个虚拟地址对应一个物理页，操作系统会在内存中维护这些映射信息。当进程访问某个虚拟地址时，CPU会通过内存管理单元（MMU）查找页表，找到对应的物理内存位置。
2. **页表缓存和TLB（Translation Lookaside Buffer）**：由于页表存储了大量的映射信息，频繁的查找会带来性能开销。为此，CPU引入了TLB，一个缓存机制，用来快速存储最近使用的页表项，加快地址转换的速度。
3. **页面置换和交换（Swapping）**：当物理内存不足时，操作系统可以将部分不活跃的虚拟内存页写入磁盘，从而释放物理内存。这些被写入磁盘的页面可以在稍后被重新载入内存，这一机制称为页面置换。
