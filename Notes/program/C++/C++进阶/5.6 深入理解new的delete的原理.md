# new 和 malloc 的区别
- `malloc`按照字节开辟内存，无需指定类型。`new`开辟内存时需要指定类型。
- `malloc`返回的是`void*`，需要手动将它转换为需要的类型。而new开辟内存时需要指定类型，所以返回的是一个选定类型的指针。
- `malloc`只负责开辟内存空间。`new`不仅可以开辟内存空间，还调用构造函数进行数据的初始化。
- `malloc`开辟内存失败返回的是`nullptr`指针，而`new`开辟内存失败抛出`bad_alloc`异常。
-  `new` 可以被重载，允许自定义内存分配逻辑。`malloc` 是标准库函数，不能被重载。
# free 和 delete的区别
- `delete`会先调用析构函数析构对象再释放内存。`free`只负责释放内存
- `delete` 可以被重载，允许自定义内存分配逻辑。`free` 是标准库函数，不能被重载。
# # free 和 delete操作符重载
- `malloc` 和 `free` 是 C 标准库函数
- `new`和`delete`本质上是操作符
	- `new`调用的是`operator new`重载函数的调用
	- `delete`调用的是`operator delete`重载函数的调用
```cpp
#include <cstddef>  // for std::size_t
#include <cstdlib>  // for malloc, free
#include <iostream> // for std::cerr
#include <new>      // for std::bad_alloc

// 重载全局new操作符
void *operator new(std::size_t size)
{
    if (size == 0) size = 1; // 防止分配0字节内存
    void *ptr = std::malloc(size);
    if (ptr == nullptr) throw std::bad_alloc(); // 内存分配失败抛出异常
    return ptr;
}

// 重载全局delete操作符
void operator delete(void *ptr) noexcept
{
    if (ptr) std::free(ptr); // 空指针检查
}

// 重载new[]操作符（数组分配）
void *operator new[](std::size_t size)
{
    if (size == 0) size = 1; // 防止分配0字节内存
    void *ptr = std::malloc(size);
    if (ptr == nullptr) throw std::bad_alloc(); // 内存分配失败抛出异常
    return ptr;
}

// 重载delete[]操作符（数组释放）
void operator delete[](void *ptr) noexcept
{
    if (ptr) std::free(ptr); // 空指针检查
}

int main()
{
    try
    {
        int *ptr = new int; // 分配单个int
        delete ptr;         // 释放单个int

        int *arr = new int[10]; // 分配int数组
        delete[] arr;           // 释放int数组
    }
    catch (const std::bad_alloc &err)
    {
        std::cerr << err.what() << std::endl;
    }

    return 0;
}
```
## 要点
在C++中，`new` 和 `delete` 操作符重载函数中之所以不需要直接涉及对象的构造和析构，是因为 **内存分配/释放** 和 **对象的构造/析构** 这两件事情是 **分开处理** 的。C++的标准行为自动处理了这两者之间的联系。
- `operator new` 和 `operator delete` 重载函数只处理 **内存的分配和释放**，不处理构造和析构。
- 在使用 `new` 和 `delete` 运算符时，编译器会自动负责对象的 **构造** 和 **析构**，这是C++语言特性提供的机制。
- - 当你调用 `new Type` 时，C++ 执行了两步操作：
    
    1. **调用 `operator new` 分配内存**。
    2. **在分配的内存上调用对象的构造函数**，初始化对象。
- 当你调用 `delete` 时，C++ 也执行了两步操作：
    
    1. **调用对象的析构函数**，进行清理工作。
    2. **调用 `operator delete` 释放内存**。
# 问题
## 问题1
`new `和 `delete[]`, `new[]`和`delete`可以混用么？C++为什么要区分单个元素和数组的内存分配和释放呢？

在 C++ 中，**`new` 和 `delete` 不能与 `new[]` 和 `delete[]` 混用**。也就是说：

- 你不能用 `new[]` 分配内存后，使用 `delete` 释放它。
- 你不能用 `new` 分配内存后，使用 `delete[]` 释放它。

### 原因分析

C++ 之所以区分 `new`/`delete` 和 `new[]`/`delete[]`，以及为什么它们不能混用，主要是因为以下几个方面：

### 1. **对象构造和析构机制不同**
当使用 `new` 和 `new[]` 分配内存时，编译器会根据上下文采取不同的处理方式：

- **`new`**: 分配内存后，调用单个对象的构造函数。
- **`new[]`**: 分配内存后，调用数组中每个对象的构造函数。这还需要存储数组的长度，以便在释放内存时能够正确调用析构函数。

同样地，`delete` 和 `delete[]` 也会表现不同：
- **`delete`**: 只调用单个对象的析构函数，并释放这块内存。
- **`delete[]`**: 会调用数组中每个对象的析构函数，释放数组的每个元素，然后释放内存。

当你使用 `new[]` 分配内存后，如果使用 `delete` 来释放，编译器不会知道它需要调用数组中每个对象的析构函数，而只是会尝试调用单个对象的析构函数。这会导致内存泄漏或未定义行为。同样，使用 `new` 分配内存后使用 `delete[]` 也会导致未定义行为，因为 `delete[]` 期望有一个数组，并会尝试读取不存在的数组大小信息，从而导致错误。

### 2. **数组的额外信息（大小）管理**
当使用 `new[]` 分配内存时，编译器通常会在分配的内存块中存储数组的大小（具体方式依赖于编译器实现）。这是为了在调用 `delete[]` 时，知道数组中有多少个元素需要调用析构函数。

例如，当你写：

```cpp
int* arr = new int[10];
```

编译器实际上会分配比 `sizeof(int) * 10` 更多的内存，以便保存数组的大小（通常会在内存块的某个偏移处存储这个信息）。这就是为什么使用 `delete` 而不是 `delete[]` 释放这种内存会导致错误，因为 `delete` 不会考虑数组大小的信息，无法正确调用析构函数。

### 3. **构造和析构的匹配要求**
C++ 的对象模型要求构造和析构必须匹配：
- `new` 对应 `delete`，负责构造和析构一个对象。
- `new[]` 对应 `delete[]`，负责构造和析构多个对象。

混用 `new` 和 `delete[]` 或者 `new[]` 和 `delete` 会打破这种匹配，导致未定义行为。

### 4. **具体的未定义行为**
- 如果你使用 `new[]` 分配了对象数组，并用 `delete` 释放它，编译器只会认为这是单个对象，它不会遍历整个数组调用每个对象的析构函数，可能导致资源泄漏或者未正确释放的内存。
  
- 如果你使用 `new` 分配单个对象，并用 `delete[]` 释放它，`delete[]` 会尝试读取额外的元数据（通常存储在数组头部附近的内存中），以为它是一个数组。这可能导致访问无效内存地址，从而崩溃或引发其他未定义行为。

### 示例：
```cpp
int* p = new int;      // 正确：分配单个int
delete[] p;            // 错误：使用了 delete[]，会导致未定义行为

int* arr = new int[10]; // 正确：分配int数组
delete arr;             // 错误：使用 delete，而不是 delete[]
```

### 5. **历史原因和语言设计**
C++ 之所以设计成这样，有一些历史和技术原因：

- **效率和灵活性**：C++ 注重高效的低级内存管理，不会为用户隐藏太多实现细节。区分 `new` 和 `new[]` 使得程序员可以明确知道什么时候在分配数组，什么时候在分配单个对象。这也避免了为所有对象分配引入数组相关的元数据，这样单对象分配就可以更加轻量。

- **与 C 的兼容性**：C++ 的内存管理与 C 的 `malloc`/`free` 保持了一定的兼容性，而 `malloc`/`free` 并不涉及对象的构造与析构，只是单纯的内存分配与释放。这使得 C++ 中的内存管理既可以支持高级的对象管理，也可以执行底层的内存操作。

### 6. **如何避免这种错误**
- **始终匹配 `new` 和 `delete`，以及 `new[]` 和 `delete[]`**。
- 使用 **智能指针**，如 `std::unique_ptr` 或 `std::shared_ptr`，特别是管理动态分配的数组时，可以使用 `std::unique_ptr<T[]>` 来自动管理内存，避免手动调用 `delete` 或 `delete[]`。

例如：

```cpp
std::unique_ptr<int[]> arr(new int[10]);  // 自动使用 delete[] 来释放内存
```

### 总结
- **`new` 和 `delete` 不能与 `new[]` 和 `delete[]` 混用**，它们有不同的语义和行为。
- **`new[]`** 会分配额外的内存来存储数组大小信息，确保数组析构时能正确处理多个对象。
- **混用** 这些操作符会导致未定义行为，如内存泄漏或崩溃。
- **最佳实践**：始终使用相匹配的 `new`/`delete` 和 `new[]`/`delete[]`，或者使用智能指针来自动管理内存。
