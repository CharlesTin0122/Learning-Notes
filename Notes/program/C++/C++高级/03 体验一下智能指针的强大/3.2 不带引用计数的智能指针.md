# 引子
请看如下代码
```cpp
SmartPtr<int> p1(new int());
SmartPtr<int> p2(p1);
```
- 用户在此操作的意图是p1和p2都指向同一块内存，因此不能用拷贝构造实现深拷贝，那样他们就指向了不同的内存。
- 如果仅仅使用浅拷贝使他们指向同一块内存，就会出现p1,p2重复析构同一块内存的问题。
- 要解决浅拷贝出现的问题，解决方法有两种：带引用计数的智能指针、不带引用计数的智能指针。

我们先来看不带引用计数的智能指针：
# 不带引用计数的智能指针
- 不带引用计数的智能指针：只能由一个指针来管理一个资源。
## 分类
- C++库提供
	- auto_ptr：已弃用
- C++11标准提供
	- scoped_ptr
	- unique_ptr
## auto_ptr
请看如下代码：
```cpp
std::auto_ptr<int> ptr1(new int());
std::auto_ptr<int> ptr2(ptr1);
*ptr2 = 20;
//std::cout << *ptr1 << std::endl;//报错
```
- 第二行的拷贝构造，底层含义是将ptr2指针指向ptr1指向的内存，然后将ptr1置空 
- ptr1是空指针，所以第4行代码报错。
- auto_ptr解决浅拷贝问题的方法是：在拷贝构造时，永远让最后一个指针管理资源，前面的指针统统置空。不推荐使用，尤其是在STL中，所以被弃用。
## scoped_ptr
- 不支持拷贝构造和赋值运算符重载，底层代码逻辑如下：
```cpp
scoped_ptr(const scoped_ptr<T>&) = delete;
scoped_ptr<T> &operator=(const scoped_ptr<T>&) = delete;
```
- 当你调用拷贝构造和赋值运算符重载时，编译器报错。
- scoped_ptr使用的比较少
# unique_ptr
- 推荐使用
- unique_ptr底层也删除了拷贝构造和赋值运算符重载
```cpp
unique_ptr(const unique_ptr<T>&) = delete;
unique_ptr<T> &operator=(const unique_ptr<T>&) = delete;
```
- 因此，你在使用如下代码时会报错
```cpp
std::unique_ptr<int> p1(new int());
std::unique_ptr<int> p2(p1);
```
- 但是你可以这样使用，将p1转化为一个右值，`std::move()`得到当前变量的右值类型，底层是一个类型强转`static)cast<T &&>(T)`。
```cpp
std::unique_ptr<int> p1(new int());
std::unique_ptr<int> p2(std::move(p1));
```
- 之所以如此，是因为unique_ptr实现了带右值引用参数的拷贝构造函数和带右值引用参数的赋值运算符重载函数： 
	- `unique_ptr(unique_ptr<T> &&other)`，`unique_ptr<T> &operator=(unique_ptr<T>&&other)`
- 但是，由于使用了移动语义，将p1指向的资源移动到了p2，所以p1也不支持访问了。好处是用户通过`std::move()`，已经知道资源由p1转移到p2了，代码更加清晰明了。
- 可以使用如下代码
```cpp
#include <memory>

// 返回只智能指针函数
template <typename T>
std::unique_ptr<T> getSmartPtr()
{
    std::unique_ptr<T> ptr(new int());
    return ptr; // 返回临时对象，是一个右值
}

int main()
{
    // 通过调用带右值引用参数的拷贝构造函数初始化变量
    std::unique_ptr<int> p1 = getSmartPtr<int>();
    return 0;
}
```
