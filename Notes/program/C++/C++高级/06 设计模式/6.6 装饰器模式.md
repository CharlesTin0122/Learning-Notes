**装饰器模式（Decorator Pattern）**是一种结构型设计模式，用于动态地向对象添加功能，而不改变其原有的结构。装饰器模式提供了一种灵活的替代继承的方案，通过将功能划分到多个装饰类中，可以实现按需组合对象功能。

---

### **装饰器模式的组成**

在 C++ 中，装饰器模式通常由以下部分组成：

1. **抽象组件（Component）**：
    
    - 定义对象的公共接口，所有需要被装饰的对象和装饰器都要实现这个接口。
2. **具体组件（ConcreteComponent）**：
    
    - 实现了抽象组件的接口，是被装饰的核心对象。
3. **抽象装饰器（Decorator）**：
    
    - 实现抽象组件的接口，并包含对具体组件或其他装饰器的引用。
    - 可以在调用组件方法之前或之后增加额外的行为。
4. **具体装饰器（ConcreteDecorator）**：
    
    - 继承抽象装饰器，并实现具体的装饰功能。
5. **客户端（Client）**：
    
    - 使用装饰器对象调用组件的方法。

### **装饰器模式的示例**

#### **场景**：对文本进行动态装饰（如加粗、加斜体）

```cpp
#include <iostream>
#include <memory>
using namespace std;

// 抽象组件
class Component {
public:
    virtual void operation() const = 0;
    virtual ~Component() = default;
};

// 具体组件
class ConcreteComponent : public Component {
public:
    void operation() const override {
        cout << "Plain Text";
    }
};

// 抽象装饰器
class Decorator : public Component {
protected:
    unique_ptr<Component> component; // 被装饰的对象
public:
    Decorator(unique_ptr<Component> comp) : component(move(comp)) {}
    void operation() const override {
        component->operation(); // 委托给被装饰对象
    }
};

// 具体装饰器：加粗
class BoldDecorator : public Decorator {
public:
    BoldDecorator(unique_ptr<Component> comp) : Decorator(move(comp)) {}
    void operation() const override {
        cout << "<b>";
        Decorator::operation();
        cout << "</b>";
    }
};

// 具体装饰器：加斜体
class ItalicDecorator : public Decorator {
public:
    ItalicDecorator(unique_ptr<Component> comp) : Decorator(move(comp)) {}
    void operation() const override {
        cout << "<i>";
        Decorator::operation();
        cout << "</i>";
    }
};

// 客户端代码
int main() {
    // 创建具体组件
    unique_ptr<Component> text = make_unique<ConcreteComponent>();

    // 用加粗装饰器装饰
    unique_ptr<Component> boldText = make_unique<BoldDecorator>(move(text));

    // 再用斜体装饰器装饰
    unique_ptr<Component> italicBoldText = make_unique<ItalicDecorator>(move(boldText));

    // 输出结果
    italicBoldText->operation(); // 输出：<i><b>Plain Text</b></i>
    cout << endl;

    return 0;
}
```

---

### **示例分析**

1. **核心思路**：
    
    - 被装饰的对象（`ConcreteComponent`）和装饰器（如 `BoldDecorator`、`ItalicDecorator`）都实现相同的接口。
    - 装饰器通过组合而不是继承的方式动态地为对象添加功能。
2. **动态扩展功能**：
    
    - 每个装饰器可以独立地增加功能，并可以按需组合多个装饰器。
3. **执行顺序**：
    
    - 装饰器调用其内部组件的操作方法，形成一个链式调用。

---

### **装饰器模式的优缺点**

#### **优点**：

1. **遵循开闭原则**：
    - 可以在不修改原有类的情况下扩展功能。
2. **灵活性高**：
    - 可以动态地组合多个装饰器，按需增加或移除功能。
3. **减少类的数量**：
    - 相比通过继承实现功能扩展，装饰器模式可以避免为每种功能组合创建子类。

#### **缺点**：

1. **复杂性增加**：
    - 每增加一个功能都需要创建新的装饰器类，导致类数量可能较多。
2. **调试困难**：
    - 由于功能分布在多个装饰器中，链式调用的层次较深时可能不易调试。

---

### **装饰器模式的应用场景**

1. **需要动态地扩展对象的功能**：
    
    - 如 GUI 系统中，为控件动态添加滚动条、边框等。
2. **功能的组合变化多**：
    
    - 如文件的读写操作，可以通过装饰器实现加密、压缩等功能。
3. **不希望修改原有代码**：
    
    - 在不修改组件代码的情况下，动态添加功能。

---

### **装饰器模式 VS 继承**

|特性|装饰器模式|继承|
|---|---|---|
|**功能扩展**|动态扩展|静态扩展|
|**类数量**|装饰器类可以重复利用，类数量较少|每种功能组合都需要单独的子类|
|**灵活性**|可以动态组合装饰器|功能扩展固定，灵活性较差|
|**实现难度**|需要设计抽象装饰器，较复杂|直接实现子类，较简单|

装饰器模式在功能组合复杂、需要灵活扩展的场景中表现尤为突出，是面向对象设计中的一个重要工具。
# 案例
```cpp
#include <iostream>

// 装饰器模式

// 汽车类
class Car
{
public:
    virtual void show() = 0;
};

class BMW : public Car
{
public:
    void show() override { std::cout << "This is a BMW car!" << std::endl; }
};

class Audi : public Car
{
public:
    void show() override { std::cout << "This is a Audi car!" << std::endl; }
};

// 装饰器类
class CarDecorator1 : public Car
{
public:
    CarDecorator1(Car *p) : car_ptr(p) {}
    void show() override
    {
        car_ptr->show();
        std::cout << "增加定速巡航功能" << std::endl;
    }

private:
    Car *car_ptr;
};

class CarDecorator2 : public Car
{
public:
    CarDecorator2(Car *p) : car_ptr(p) {}
    void show() override
    {
        car_ptr->show();
        std::cout << "增加主动刹车功能" << std::endl;
    }

private:
    Car *car_ptr;
};

int main()
{
    Car *p1 = new BMW();
    Car *p2 = new Audi();

    p1->show();
    p2->show();

    Car *p3 = new CarDecorator1(p1);
    Car *p4 = new CarDecorator2(p2);

    p3->show();
    p4->show();

    return 0;
}
```
