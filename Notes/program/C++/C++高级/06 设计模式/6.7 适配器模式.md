**适配器模式（Adapter Pattern）**是一种结构型设计模式，用于将一个类的接口转换为客户期望的另一个接口。适配器模式使原本接口不兼容的类能够一起工作，解决接口不匹配的问题。

---

### **适配器模式的组成**

在 C++ 中，适配器模式通常由以下部分组成：

1. **目标接口（Target）**：
    
    - 定义客户期望的接口，适配器最终要实现这个接口。
2. **适配者（Adaptee）**：
    
    - 已经存在的类，其接口与目标接口不兼容，需要通过适配器转换。
3. **适配器（Adapter）**：
    
    - 实现目标接口，并将客户的请求转换为适配者能够理解的形式。
4. **客户端（Client）**：
    
    - 调用目标接口的类，与适配器交互，完全不需要了解适配者的存在。

---

### **适配器模式的类型**

适配器模式有两种实现方式：

1. **类适配器**（使用继承）：通过多重继承将目标接口和适配者连接起来。
2. **对象适配器**（使用组合）：通过对象组合实现适配，将适配者作为适配器的成员。

---

### **适配器模式的示例**

#### 示例：类适配器

**场景**：旧的电源接口提供 `220V` 电压，而客户期望使用 `110V` 电压的设备。

```cpp
#include <iostream>
using namespace std;

// 目标接口
class Target {
public:
    virtual void request() const = 0;
    virtual ~Target() = default;
};

// 适配者
class Adaptee {
public:
    void specificRequest() const {
        cout << "Adaptee: Providing 220V power supply." << endl;
    }
};

// 适配器（类适配器，使用多重继承）
class Adapter : public Target, private Adaptee {
public:
    void request() const override {
        cout << "Adapter: Converting 220V to 110V..." << endl;
        specificRequest(); // 调用适配者的方法
    }
};

// 客户端代码
int main() {
    Target* adapter = new Adapter();
    adapter->request(); // 使用适配器调用目标接口
    delete adapter;
    return 0;
}
```

**输出**：

```
Adapter: Converting 220V to 110V...
Adaptee: Providing 220V power supply.
```

#### 示例：对象适配器

**场景**：同样的电源转换场景，但通过对象组合实现适配。

```cpp
#include <iostream>
#include <memory>
using namespace std;

// 目标接口
class Target {
public:
    virtual void request() const = 0;
    virtual ~Target() = default;
};

// 适配者
class Adaptee {
public:
    void specificRequest() const {
        cout << "Adaptee: Providing 220V power supply." << endl;
    }
};

// 适配器（对象适配器，使用组合）
class Adapter : public Target {
private:
    shared_ptr<Adaptee> adaptee; // 持有适配者对象
public:
    Adapter(shared_ptr<Adaptee> adpt) : adaptee(move(adpt)) {}
    void request() const override {
        cout << "Adapter: Converting 220V to 110V..." << endl;
        adaptee->specificRequest(); // 调用适配者的方法
    }
};

// 客户端代码
int main() {
    shared_ptr<Adaptee> adaptee = make_shared<Adaptee>();
    Target* adapter = new Adapter(adaptee);
    adapter->request(); // 使用适配器调用目标接口
    delete adapter;
    return 0;
}
```

**输出**：

```
Adapter: Converting 220V to 110V...
Adaptee: Providing 220V power supply.
```

---

### **示例分析**

1. **适配目标接口与适配者**：
    
    - 适配者 `Adaptee` 提供了现有功能，但接口不符合客户需求。
    - 适配器 `Adapter` 将适配者的方法封装并转换成目标接口的形式。
2. **类适配器 vs 对象适配器**：
    
    - **类适配器**通过继承实现，适配器继承了适配者的接口和实现。
    - **对象适配器**通过组合实现，适配器持有适配者的对象。
3. **透明性**：
    
    - 客户端只需操作目标接口 `Target`，完全不用关心适配者的实现细节。

---

### **适配器模式的优缺点**

#### **优点**：

1. **增强兼容性**：
    - 将不兼容的接口连接起来，使得原本无法协同工作的类能够协同工作。
2. **遵循开闭原则**：
    - 在不修改现有代码的前提下，添加适配器实现新的接口需求。
3. **灵活性**：
    - 对象适配器可以适配多个适配者，具有更高的灵活性。

#### **缺点**：

1. **类适配器的局限性**：
    - 由于使用多重继承，适配器必须继承自一个具体适配者，可能导致灵活性下降。
2. **增加复杂性**：
    - 引入了额外的适配器类，可能使系统设计变得更复杂。

---

### **适配器模式的应用场景**

1. **接口不兼容**：
    
    - 当已有类的接口与新需求不兼容时，通过适配器进行桥接。
2. **兼容第三方库**：
    
    - 将第三方库的接口适配为项目中通用的接口。
3. **遗留系统集成**：
    
    - 使用适配器对旧系统的接口进行封装，以适应新系统。
4. **代码复用**：
    
    - 通过适配器将功能扩展到多个上下文中，而无需修改已有类。

---

### **适配器模式 VS 桥接模式**

|特性|适配器模式|桥接模式|
|---|---|---|
|**目的**|使不兼容的接口可以协同工作|将抽象与实现分离|
|**作用时机**|在现有类已存在时适配新接口|在系统设计时预见变化并分离抽象实现|
|**实现方式**|通过封装适配现有接口|通过组合分离抽象与实现|

适配器模式主要解决现有类与新接口的兼容性问题，是一种重要的设计模式。
