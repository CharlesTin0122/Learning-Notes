**单例模式**（Singleton Pattern）是一种常见的设计模式，它确保一个类在整个程序运行期间只有一个实例，并提供一个全局访问点。单例模式在需要唯一全局状态或共享资源的场景中非常有用，比如日志记录器、配置管理器、线程池等。

### 实现单例模式的步骤

在C++中，单例模式的实现通常包括以下几个关键点：

1. **私有化构造函数**：防止外部直接创建对象。
2. **删除拷贝构造函数和赋值操作符**：防止通过拷贝或赋值创建新的实例。
3. **提供一个静态方法获取唯一实例**：通过静态成员函数提供实例访问。
### 分类
- 饿汉式单例模式：在类加载时就初始化单例实例。还没有获取实例对象，实力对象就已经产生了。一定是线程安全的。
- 懒汉式单例模式，唯一的实例对象，直到第一次获取的时候，才产生唯一的实例。
### 经典实现

饿汉式单例模式：
```cpp
#include <iostream>

class Singleton
{
public:
    // 获取类的唯一实例方法
    static Singleton *getInstance() { return &instance; }

private:
    // 静态唯一实例对象,储存在.data段，未获取便已存在
    static Singleton instance;
    // 构造函数私有化
    Singleton() { std::cout << "Singleton initialized!" << std::endl; }
    // 禁用拷贝构造和赋值操作
    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
};
// 静态成员变量在类外定义
Singleton Singleton::instance;

int main()
{
    Singleton *p = Singleton::getInstance();

    return 0;
}
```

懒汉式单例模式
```cpp
#include <iostream>

class Singleton
{
public:
    // 获取类的唯一实例方法,在多线程的情况下，此函数在没有执行完时可能会被再次调用
    static Singleton *getInstance()
    {
        // 如果实例指针为空，创建一个实例，如果不为空，返回实例
        if (instance == nullptr) { instance = new Singleton; }
        return instance;
    }

private:
    // 静态唯一实例对象指针
    static Singleton *instance;
    // 构造函数私有化
    Singleton() { std::cout << "Singleton initialized!" << std::endl; }
    // 禁用拷贝构造和赋值操作
    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
};
// 静态成员变量在类外定义
Singleton *Singleton::instance = nullptr;

int main()
{
    Singleton *p = Singleton::getInstance();

    return 0;
}
```

线程安全的懒汉式单例模式
```cpp
#include <iostream>
#include <mutex>

// 全局互斥锁
std::mutex mtx;

class Singleton
{
public:
    /*获取类的唯一实例方法
     *在多线程的情况下，此函数在没有执行完时可能会被其他线程再次调用，不是可重入函数
     */
    static Singleton *getInstance()
    {
        // 如果实例指针为空，创建一个实例，如果不为空，返回实例
        if (instance == nullptr)
        {
            // 分配内存，构造对象，变量赋值。不是线程安全的。所以要互斥锁 + 双重判断。
            std::lock_guard<std::mutex> guard(mtx);
            if (instance == nullptr) { instance = new Singleton; }
        }
        return instance;
    }

private:
    // 静态唯一实例对象指针,volatile关键字，防止多线程对共享变量进行缓存
    static Singleton *volatile instance;
    // 构造函数私有化
    Singleton() { std::cout << "Singleton initialized!" << std::endl; }
    // 禁用拷贝构造和赋值操作
    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
};
// 静态成员变量在类外定义,volatile关键字，防止多线程对共享变量进行缓存
Singleton *volatile Singleton::instance = nullptr;

int main()
{
    Singleton *p = Singleton::getInstance();
    return 0;
}
```

以下是另一种线程安全的懒汉式单例模式：

```cpp
#include <iostream>

class Singleton
{
public:
    // 禁用拷贝构造和赋值操作
    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;

    // 获取实例的静态方法
    static Singleton &getInstance()
    {
        /*局部静态变量，程序运行到时才会初始化，
         *局部静态变量的初始化，汇编指令会自动添加互斥锁，线程安全（C++11及之后）*/
        static Singleton instance;
        return instance;
    }

    // 示例方法
    void showMessage() const { std::cout << "Hello from Singleton!" << std::endl; }

private:
    // 私有构造函数
    Singleton() { std::cout << "Singleton initialized!" << std::endl; }
};

int main()
{
    Singleton &s1 = Singleton::getInstance();
    s1.showMessage();

    Singleton &s2 = Singleton::getInstance();
    s2.showMessage();

    // 输出证明s1和s2是同一个实例
    std::cout << "s1 and s2 are the same instance: " << (&s1 == &s2) << std::endl;

    return 0;
}
```

### 代码解析

1. **局部静态变量**：`static Singleton instance` 确保 `instance` 只会初始化一次，即使多个线程同时调用 `getInstance`，也可以保证线程安全（C++11及之后的标准）。
2. **删除拷贝和赋值操作**：防止通过复制方式创建多个实例。
3. **单例唯一性**：`getInstance` 返回对同一个对象的引用，无论调用多少次。

### 线程安全的注意事项

- 在C++11之前，需要显式使用锁（如`std::mutex`）保护实例初始化：
    
    ```cpp
    static Singleton* instance;
    static std::mutex mtx;
    
    static Singleton& getInstance() {
        if (instance == nullptr) {
            std::lock_guard<std::mutex> lock(mtx);
            if (instance == nullptr) {
                instance = new Singleton();
            }
        }
        return *instance;
    }
    ```
    

### 单例模式的优缺点

#### 优点：

1. 确保全局只有一个实例，节省资源。
2. 提供一个全局访问点，便于控制和维护。

#### 缺点：

1. 可能导致过度依赖全局状态，降低模块化设计的灵活性。
2. 难以单元测试，因为全局实例可能难以替换。

### 实际应用

单例模式适用于需要唯一实例的场景，但应谨慎使用，避免因滥用而增加代码复杂度或耦合度。
