在C++多线程编程中，线程间互斥是一个常见的问题，特别是在访问共享资源时，多个线程可能会同时读取或修改数据，从而导致竞态条件（Race Condition），这会引发不可预测的行为。为了解决这个问题，C++提供了多种方式来确保在任何时刻只有一个线程能访问某个共享资源。最常见的方式是使用**互斥锁（Mutex）**来进行线程间的同步。

### 1. 互斥锁（Mutex）

**互斥锁（Mutex）**是一个用于保护共享资源的机制，确保只有一个线程在任何给定的时间内访问资源。当一个线程锁住一个互斥量时，其他线程无法访问被保护的资源，直到该互斥量被解锁。

C++标准库中提供了互斥量的支持，位于`<mutex>`头文件中，主要有以下几种类型：

- **`std::mutex`**：最基本的互斥量。
- **`std::recursive_mutex`**：递归互斥量，允许同一线程多次锁定同一个互斥量。
- **`std::timed_mutex`**：带有超时机制的互斥量，可以在等待一段时间后放弃锁定。
- **`std::shared_mutex`**（C++17及以上）：支持多读单写的互斥量，允许多个线程同时读取资源，但写入时需要独占锁。

### 2. 互斥锁的基本使用

使用互斥量的基本流程通常如下：

1. 创建一个互斥量对象。
2. 线程在访问共享资源之前需要锁定该互斥量。
3. 访问完共享资源后，解锁该互斥量。

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;  // 互斥量

void print_hello(int i) {
    mtx.lock();  // 锁定互斥量
    std::cout << "Hello from thread " << i << std::endl;
    mtx.unlock();  // 解锁互斥量
}

int main() {
    std::thread t1(print_hello, 1);
    std::thread t2(print_hello, 2);

    t1.join();
    t2.join();

    return 0;
}
```

### 3. `std::lock_guard` 和 `std::unique_lock`

使用`lock()`和`unlock()`显得繁琐且容易出错，特别是在异常发生时。如果在锁定后发生异常，`unlock()`就可能不会被执行，从而导致死锁。为了解决这个问题，C++提供了`std::lock_guard`和`std::unique_lock`这两种智能锁机制，能够自动管理锁的获取和释放。

#### 3.1 `std::lock_guard`

`std::lock_guard`是一个简单的RAII（Resource Acquisition Is Initialization：资源获取即初始化）风格的互斥量管理工具，锁定互斥量并在作用域结束时自动释放锁。不支持拷贝构造和赋值运算符重载。

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;

void print_hello(int i) {
    std::lock_guard<std::mutex> guard(mtx);  // 自动锁定
    std::cout << "Hello from thread " << i << std::endl;
}

int main() {
    std::thread t1(print_hello, 1);
    std::thread t2(print_hello, 2);

    t1.join();
    t2.join();

    return 0;
}
```

#### 3.2 `std::unique_lock`

`std::unique_lock`提供了更多的灵活性，它不仅支持手动锁定和解锁，还支持延迟锁定、锁的交换等功能。它通常用于需要在不同时间点手动控制锁的场景。支持右值拷贝构造和右值赋值运算符重载，在函数调用、函数返回、函数参数传递过程中允许**临时对象**拷贝构造和**临时对象**赋值运算符重载。

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;

void print_hello(int i) {
    std::unique_lock<std::mutex> lock(mtx);  // 锁定互斥量
    std::cout << "Hello from thread " << i << std::endl;
    // 手动解锁：lock.unlock();  // 可以手动解锁
}

int main() {
    std::thread t1(print_hello, 1);
    std::thread t2(print_hello, 2);

    t1.join();
    t2.join();

    return 0;
}
```

### 4. 死锁（Deadlock）

死锁是多线程程序中常见的错误，发生在两个或多个线程互相等待对方释放已锁定的资源时，造成程序永久阻塞。避免死锁的关键是设计合理的锁策略，确保各个线程按照相同的顺序获取锁，或者使用`std::lock`来一次性锁定多个互斥量，从而避免死锁。

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx1, mtx2;

void deadlock_example() {
    std::lock(mtx1, mtx2);  // 防止死锁
    std::lock_guard<std::mutex> lg1(mtx1, std::adopt_lock);
    std::lock_guard<std::mutex> lg2(mtx2, std::adopt_lock);

    std::cout << "No deadlock!" << std::endl;
}

int main() {
    std::thread t1(deadlock_example);
    std::thread t2(deadlock_example);

    t1.join();
    t2.join();

    return 0;
}
```

### 5. 积极互斥（Active Mutex）

在某些高并发的情况下，线程可能会频繁地获取和释放互斥锁，这时传统的互斥量可能会导致性能瓶颈。为了优化性能，可以使用积极互斥（**Active Mutex**）的思想。

积极互斥锁指的是通过减少锁的获取与释放次数，或者通过减少互斥锁的粒度来提高效率。这通常通过以下两种方式来实现：

1. **减少锁的粒度**：将共享资源划分为多个较小的部分，每个部分使用不同的锁，从而减少线程之间的竞争。
2. **锁粒度加粗**：通过增加锁的持有时间，减少锁的竞争次数。在某些情况下，持有较长时间的锁可以避免频繁的上下文切换，尤其是当锁的获取和释放非常频繁时。

### 总结

在C++多线程编程中，互斥量是解决线程间同步问题的核心工具。通过使用`std::mutex`及其智能锁类型（如`std::lock_guard`和`std::unique_lock`），我们可以有效避免竞态条件、保证资源的互斥访问。同时，使用积极互斥的策略可以在一些高并发场景下提高程序的性能。然而，在设计多线程程序时，死锁是一个需要特别小心的问题，合理的锁策略和锁管理工具（如`std::lock`）可以有效避免死锁的发生。
# 案例
```cpp
#include <chrono>
#include <iostream>
#include <list>
#include <mutex>
#include <thread>

// 模拟车站三个窗口买票

// 车站有100张票
int ticketCount = 100;
// 全局互斥锁
std::mutex mtx;

// 卖票线程函数
void sellTicket(int idx)
{
    while (ticketCount > 0)
    {

        // mtx.lock(); // 互斥锁锁定，线程解锁才能操作锁内代码，每次只能有一个线程开锁
        {
            // lock_guard互斥锁，出作用域自动析构。不支持拷贝构造和赋值运算符重载.防止死锁发生。
            std::lock_guard<std::mutex> lock(mtx);

            // 互斥锁内加判断，防止多线程同时访问时卖出第0张票出错
            if (ticketCount > 0)
            {
                // 打印售票信息
                std::cout << idx << " Window selled " << ticketCount << " ticket" << std::endl;
                // 票数自减,这不是一个线程安全的操作，每个线程都会调用，同时调用时会导致多减或者少减。
                // 所以要做线程间的互斥,每次只有一个线程可以调用
                ticketCount--;
            }
        }
        // mtx.unlock(); // 互斥锁解锁，解锁后，其他线程才能访问锁内内容

        // 线程等待100毫秒
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
}
// 主函数
int main()
{
    // 线程链表
    std::list<std::thread> t_list;
    // 链表填充三个卖票窗口线程
    for (int i = 1; i <= 3; ++i)
    {
        t_list.push_back(std::thread(sellTicket, i));
    }
    // 主线程等待子线程
    for (std::thread &t : t_list)
    {
        t.join();
    }

    std::cout << "Tickets all selled!" << std::endl;
    return 0;
}
```
